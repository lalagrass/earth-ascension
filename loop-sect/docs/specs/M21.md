# M21 灶邊接力

Loop 24。支柱 P1 P5。PLAN-03 第一項。

## 目標

retro 7 的帳本：新的食物來源（打獵、菜園）讓撿回來的食物變多，煮掉的反而變少，多的堆在灶邊被生吃、被偷，大家吃到的飯變少。這輪讓「灶邊堆著生食材」本身成為想煮飯的理由：堆得越多，路過的人越想順手煮一鍋；條理的人更常順手。不排班、不改門檻。

## 前置條件（v5、v8）

- 帳本（`diag/share`，種子 1–12，十日）：base 撿 604、煮掉 524、被偷 61、吃到的飯 1006。hunt 撿 727、煮掉 484、被偷 115、吃飯 928。farm 撿 811、煮掉 492、被偷 64、吃飯 943。
- 煮飯候選（`ai.mjs`）：飯 < `MEAL_TARGET` 6、生 ≥ 2 時才有；活計 `需求 × 1.4`（需求＝1 − 飯／6），鍋裡沒飯時再加 `1 + 0.4 × 餓的人數`。
- v7 名次（`rank.mjs cook`，5 日）：base 出現 1886 次、排第一 5%、名次中位 18；hunt 6%、中位 19。輸給吃飯、聊天、蓋房、練功。
- 野豬偷灶邊（生與飯都算），被偷的飯只有 6 份、生 61 份：煮成飯本身就比較不會被偷。
- 會改到 base：雜湊會變。舊指標照現有門檻判；只在 NOISE-01 雜訊帶裡翻的，列出位置、不算退步。

## 玩家會感受到的主張

「灶邊的食材不會堆著爛掉：堆多了自然有人順手煮，多了打獵、菜園，大家吃得更飽，不是更餓」。

## 規則與資料（`data.mjs` 的 `KITCHEN`）

- `KITCHEN = { RAW0: 4, RAW_K: 8, PULL: 1.2, CAP: 12, J: 0.3 }`。
- 堆量 `pile = clamp((生 − RAW0) / RAW_K, 0, 1)`。
- 煮飯候選的條件改成：生 ≥ 2、有柴、飯 < `MEAL_TARGET`，**或** `pile > 0` 而且飯 < `CAP`。
- 活計加 `PULL × pile`；個性加 `J × 條理 × pile`。堆量 > 0 時頭上寫「灶邊堆著，順手煮一鍋」。
- 粗估：base 平均生 6.2 → pile 0.27 → 活計 +0.33；hunt 平均生 9.5 → pile 0.69 → +0.83，跟打獵（1.6＋缺糧）同一級。

### 為什麼沒過

retro 7 的假設是「多的食物堆在灶邊沒人煮」。十日帳本是對的，但最差日的飢餓不在那時候：`hungry-why` 與 `day.mjs`（base 種子 1）看到，餓的那幾刻灶邊是**飯 0、生 0**，野莓叢也被吃空，堆量是 0，這條規則根本沒作用。hunt 多出來的被偷（68→123）是打獵的人不在家，不是沒人煮。第三次沒有指向那一段的假設，所以照 v5 停在兩次。

### 留給擁有人

開著（`RAW0 6`）時 base 兩組種子都明顯少餓、猜個性不掉。它解不了打獵與菜園，但本身是好的。要不要單獨打開，等擁有人決定。

### 恢復的步驟

1. `KITCHEN.ON = true`（`RAW0` 已是 6）。
2. 重量 report 兩組種子；M10-A5[base]、M10-A6 要過。
3. headless：生食材堆著時有人頭上寫「灶邊堆著，順手煮一鍋」（這輪因為關著沒做 A8）。
