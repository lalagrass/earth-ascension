# Loop engineering 規格

本分支（`loop-sect/`）用固定的開發迴圈推進。每一輪 loop 只做一個 milestone，做完才進下一輪。目的是讓「人不在場時 AI 連續開發」也有可檢查的節奏：每輪都有寫在前面的驗收條件、機器能跑的檢查、自我審查紀錄與一個推上去的 commit。

## 一輪 loop 的七步

| 步 | 做什麼 | 產出 | 完成條件 |
|---|---|---|---|
| 1. 選題 | 從 [MILESTONES.md](MILESTONES.md) 取第一個狀態為「待做」的 milestone | log 開一節 | 只取一個；前一輪未完成不得開新輪 |
| 2. 規格 | 寫 `docs/specs/Mxx.md`：目標、玩家看到什麼、規則、資料、**驗收條件（編號 A1…）**、不做什麼。數值標 `data.mjs` 常數名 | spec 檔 | 每條驗收都能對應到一個自動測試或 headless 檢查，並附一行可行性粗估（什麼情況下它根本不會發生），粗估要引用一個既有 soak 或 diag 的數字。門檻在第一次 soak 前寫定。另寫一句「玩家會感受到的主張」並對到一個 soak 量測 |
| 3. 實作 | 只改 `loop-sect/`；資料放 `src/data.mjs`，規則是純函式，畫面只讀 state | 程式 | 不加套件、不碰其他分支目錄與共用 CI |
| 4. 自動檢查 | `node --test loop-sect/test/*.test.mjs`（規則）＋ `node loop-sect/tools/soak.mjs`（多種子長跑不變量）＋ `node loop-sect/tools/headless.mjs`（真瀏覽器正常操作） | 三項都 exit 0 | 失敗就回第 3 步，不得跳過或關掉測試。平衡類失敗先看 soak 的時間分布與最差種子，在 log 寫下假設與 diag 數字再改；改完變差就退回 |
| 5. 自我審查 | 依下方清單逐條看 diff，並看寬、窄兩張截圖，找到的問題修掉再跑第 4 步 | log 記下發現與修正、截圖看到什麼 | 清單全勾 |
| 6. 提交 | 一個 milestone 一個（或少數幾個）commit，push 到分支 | commit SHA | push 成功 |
| 7. 記錄 | 在 [docs/LOOP_LOG.md](docs/LOOP_LOG.md) 寫：spec 連結、驗收結果表、檢查輸出摘要、時間分布前十與上一輪的差異、審查發現、已知限制、下一輪候選 | log 節 | MILESTONES 狀態改為「完成」 |

停止條件：達到本次授權的輪數（見 `loop-state.json` 的 targetLoops），或某步連續修三次仍失敗（記錄卡點後停下，不硬過；v6：程式沒做到規格寫的事是 bug，修掉不算一次）。v5：修三次仍失敗時，停止調參、全部退回，把 milestone 標成「暫停」並寫恢復條件；若有不需要擁有人決定的下一個 milestone，可以先做，同時請擁有人決定。

每三輪做一次 retro（`docs/RETRO-xx.md`），把改進寫回本頁；通知擁有人時附試玩指令與一張截圖，不等回覆。

## 版本

- v1（loop 1–3）
- v2（[retro 1](docs/RETRO-01.md) 後）：驗收要附可行性粗估、先診斷再調數字、數值標常數名、每輪看截圖、每三輪 retro 與外部審查、診斷腳本放 `tools/diag/` 留存
- v3（[retro 2](docs/RETRO-02.md) 後）：門檻在第一次量測前寫定，改門檻要寫原值與理由；自然行為的測試至少 6 個種子或改控制實驗；每輪 log 附時間分布並與上一輪比；規格寫一句「玩家會感受到的主張」並在 soak 驗
- v10（[retro 9](docs/RETRO-09.md) 後）：新的分布類主張用 48 個種子的分位數寫；先設計影響範圍讓舊雜湊不變；搬動共用的東西先查引用
- v11（[retro 10](docs/RETRO-10.md) 後）：新內容寫出第幾日用完並用三十日長跑對一次；瀏覽器等待只輪詢畫面或小欄位
- v9（[retro 8](docs/RETRO-08.md) 後）：針對飢餓的新規則，先算「餓著的那些刻，規則條件成立的比例」；假設與指標在同一個時間窗；計畫裡靠前一項成功的要標出備案
- v8（[retro 7](docs/RETRO-07.md) 後）：新情境第一次量之前跑 `tools/diag/share.mjs` 看擠掉誰；飢餓不過先看帳本再提假設；新食物來源算每人·tick 產出；新建築情境的飢餓列同層對照當參考
- v7（[retro 6](docs/RETRO-06.md) 後）：新候選第一次量之前先跑 `tools/diag/rank.mjs` 看名次；累積類粗估引用 p75／p90；舊門檻量雜訊帶，落在雜訊帶裡的整理成一張決定卡；headless 讀像素前等兩幀
- v6（[retro 5](docs/RETRO-05.md) 後）：暫停、請擁有人決定或推薦放寬門檻前，用第二組種子（`report --from 13`）重量；比兩組人時分層比；選擇比例的粗估寫出選法並先量；規則漏寫是 bug、不算調參次數
- v5（[retro 4](docs/RETRO-04.md) 後）：規劃寫前置條件；粗估引用同資源同時段的數字；小樣本指標標出；暫停一個 milestone 的做法
- v4（[retro 3](docs/RETRO-03.md) 後）：粗估引用既有數字；改數值前寫假設，變差就退回；soak 印最差種子；畫面重疊檢查；外部審查改為附試玩指令的通知

## 自我審查清單

1. **地圖上真的發生**：面板上的變化都有對應的地圖行動（走到、拿起、搬運、做完），不直接改數字代替行動。（吸取 Gemini 分支固定戰果、直接設等級的教訓）
2. **守恆**：資源、食物、預約不憑空出現或消失；取消會歸還。
3. **不瞬移**：每 tick 位移不超過速度上限，soak 會檢查。
4. **決定論**：同種子同輸入，結果相同（soak 比對兩次雜湊）。
5. **個性有差**：不同人格在同情境下的選擇比例有可量測差異，並把理由顯示給玩家。
6. **範圍**：只改 `loop-sect/`；沒有存檔；沒有新依賴。
7. **證據不膨脹**：截圖與長輸出寫到 `loop-sect/.evidence/`（已 gitignore），commit 只留 log 摘要。（吸取 GPT 分支證據 1.69GB 的教訓）
8. **數值變更有依據**：每個平衡數值的變更都寫出促成它的診斷數字；改到舊 milestone 的數值要在該規格加註。
9. **不靠單一種子**：量自然行為的測試至少 6 個種子聚合，或改成只改一個變數的控制實驗。
10. **新東西吃掉誰的時間**：和上一輪的時間分布比，舊 milestone 的效果（專長、作息、聊天）有沒有被擠掉。
11. **截圖逐張看重疊**：頭頂字、名字、標籤有沒有疊在一起或被人物擋住（headless 自動檢查做好之前）。
12. **小樣本**：這輪碰到的指標若事件數 < 20，跨門檻時先確認是不是同一批事件，再判斷退步。
13. **第二組種子**（v6）：要暫停、請擁有人決定或推薦放寬門檻前，相關指標用 `report --from 13` 開、關各量一次；比兩組人時在同一層（職別、情境）裡比。
14. **新候選的名次**（v7）：新增或改分數的候選，第一次量之前跑 `node loop-sect/tools/diag/rank.mjs <kind> <情境>`，名次寫進規格；排第一不到 5% 的，先想清楚為什麼會被選。
15. **長尾**（v7）：「累積到門檻才發生」的事，粗估引用 p75／p90 與最大值。
16. **擠掉誰、帳本**（v8）：新活計或新情境第一次量之前跑 `node loop-sect/tools/diag/share.mjs <情境>`，寫進前置條件；飢餓不過時先看帳本哪一段變少，假設指向那一段。
17. **產出效率**（v8）：新的食物或材料來源寫每人·tick 產出並跟現有來源比；比較低的，活計分要隨缺糧走。
18. **餓的那一刻會觸發嗎**（v9）：針對飢餓的新規則，第一次量之前算「餓著的人·tick 裡規則條件成立的比例」，寫進前置條件；< 30% 的不做。帳本與時間分布在指標量的那段時間裡算。
19. **48 個種子與影響範圍**（v10）：新的分布類主張（飢餓、比例）寫成 48 個種子的中位數與 p90（`tools/diag/hunger48.mjs`）；新規則先寫出會碰到哪些情境、哪幾日，能限制的就限制；搬動共用的東西先 grep 引用。
20. **內容用完的日子與瀏覽器等待**（v11）：新增可學、可蓋、可解鎖的內容時，在規格寫「照現在的速度第幾日用完」，用 `tools/long.mjs --days 30` 對一次；headless 等條件時只看畫面或單一小欄位、`polling: 2000`，不要每格拿整份 snapshot（會拖慢遊戲到逾時）。

## 檢查工具

- `test/*.test.mjs`：Node 內建 test runner，驗單一規則與反例。
- `tools/soak.mjs`：無畫面跑多個種子各數個遊戲日，檢查不變量（無 NaN、不瞬移、資源不為負、需求在範圍內、決定論、沒人長期卡住），輸出一行一種子的摘要。
- `tools/headless.mjs`：用已裝的 Playwright Chromium 開 `index.html`，走玩家正常操作（創角、開始、加速、點選人物、下建造），讀 `window.__sect`（唯讀遙測）斷言，並截一張圖到 `.evidence/`。

## 執行

```sh
python3 -m http.server 8790 --directory loop-sect   # 然後開 http://127.0.0.1:8790/
node --test loop-sect/test/*.test.mjs
node loop-sect/tools/soak.mjs
node loop-sect/tools/headless.mjs
```
