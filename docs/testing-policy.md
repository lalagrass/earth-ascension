# 分層測試與 seed 政策

依擁有人要求與 [#87](https://github.com/lalagrass/earth-ascension/issues/87)，從本政策起減少日常開發的重複模擬。適用 Earth 與 Sect Chronicle；產品範圍、發布權限及原有驗收門檻不變。

## 選擇驗證層級

| 場景 | 預設驗證 | 可支持的結論 |
|---|---|---|
| 文件、純呈現且不改模擬行為 | 文件連結／契約或相關瀏覽器操作；必要檢查與 CI 照常 | 文件／呈現正確；不新增多 seed 實驗 |
| 開發中的快速迭代 | 3 個固定開發 seed，加已知失敗與邊界案例 | 冒煙檢查，不能宣稱分布或驗收通過 |
| 一般局部行為 PR | 5 個固定開發 seed，同設定改前／改後配對，加失敗與邊界案例；完整必要單測與 CI | 狹義修復與回歸證據；下列升級條件優先 |
| 正式量測／高風險變更／里程碑或發布候選 | 完整適用驗收矩陣、原定樣本、策略、時長及保留集流程 | 僅對實際通過的驗收項目下結論 |

「production 增量」是在發布候選／staging 完成驗證，不能先發布再補測。開發回圈可先跑相關單測；提交與合併仍完成 CONTRIBUTING 的全部必要檢查及現有 CI，不刪減 golden、遷移或單測內既有 seed 迴圈。單測 fixture 數量與世界模擬實驗樣本是不同用途。

## 固定樣本與執行方式

- Earth 冒煙集合為 `[0, 1, 2]`，一般 PR 為 `[0, 1, 2, 3, 4]`；故障重現 seed 額外加入，不用好看 seed 替換失敗者。一般世界行為沿用 100 NPC×60 月；局部迭代可先用短流程，但必須覆蓋出錯月份及邊界，提交前恢復受影響的完整時長。
- 遊戲冒煙集合為 `sg-dev-000`～`sg-dev-002`，一般 PR 為 `sg-dev-000`～`sg-dev-004`。僅在相應引擎／場景已交付且支援字串 seed 時使用；按改動涵蓋相關策略與完整已批准切片。既有 golden fixture 原樣保留；尚未交付的全流程標為未驗證，不用純函式測試冒充完整試玩。
- 記錄精確 seed 清單、NPC／策略、時長、版本、head/base/tree、命令、結果與失敗案例。不同設定的數字不可直接比較。配對實驗兩邊使用相同 seed、輸入與環境。
- 先查腳本實際支援的參數；本政策沒有新增快速 CLI。腳本只支援完整報告時，仍用原命令；不能假造 `--seeds` 或覆寫正式報告為小樣本。新增快速模式另依 issue 範圍實作。

## 何時必須立即升級

以下情況在相關 PR／驗收通過前跑完整受影響矩陣，不能延到發布：

1. 要宣稱平衡、機率／分布、技能或策略有效性、效能改善、因果效果，或交付已承諾樣本數的實驗報告。
2. 改共用 RNG、規則版本、結算順序、存檔 schema、遷移、回放或共用測試工具，可能影響多個規則／情境。完整 seed 矩陣之外仍須對應相容性、身份交換、遷移及 hash 檢查。
3. 冒煙失敗、結果與既有證據矛盾、疑似低機率問題，或無法界定影響面；先重現並修復，再擴大受影響矩陣。不能只換 seed 重跑到綠燈。
4. 明確 issue／事前規格要求較大樣本。該承諾優先於 3／5 個預設；本政策不回溯縮小既有 PR 報告、不修改歷史結論。

完整樣本依各產品契約：

- Earth：[M2 A1–A10](m2/acceptance.md) 的 30 個開發 seed（0～29）、10 個保留 seed及各項指定情境／時長照舊；整體世界基準為 100 NPC×60 月，個別驗收依其原定設計。候選門檻仍待校準，樣本跑完不等於 milestone 通過。
- 遊戲：[驗收](../sect-chronicle/docs/ACCEPTANCE.md) AC-C01 的至少 20 seed×42 時段回放保留；SG-15 的 `sg-bal-000`～`sg-bal-099`、六策略及獨立保留集在該階段獲准後執行。本政策不授權 SG-14～17 或尚未批准的實作。
- 保留集不作日常調參／挑案例。正式驗收前記錄集合與使用歷史；若已被實驗調參使用，公開記錄暴露並交產品 PO／擁有人定案替代集合，不把它宣稱成未見資料。不得因結果失敗而事後換保留集或改門檻。

## 復用證據與減少 token

- 審查按 [CONTRIBUTING](../CONTRIBUTING.md#基底前進時如何復用審查) 核對差異、實際合併結果與 CI。未受影響且可重現的作者／前次審查證據可復用；不為無關文件變更重跑完整實驗。需獨立抽查時可先用 3 seed；缺證據、矛盾或相關改動則補完整受影響驗證。
- 測試在程序內執行，seed 數主要影響運算時間，並不按 seed 自動消耗模型 token。將完整 stdout／原始結果存檔，agent 先讀命令、exit code、樣本數、摘要與失敗案例，必要時才讀詳細片段；不要把成功的逐月輸出反覆貼進聊天。
- PR 明列「冒煙」或「完整驗收」、復用證據的 SHA／連結與理由、尚未執行的項目。較小樣本不提供與完整矩陣相同的稀有錯誤檢出能力；不報無依據的節省百分比或通過率。
