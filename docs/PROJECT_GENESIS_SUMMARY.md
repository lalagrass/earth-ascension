# Project Genesis — M1 驗收摘要

本檔摘錄需求與 M1 驗收基準；完整原文已存於 [PROJECT_GENESIS.md](PROJECT_GENESIS.md)。實作狀態見 README 與 review-retro。

## 角色與任務

Founder Delegate、Product Owner、Research Lead、Technical Lead 自主研究、規劃、技術選型並交付第一個可玩的 MVP。可以安排開發、測試、Review 與 Retro；無須複雜代理或 Sprint。M1 完成後停止，不開始 M2。

## 1. Product Vision

現代地球靈氣復甦；自主 NPC、組織、文明演化；角色能力、人格、價值與人生目標；成長、命運、歷史、傳記；未來可擴展跨世代、千年文明及小說生成。核心：「創造一個人，給他一個世界，看看他會成為誰。」玩家決定初始條件，不控制每一步。世界即使無干預亦持續運作。

核心設計原則：Simulation First，Story Second；世界規則與狀態是唯一事實來源；LLM 可提出意圖、策略、敘事，不得竄改事實；NPC 只知道合理可知資訊；無主角光環；能力、人格、環境須有可觀察影響；意外須可追溯；不強造戰爭、奇遇與英雄；支援長期演化、存檔恢復與歷史；AI 提升而不取代規則。

## 2. 世界背景

2026 年現代地球，未知物理現象暫稱靈氣。初期無成熟修仙知識、功法或宗門；科學家、企業、政府、民間組織與一般人逐步探索。未來可能有修仙、靈能科技、靈氣經濟或制度，不能預先保證。

第一版：虛構現代台灣城市；建議一城五區、100 具名 NPC、五初始組織、背景人口統計化、最多三玩家人物、每次手動一個月，初期目標連續 60 個月。不做完整地球、數十萬 NPC、3D 地圖或大型戰鬥。

參考 Our World in Data、World Bank Open Data、現代人口／職業／教育／經濟／組織結構及 Agent-based Modeling；紀錄來源、年份、授權與適用限制。第一版只需基本社會背景。靈氣至少定義地理濃度、生成、流動、消耗、恢復、生物適應、研究、知識、技術應用、修煉風險及代價，不照抄小說體系。

## 3. Character Genesis

五種先天能力：根骨、悟性、意志、感知、社交。預設 30 點，每項 1–10，所有配置遵守點數。測試模式：標準 30、強化 35、高天賦 40；無真實付款，保留日後平衡與 Pay-to-Win 分析資料，不保證高點數成功。

研究 IPIP Big Five、Schwartz Basic Human Values、Generative Agents 記憶／反思／規劃；約 16 題情境測驗產生人格、偏好、價值。不得宣稱正式心理診斷；回答不決定一生；人格與價值持續，重大事件可逐漸改變；人格、價值、能力、技能分開建模。同能力不同人格應產生不同傾向。

人物後天狀態至少有年齡與生命週期、健康、財富資源、教育職業、技能研究能力、家庭社交關係、長短期目標、重要記憶、已掌握知識、對他人的信任態度；依處境行動。

## 4. Autonomous World Engine

時間、NPC 日常、需求、目標、工作、學習、生活、社交、組織、資源、靈氣研究、知識傳播、死亡、事件及狀態驗證。每次推進一月，獨立可恢復結算。

Tier 0 規則決策處理一般生活、工作、學習、休息、社交；Tier 1 處理職業、研究、關係、人生目標；Tier 2 處理組織競爭、特殊發現與重大轉折。Tier 1／2 預留 LLM 介面，但 MVP 無 LLM API 仍完整運行。所有行動由引擎驗證前置條件、代價與結果。

## 5. AI 模型與開發方式

優先使用現有 ChatGPT／Codex 訂閱研究及開發，不購買雲端 GPU 或大量 API tokens；先查實可用工具。Codex 可負責架構、Python、測試、修復、UI；Python Rule Engine 處理大量 NPC、人口資源與結算；LLM Assisted Policy 留給少數重大決策、組織策略、記憶摘要、傳記。先做 RulePolicy，再評估手動 Codex 輔助。不得把個人訂閱當成商業玩家共用後端；可插拔 API／本機模型介面先預留即可。

## 6. Web Dashboard（必要）

A 世界總覽：年月、人口與 NPC、靈氣、組織、重大事件、趨勢圖。B 人物創建：姓名、出身、點數模式與分配、測驗、目標、投放。C 人物觀察：能力技能成長、個性價值需求、關係、目標、行動、記憶、人生事件。D 組織：成員、資源、研究、目標、活動。E 世界歷史：按月事件、文明變化、人物組織事件、回放。F 生命編年：完整生命歷程、轉折、關係、因果傳記、追蹤推薦。

「推進一個月」須真正讀取、模擬、保存、更新及顯示變化；可一天多次手動推進，不得用固定假事件。另有「為什麼他這樣做？」展示目標、資訊、依據與後果。

## 7. Persistence and History

SQLite 世界狀態與事件；存檔、中斷恢復、每月原子結算、防重複、固定 seed、世界版本、生命歷程、重大事件來源、歷史快照與查詢。同 seed、初始資料、規則版本可重現純規則結果；LLM 自由文字不能直接成為世界事實。

## 8. Story Discovery

首版無需長篇小說，但需可擴充故事資料模型。候選可來自人生逆轉、抉擇、衝突、成敗、影響力、執念、關係變化；推薦需真實模擬事件，平淡五年也正常呈現，不編傳奇。長期目標是千年世界史中發現小說人物，MVP 僅生平與事件追溯。

## 9. 前置研究與授權

研究 Mesa、Mesa-LLM、Generative Agents／Smallville、IPIP、Schwartz、OWID、World Bank、Dwarf Fortress、RimWorld、Wildermyth、Crusader Kings III、Cultivation World Simulator、WorldSim。紀錄來源、可直接用的內容、授權、可借鑑演算法架構及不值得現在實作的功能。避免非商業授權程式或素材混入可能商業化產品；不得為研究延遲 MVP。

## 10. 技術建議

優先 Python 3.12、uv、pytest、SQLite、Streamlit、Mesa 或精簡引擎、GitHub、Codex。選簡單、可測試、易維護架構；無必要不做 Kubernetes、微服務、複雜 Multi-Agent Framework、3D、雲端資料庫、分散式系統、GPU 伺服器。

## 11. 驗證與實驗

A 同能力不同人格的職業、社交、學習、研究、長期目標差異。B 多 seed 比較 30／35／40 點發展。C 100 NPC 連續 60 月，檢查成長、目標與關係。D seed 重現、存檔恢復、防重複、資源人口一致、死亡後歷史、無玩家運行。E 實際 Dashboard 建人、測驗、投放、推進 12 月、看人生與編年；用真實結果展示。

## 12. M1 第一里程碑

第一個可玩的月度模擬循環。驗收：Dashboard 可啟動、可建人投放、手動推進一月、NPC 真實自主行為、世界持續變化、人成長且保留歷史、存檔重啟、人物與世界事件可看、基本測試通過。60 月大型實驗與完整 AI 決策不阻擋 M1。

## 13. 工作方式與自主權

確認環境與 GitHub 權限；建立獨立 Earth Ascension repository，優先私人；最小研究與架構、拆解可驗收工作、開發、測試、Review、啟動 Dashboard 端到端驗證、Retro，完成即停。可自行做非破壞修改、一般選型、公開研究、測試、修復、文件、M1 必要調整；需核准付費 API／雲端、真實金流、公開發布或部署、重大產品機制改動、刪重要資料、進 M2。

## 14. M1 交付物與停止條件

提供 GitHub repository 連結與版本、Dashboard 啟動方式、實際介面截圖、已完成與未完成、實測結果、12 月世界範例、一名投放人物生命歷程、限制、簡短 Retro、下一里程碑最值得改善的三件事；分清完成／部分／未做，規劃中的 AI 不可說成完成。完成第一版、測試、Review、Retro 後停止，不開始 M2。
