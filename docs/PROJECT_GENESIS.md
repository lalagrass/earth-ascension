# Project Genesis — Earth Ascension《靈氣紀元》

## 你的角色與任務

你是本專案的 **Founder Delegate、Product Owner、Research Lead 與 Technical Lead**。

請自主完成必要研究、產品規劃、技術選型，並透過可用的 Codex／GitHub 開發能力，交付第一個可遊玩的 MVP。

你可以主動安排開發、測試、Code Review 與 Retro，但不需要建立複雜的多代理組織或冗長的 Sprint 流程。

**你的任務不是持續提出計畫，而是讓第一個可玩的產品真正落地。**

在第一個里程碑完成、測試並交付驗收結果後停止，不要自行展開下一個里程碑。

# 1. Product Vision

建立一款結合以下特色的自主世界模擬遊戲：

- 現代地球與靈氣復甦
- 自主 NPC、組織與文明演化
- 人物初始能力分配
- 人格、價值觀與人生目標
- 人物自主成長及命運變化
- 可回放的歷史與人物傳記
- 未來可擴展為跨世代、千年文明及小說生成系統

核心概念：

**「創造一個人，給他一個世界，看看他會成為誰。」**

玩家並非傳統 RPG 的操作者，而是創造者與觀察者。

玩家可以決定人物的初始條件，但不直接控制其每一個決策。

人物有自己的目標、性格、知識與自由意志，會根據世界環境自主選擇行動。

世界即使沒有玩家干預，也必須能夠持續運行。

## 核心設計原則

1. Simulation First，Story Second。
2. 世界規則與世界狀態是唯一事實來源。
3. LLM 可以提出意圖、策略與敘事，不得直接竄改世界事實。
4. NPC 只知道自己合理能知道的資訊。
5. 人物沒有保證成功的主角光環。
6. 人物性格、能力與環境必須對行為產生可觀察的影響。
7. 世界可以出現意外事件，但事件必須能夠追溯原因。
8. 不為了增加劇情而強行製造戰爭、奇遇或英雄。
9. 支援長期演化、存檔、恢復與歷史追溯。
10. AI 應該提升模擬品質，而不是取代所有規則。

# 2. 世界背景

## 初始時間

2026 年，現代地球。

某個尚未被人類科學理解的新物理現象開始出現，暫時稱為「靈氣」。

初始人類社會不具有完整的修仙知識、修行功法或預先建立的修仙宗門。

科學家、企業、政府、民間組織及一般人會依照各自的目標與知識，逐漸探索這個新現象。

未來可能發展出修仙、靈能科技、靈氣經濟或新的社會制度，但不應預先保證。

## 第一版範圍

請使用一個虛構的現代台灣城市，保留合理的現代生活背景。

初始建議：

- 1 個城市，5 個區域。
- 100 名具名 NPC。
- 5 個初始組織。
- 背景人口以統計方式模擬。
- 玩家可以投放最多 3 名自訂人物。
- 每次手動推進 1 個月。
- 初期目標是能連續推進 60 個月。

請不要在第一版建立完整地球、數十萬 NPC、3D 地圖或大型戰鬥系統。

## 現實背景資料

請研究並適度參考：

- Our World in Data
- World Bank Open Data
- 現代社會的人口、職業、教育、經濟與組織結構
- 現有文明模擬及 Agent-based Modeling 研究

資料應註明來源、年份、授權與適用限制。

第一版只需要足以支撐合理生活及社會運作的背景，不需要建立龐大的歷史知識庫。

## 靈氣規則

靈氣是一種新的、可建模的虛構物理資源。

至少定義：

- 地理分布與濃度
- 生成、流動、消耗與恢復
- 生物適應性
- 研究與知識發現
- 技術應用
- 修煉的風險與代價

不要直接複製某部小說的完整修煉體系。

讓現代人透過研究、實驗、訓練與交流，逐漸發現有效的使用方法。

# 3. Character Genesis — 人物創建

## 初始能力

每個人物具有五種先天能力：

1. 根骨：身體潛能、修行適應性。
2. 悟性：理解、學習與研究能力。
3. 意志：毅力、抗壓與長期投入能力。
4. 感知：觀察、察覺與環境敏感度。
5. 社交：溝通、合作與社會影響力。

初始點數預設為 30 點。

各項能力範圍為 1–10。

必須保證所有人物配置符合點數規則。

## 課金能力實驗

保留以下測試模式：

- 標準：30 點
- 強化：35 點
- 高天賦：40 點

MVP 不進行真實付款。

只建立可以測試不同點數預算的機制。

未來預期允許透過課金增加初始能力，但不保證角色成功。

需要保留相關資料供日後分析課金平衡與 Pay-to-Win 風險。

## 人格與價值觀

請研究：

- IPIP Big Five
- Schwartz Basic Human Values
- Generative Agents 的記憶、反思與規劃方法

建立約 16 題情境測驗。

測驗結果形成角色的初始人格、行為偏好與價值觀。

注意：

- 不宣稱是正式心理診斷。
- 不要讓某個回答直接固定人物一生。
- 人格與價值觀需要具有持續性。
- 重大人生事件可以逐漸改變人物。
- 人格、價值觀、能力、技能必須分開建模。

同樣的能力但不同人格，應該產生不同的行為傾向。

## 人物後天狀態

至少支援：

- 年齡與生命週期
- 健康
- 財富與資源
- 教育與職業
- 技能與研究能力
- 家庭及社交關係
- 長短期目標
- 重要記憶
- 已掌握的知識
- 對其他人物的信任與態度

人物必須根據自己的處境行動。

# 4. Autonomous World Engine

世界引擎負責：

- 時間推進
- NPC 日常行為
- 人物需求及目標
- 工作、學習與生活
- 社交與關係變化
- 組織活動
- 資源分配
- 靈氣研究
- 技術與知識傳播
- 人物死亡與事件
- 世界狀態驗證

每次推進一個月，完成一次獨立、可恢復的世界結算。

## NPC Decision

請使用分層決策機制：

**Tier 0 — 規則決策**

一般生活、工作、學習、休息、普通社交。

**Tier 1 — 較複雜的行動規劃**

變更職業、研究方向、建立關係、選擇人生目標。

**Tier 2 — 重大決策**

組織競爭、特殊發現、人生重大轉折。

Tier 1／Tier 2 預留 LLM 決策介面，但 MVP 必須能在沒有 LLM API 的情況下完整運行。

所有行動都應由世界引擎驗證其前置條件、代價和結果。

# 5. AI 模型與開發方式

目前希望優先使用既有 ChatGPT / Codex 訂閱資源進行開發及研究，不額外購買雲端 GPU 或大量 API tokens。

請先檢查實際可使用的模型及工具，不要假設某個模型或自動化功能一定可用。

建議分工：

**Codex：**

- 架構設計
- Python 開發
- 測試
- Bug 修復
- UI 實作

**Python Rule Engine：**

- 大量 NPC 的規則決策
- 人口與資源結算
- 世界時間推進
- 狀態一致性

**LLM Assisted Policy：**

- 少數重大角色決策
- 組織策略
- 人物記憶摘要
- 人物傳記與敘事

請先完成 RulePolicy，再評估使用 Codex 手動輔助決策是否值得。

不要把個人 ChatGPT / Codex 訂閱當成未來商業玩家共用的 AI 後端。

預留可插拔的 API / 本機模型介面，但第一版不必正式整合。

2. 執行本月模擬。
3. 保存所有結果。
4. 更新 Dashboard。
5. 顯示本月重大變化。

一天可以手動推進很多次。

不得使用固定假事件偽裝成模擬結果。

另外加入「為什麼他這樣做？」功能，呈現人物當下的目標、資訊、決策依據與行動後果。

# 7. Persistence and History

使用 SQLite 作為世界狀態與事件紀錄的主要儲存方式。

必須支援：

- 世界存檔
- 中斷恢復
- 每月原子性結算
- 避免重複執行
- 固定隨機種子
- 世界版本管理
- 人物生命歷程
- 重大事件來源追溯
- 歷史快照與查詢

同一個 Seed、相同初始資料與規則版本，應能重現相同的純規則模擬結果。

LLM 產生的自由文字不能直接成為新的世界事實。

# 8. Story Discovery

但必須建立可擴充的人物故事資料模型。

人物故事候選可以參考：

- 人生逆轉
- 關鍵抉擇
- 社交衝突
- 成就與失敗
- 世界影響力
- 長期執念
- 人物關係變化

故事推薦需要有真實的模擬事件支持。

如果某個角色平淡生活了五年，也應正常呈現，不得強行編造傳奇。

最終願景是能從千年世界史中發現值得寫成小說的人物，但 MVP 只需提供人物生平與事件追溯。

# 11. 驗證與實驗

請至少完成：

### Experiment A：人格差異

相同能力、不同人格。

比較 NPC 在職業、社交、學習、研究與長期目標上的差異。

### Experiment C：長期演化

- 存檔恢復
- 重複推進防護

- 人物死亡後歷史保留

實際開啟 Dashboard：

1. 建立角色。
2. 完成心理測驗。
3. 投放世界。
4. 推進 12 個月。
