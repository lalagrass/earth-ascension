# M3 提案：Creator Directions／開放方向與角色自主探索

狀態：2026-10-17 產品與技術規劃，**待批准；沒有 M3 實作**。玩家希望在推進前對自己的角色輸入「研究靈氣可否應用在中國古武學」這類**大方向**，讓角色自己想問題、決定是否採納及如何行動。本修訂取代先前「只支援一個研究題目」的提案；[組織演化探索](discovery.md)保留為後續候選。

## 產品判斷

**建議做成開放方向，而非題目選單。** 玩家可以輸入不同領域、不同措辭的方向，不必先替角色寫出步驟。角色的解讀受人格、長期目標、記憶、有限情報、能力與資源影響；它可提出數個問題或做法，選一個可行的下一步，也可有理由地暫緩或不採納。玩家不指定當月行動或答案。這符合原始[創造者與觀察者定位](../PROJECT_GENESIS.md)。

**開放文字不等於任意世界機制即刻可用。** P0 接受各種大方向並保存原文，角色可形成相關假說與計畫；實際行動仍須使用有前置、成本及結果規則的有限行動原語。遇到目前世界無法檢驗的主張，介面明示「目前無法驗證」及缺少的能力，不暗中改寫成通用研究，也不保證發現。角色想法是猜想；只有完成行動後帶來源的世界事件才可能成為觀察證據，規則再裁定有限結論。這是由[現有決策規則](../../earth_ascension/m2.py)、[存檔入口](../../earth_ascension/store.py)與 Simulation First 原則得出的設計選擇。

[Generative Agents 原論文](https://arxiv.org/html/2304.03442v2)展示自然語言介入、記憶與計畫的可能性，也指出生成與記憶檢索會出錯；其 25 名代理、兩天模擬不能證明本遊戲 100 NPC、60 月的可行性。[BDI 原論文](https://cdn.aaai.org/ICMAS/1995/ICMAS95-042.pdf)提供「想做」與「承諾去做」有別的概念背景。這些是參考，不能代替本遊戲驗收，也不要求導入大型框架。

### 玩家範例的實際流程

| 時點 | 玩家與角色可見的行為 |
|---|---|
| 推進前 | 玩家選自己的在世人物，輸入「研究靈氣可否應用在中國古武學」。顯示原文與提示：「這是建議，人物會自己判斷；結果不保證。」空白、超長或無法安全保存的輸入才拒絕；**不以固定題目表拒絕其他方向**。 |
| 提交與修訂 | 留下帶人物、月份、版本的玩家方向；可在推進前撤回或修改。原文不直接寫入人物知識、世界事實或當月歷史快照。 |
| 角色思考 | 人物可能問「訓練前後的靈氣變化可觀察嗎？」或「該先找懂身體訓練的人談嗎？」另一人物可能優先穩定生計、查資料，或因證據不足暫緩。顯示其問題、候選步驟、來源與取捨；不預設人物懂某門武術。 |
| 多月探索 | 每月從共同快照選擇可行行動，支付正常成本，與生存及原有目標競爭。成功、失敗或無結果都留下紀錄；角色可依新證據改變問題、重排步驟或放棄，不必每月重複研究。 |
| 回看 | Dashboard 分開顯示玩家原文、人物的問題／計畫、已嘗試行動、觀察結果、未證實主張、採納／暫緩原因；每條「已知」連到人物可得的來源事件。 |

「中國古武學」可作文化靈感與研究對象，但 M3 不聲稱現實中的靈氣有效，不臆造真實門派、招式或歷史。若世界沒有測量某特定效果的規則，人物可提出問題，不能宣布該效果成立。

## P0 範圍與非目標

1. **開放方向輸入。** 每位在世玩家人物最多一個活躍方向，同月最多一個生效修訂。可輸入研究、工作、社交或生活的大方向；不靠單一題目代碼或關鍵詞決定是否受理。文字上限暫定 200 字，Sprint 0 試用後鎖定。不能直接向其他 NPC 下命令。
2. **角色自主解讀。** 從角色已知資訊產生候選問題、短期步驟與暫緩選項。嚴格區分「玩家原文」「角色推測」「計畫承諾」「觀察證據」「已驗證世界事實」。預覽可顯示可能方向，正式解讀以結算時角色當下可知資訊為準。角色可拒絕或重新詮釋並附原因。
3. **有界執行。** 現有 M2 只有少數一般行動，研究目前只產出通用 `practice_basis`；它不能充當「古武學研究證據」。P0 須盤點研究、修習、工作、交流、休息等行動，為可支援的方向加最小、可觀察的題目標的與證據規則，才容許查找／請教／觀察／比較等步驟接到行動。其他方向仍可受理，但若無對應驗證規則，合格結果是角色提出具體問題、指出缺少的前置並有理由地暫緩。新技能、武術、科技或物理效果需另有世界規則與驗收；不能以改寫通用研究敘事冒充進展。
4. **多月但有退出。** 短計畫暫定 1–4 月，定期及重大事件後重評。方向只提供有上限的偏好，不覆蓋健康、生計、資源和原有長目標。無進展、證據反對或目標改變時可調整或停止，合理的持續工作仍容許。trace 記候選、分數、前置、加權與採納／暫緩原因。
5. **證據與有限情報。** 嘗試可以無結果或得到互相矛盾的觀察；只有經規則驗證且人物親歷／合理得知的事實可影響後續選擇。歷史月份只顯示當時已知資料。

非目標：玩家腳本式操控每月行動、無限新世界機制、保證研究成功、每月全員 LLM、付費 API、現實武術功效宣稱、讓 NPC 群體直接接單、組織演化及部署。沒有玩家方向時，M1／M2 世界仍可自行運行。

## 技術契約與方案比較

| 契約 | 最小設計 |
|---|---|
| 輸入與身分 | Append-only 方向／修訂日誌：方向 ID、人物 ID、原文、建立月、修訂號、狀態、預期月份、冪等鍵。提交／撤回用 SQLite 交易檢查人物身分、存活及月份；展示時跳脫 HTML。不能改寫已封存快照。 |
| 解讀與計畫 | 版本化角色提案記錄：方向 ID、角色已知事件 ID、候選問題、假說狀態、候選行動原語、前置、預估成本、選擇／暫緩原因、有效月份。提案可用文字表達猜想，但只能引用角色知道的事實；任何機械效果均須通過規則驗證器。 |
| 同月決策 | `advance(expected_month)` 在同一交易讀取截止時已確認的輸入，凍結共同快照；所有角色先基於同一月初狀態提案，再依既有衝突／結算規則處理資源。先結算者的新發現不得成為其他人物的同月情報。 |
| 回放與版本 | 規則、解讀器、行動原語、世界資料及 RNG namespace 分別版本化。Canonical hash 納入實際消耗的方向修訂、核准提案、決策及結果。固定 seed／相同輸入日誌須重現；專用 RNG 流避免方向輸入改洗無關抽樣。 |
| 舊存檔 | M1 與 M2 0.2.0 不補造過去方向；採已核准的相容讀取或複本遷移。沒有方向時沿原規則，未知版本明確拒絕；保留歷史與 M1 六頁。 |

**方案 A：無 LLM baseline，P0 正式路徑。** 開放輸入一律可保存；用版本化的輕量概念擷取、角色狀態和小型行動原語庫產生不同候選問題，再由規則驗證與選擇。這能提供自主性及零呼叫成本，但對陌生隱喻與跨領域細節的理解可能很淺。不能宣稱「任何文字都能真正理解」；若大量退化成通用行動，P0 即不通過。

**方案 B：可選影子提案，另行批准。** 在輸入或重規劃時，以本機／零付費模型離線提出結構化候選，與方案 A 在封存語料上盲評；影子輸出不改世界。若日後考慮正式啟用，先測品質／延遲／成本，再加 schema、角色資訊邊界、規則驗證、輸出快照與模型版本。回放讀已保存的核准提案，不重問模型；模型不得裁定新事實。**本輪無模型執行或付費呼叫。**

**先決工作：** [#11](https://github.com/lalagrass/earth-ascension/issues/11) 定義當月輸入與不可變快照／hash；[#10](https://github.com/lalagrass/earth-ascension/issues/10) 分清規則、資料及 RNG 版本。[#2](https://github.com/lalagrass/earth-ascension/issues/2)、[#8／#1](https://github.com/lalagrass/earth-ascension/issues/8)、[#9／#4](https://github.com/lalagrass/earth-ascension/issues/9) 的記憶、目標及計畫修復影響角色思考的可信度；先由貢獻者 PR 修復，維護者依[M2 審核計畫](../m2/contribution-review-plan.md)重跑 A1–A10，再排 M3。不能把 M3 功能塞進修復 PR。

## 可執行驗收：候選門檻於 Sprint 0 封存

| 項目 | 對照、樣本與判準 |
|---|---|
| 開放輸入與相關性 | 先封存至少 40 句方向，含靈氣×古武學、完全不同的研究題、社區幫助、人際關係、模糊與不可檢驗方向；另留至少 10 句開發期未見的 holdout。不同人格／知識／資源情境產生候選。兩名盲評者評「與原文相關」「符合角色已知資訊」「可行性判斷正確」各 0–2 分：可執行時給可驗證步驟，**不可執行時具體說明缺失並暫緩，也可得滿分**。候選線：各項平均 ≥1.5、分歧仲裁，待首輪試驗校準後鎖定。任何非空合法文字被固定題目表拒絕，或無理由地全映射同一行動，皆失敗。 |
| 自主與因果 | 固定能力／世界、30 seed 配對有方向／無方向，另配對同方向不同人格、同人格不同經歷；比較 24 月內實際行動序列、計畫變更與 trace。候選線：至少 18/30 seed 有可解釋的行動路徑差異；不同情境不能只換敘事文字。另設同一方向的可控 fixture：有能力／情報／資源者可採納，有健康／生計壓力或缺前置者須暫緩，並核對 trace 與實際機械決策一致；緊急 fixture 30/30 不因方向失去必要行動。數值待 M2 修復後基線校準，封存後不得追結果改線。 |
| 假說與結果 | 為至少兩種可支援方向預定不同的題目標的／證據結果；同一角色、seed、能力和世界下交換這兩種方向，必須出現題目相關步驟或優先序差異。另設原例及其他方向可做／暫不可做步驟；同一快照消融方向及已知事件，檢查 6–12 月後提案與決策的來源鏈。可支援方向需觀察到題目標的、來源及後續使用的差異，不能只換研究文字；不可支援方向須正確暫緩。未經嘗試的結論、角色未知情報、無規則支持的效果皆 0 次；已驗證事實與猜想在 API、Dashboard、歷史中分開。 |
| 回放與舊檔 | 30 seed×60 月，同 seed／修訂序列／版本重跑，canonical hash 30/30 相同；測撤回、重送、crash、同月提交邊界。M1 0／12／60 月和 M2 0.2.0 存檔複本讀取或明確遷移；M1、無方向 M2 及 Chrome 端到端回歸。 |
| 成本 | 修復後 M2 基線與 M3 同機配對 100 NPC、最多 3 玩家人物、60 月、30 seed；報逐 seed 耗時、DB／API 大小與異常值。候選線：耗時中位 ≤1.2×、任一 seed ≤1.5×、DB 中位 ≤1.2×；Sprint 0 量基線後先鎖定或書面修訂。正式路徑 LLM 呼叫與費用皆 0。 |

失敗條件：看似自由的輸入實際只觸發一個通用研究標籤；角色想法變成世界事實；每種人格都做同樣事；生計被輸入強制覆蓋；無法說明採納／拒絕原因；回放或舊檔失效。

## 有限 backlog 與決策點

| 階段 | 交付與停止條件 |
|---|---|
| Discovery（本輪） | 確認「開放方向，角色自己想」為 M3 候選主軸，交產品語義、輸入／提案／證據分層、方案與驗收設計；**只改規劃文件**。 |
| Sprint 0（M2 修復及批准後） | 封存方向語料、holdout、盲評規則及 30 seed 基線；盤點可執行行動原語與不可驗證邊界；鎖輸入／版本／hash 契約和候選門檻。M2 前置或基線不足即停止。 |
| Sprint 1 | 輸入／修訂日誌、角色候選問題與步驟、規則驗證、暫緩原因；先完成無 LLM baseline。不能只靠文字看起來相關，須有可解釋的決策差異。 |
| Sprint 2 | 多月重評、證據來源與 Dashboard、回放／遷移／Chrome／100 NPC×60 月驗收；獨立 PR review。開放語料大量失配時不能宣稱 M3 完成。 |
| 可選後續 | 只有無 LLM baseline 的限制經測量且使用者批准後，才試零付費影子提案；是否正式引入 LLM 與花費另作產品決策。 |

**待使用者決策：** M3 是否以開放方向取代[組織演化](discovery.md)作首要主題；若無 LLM baseline 的語義品質不足，是否允許另行研究模型輔助。本文不授權 M3 開工或付費呼叫。
