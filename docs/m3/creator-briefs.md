# M3 提案：Creator Briefs／玩家研究委託

狀態：2026-10-17 產品與技術規劃，**待批准；沒有 M3 實作**。使用者希望在推進前，對自己投放的人物輸入「研究靈氣可否應用在中國古武學」這類想法。M3 建議先讓**研究問題**可被表達、確認、追蹤和有限影響決策，再評估其他類型的客製行為。原先的[組織演化探索](discovery.md)保留為後續候選，不同時塞進本里程碑。

## 判斷與邊界

**值得做。** 玩家目前只能在創角時從五個固定目標選一個；M2 新人物的自由目標文字會被拒絕，研究結果也只有通用的「靈氣觀測紀錄」與 `practice_basis`。直接增加文字欄只會顯示不同句子，無法證明人物真的研究了指定問題。這是由[現有程式](../../earth_ascension/m2.py)及[存檔入口](../../earth_ascension/store.py)得出的工程判斷。

建議產品語義是**「我給人物一個研究提議」**，不是「我命令人物下月一定研究，更不是我決定答案」。角色仍可因健康、資源、已知情報與自身目標而延後或不採納。沒有實驗結果時，歷史應寫「尚無可重現證據」，不能把玩家輸入或模型文字寫成發現。這延續原始[Simulation First 原則](../PROJECT_GENESIS.md)與 M2 的有限知情設計。[Generative Agents 原論文](https://arxiv.org/html/2304.03442v2)展示自然語言介入和計畫，但也報告記憶細節編造及錯誤檢索；它**沒有**驗證本遊戲 60 月或此介面的效果。本提案的「文字→經確認的結構化委託→規則結果」是本專案設計選擇，並不複製其 LLM 架構。[BDI 原論文](https://cdn.aaai.org/ICMAS/1995/ICMAS95-042.pdf)提供「願望與實際承諾不同」的概念背景。

### 使用者範例的實際流程

| 步驟 | 玩家所見／世界處理 |
|---|---|
| 第 12 月，選自己的在世人物，輸入「研究靈氣可否應用在中國古武學」 | 保留原句作玩家研究問題；它不是世界已證實的知識，也不代表人物已懂某一門武術。只有玩家人物可收委託，不能直接指定 NPC。 |
| 送出前顯示預覽 | 「理解為：研究方向＝靈氣與身體技法；目的＝檢驗是否可應用；你的人物可能先補基礎、研究、暫緩或放棄；不保證發現。」玩家確認或取消。若題目無法明確對應到支援方向，要求選方向或保持未送出，**不靜默套成通用研究**。 |
| 確認後、按「推進一個月」前 | 儲存一筆有版本的**玩家輸入**，月數與人物明確；不更改當月歷史快照或憑空新增角色知識。可在推進前撤回／修改，留下可審計修訂紀錄。 |
| 月結算 | 從共同凍結快照讀取此委託，作為有限的研究偏好及可行性線索；角色仍依自身分數、資源與固定 RNG 選行動。若缺 `practice_basis`，先作基礎研究，不能跳到應用成果。只有真的選研究且付出成本時才記研究嘗試。 |
| 後續月份 | 介面顯示「已受理／補前置知識／研究中／暫緩（原因）／有可重現結果／結束」，連到每次嘗試、相關發現與訓練效果的真實事件 ID。沒有證據時不得自動宣布古武學成功。 |

「中國古武學」在 P0 是玩家原文及文化靈感；可操作的遊戲題目是虛構世界中的「靈氣與身體技法」。M3 不建立真實中國武術資料庫，不聲稱現實中靈氣存在或能應用於武術，也不生成某門派的歷史或招式。

## P0 產品範圍

1. **一個活躍委託。** 每位在世玩家人物最多一筆活躍研究委託；同月最多一個生效版本。文字上限暫定 80 字，確切長度在 UI 試用時校準；原文只作顯示與追溯，永不作程式指令。NPC 不可由玩家直接設定。每次推進前可撤回或改題；在既有計畫檢查點（目前每四月）評估是否續留。
2. **小型題目表。** P0 只支援 `qi_body_technique`（靈氣與身體技法）這一個專門研究方向，加上既有 `practice_basis` 作前置。使用者可輸入自己的問題；小型、可版本化的詞語／句式表產生預覽，玩家確認方向後才生效。詞語無法識別或有歧義時要求明確選擇，不產生機械效果。題目表規定可觀察前置、研究成本、證據、可能結果和已知者的效果，往後可加主題而不重寫月結算。
3. **自主接受。** 委託僅影響角色本來可選的研究行動分數及研究子題；加權有明確上限（候選：不超過現有長期目標加分 `0.6`，需在 Sprint 0 校準）。健康／生計限制、原有長目標與人格仍作用。決策 trace 記 `brief_id`、加權、可行性及採納／暫緩原因，玩家可看見「這次為何沒有照提議做」。
4. **真實研究結果。** 專題研究須有基礎知識、實際研究行動、支出及獨立用途 RNG；可多次未得可重現證據。若取得有限專題事實，只有親歷或實際交流得知的人物能在後續 `修習` 使用一個**有界且可量測**的成本／效果差異（具體數值待試驗校準）。通用 `practice_basis` 與專題事實分開，不能只換發現文字。
5. **可見可回放。** 推進前顯示已確認的委託，推進後顯示研究狀態、所花資源、實驗事件、已知事實與最近未採納原因；歷史月份只能看當時已有的輸入和結果。M1 六頁與不送委託的 M2 流程照常。

P1／非目標：任意自然語言行為命令、保證研究成功、所有 NPC 接受玩家委託、完整武術／職涯系統、因一句話創造新科技、每月 LLM 決策、付費 API、組織演化、M4 或部署。若 P0 證明題目映射與角色回應可靠，再評估社交／工作類委託及可選的**離線、零付費影子解析**；影子輸出不改世界。

## 技術契約與依賴

| 契約 | 最小設計 |
|---|---|
| 玩家輸入 | append-only `brief_intake` 或等價修訂日誌：`brief_id/person_id/raw_text/topic_id/interpretation_version/created_month/revision/status/expected_month`。預覽不寫入；確認與撤回以 SQLite 交易、人物身分、當前月與冪等鍵驗證。原文顯示需 HTML escape。 |
| 月結算 | `advance(expected_month)` 同一交易鎖內讀入截至當月的確認版委託，加入下月共同決策快照；決策、結果及 `state_hash` 納入**實際消耗的結構化輸入版本**。重啟或重播用相同輸入日誌與 RNG 會得到同結果。 |
| 研究狀態 | 一個 `research_brief` 狀態機：`queued → prerequisite/researching/deferred → supported/inconclusive/withdrawn`；`supported` 必須有真實專題事件和已知 fact ID。未研究、未成功與情報未知彼此不同。所有轉移有月份與原因。 |
| 隨機數 | 為題目嘗試加 `brief-topic` 專用 RNG 流；不借用一般行動選擇或通用發現流。世界資料、規則與 RNG namespace 各自版本化；規則改版不得無意重洗所有人的抽樣。 |
| 舊資料 | 既有 M1、M2 0.2.0 存檔不臆造過去委託。須能以已核准的相容或複本遷移路徑讀取；沒有委託時等同原本規則。未知版本明確拒絕。 |

**先決 PR：** [#11](https://github.com/lalagrass/earth-ascension/issues/11) 必須先定義當月玩家輸入與不可變快照／hash 的語義；[#10](https://github.com/lalagrass/earth-ascension/issues/10) 必須先拆清規則、資料及 RNG 版本。[#2](https://github.com/lalagrass/earth-ascension/issues/2)、[#1／#8](https://github.com/lalagrass/earth-ascension/issues/8)、[#4／#9](https://github.com/lalagrass/earth-ascension/issues/9) 的記憶與目標缺陷若未解決，角色對研究經歷的記憶與長目標可能失真，委託效果也難以解釋；故須先完成並重跑 M2 驗收。這是順序依賴，不把 M3 功能混進他們的修復 PR。

## 驗收與失敗條件（候選門檻須於 Sprint 0 鎖定）

| 項目 | 可執行檢驗 | 判準 |
|---|---|---|
| 輸入理解與安全 | 先封存 30 句語料，含原例、同義／模糊／完全無關題；讓不同使用者確認預覽；測超長、HTML、重送、撤回、改題、非玩家人物及已故人物。 | 原例與預先標記為支援的同義句全部映射 `qi_body_technique`；不支援句子 0 次靜默映射／0 次世界事實新增；拒絕有明確原因。語料須先封存再開發解析規則。 |
| 自主性及可見影響 | 固定能力／人格／世界，30 seed 配對「有委託」與「無委託」，0–24 月；另做低健康／低財富、無基礎知識 fixture。記研究月數、專題嘗試、暫緩原因及決策 trace。 | 至少 18/30 seed 在 24 月內有**研究行動路徑**差異，不能只靠同一研究行動換題目通過；有委託的選擇 trace 須正確引用委託。在事先鎖定、原本選生計／休息的緊急 fixture 中，加入委託後 30/30 仍選生計／休息。18/30 為**待校準候選**，Sprint 0 基線後先鎖定，不能依結果移動。 |
| 專題因果 | 對同一保存快照固定其他狀態，分別移除委託及已知專題 fact；檢查同一研究行動是否走不同題目、後續 `修習` 成本／效果、來源引用；負對照用無關事實。 | 具研究前置的同動作 fixture 30/30 正確切換子題；有來源、無同月提前使用；確有專題發現的 fixture 30/30 顯示事前定義的有界差異；無發現時 0 次假成果。不能把所有世界都必須成功當通過線。 |
| 回放與相容 | 同 seed／輸入修訂序列重跑 30 seed×60 月；M1 0／12／60 月與 M2 0.2.0 存檔複本測試，含 crash／重送情境；Chrome 走原例輸入→預覽→確認→推進→點來源及歷史。 | 相同輸入與版本 canonical hash 30/30 完全相同；一筆確認最多作用一次；舊檔不失資料；M1 與 M2 原流程回歸。 |
| 成本 | 100 NPC、最多 3 名玩家人物、60 月，30 seed 與修復後 M2 基線同機配對；報逐 seed 耗時、DB／API 大小、異常值。 | 候選線：耗時中位 ≤基線 1.2×、任一 seed ≤1.5×、DB 中位 ≤1.2×；Sprint 0 見基線後先鎖定或修訂並記理由，不能事後移線。正式路徑 LLM 呼叫與費用都為 0。 |

當委託只增加研究字數、沒有選擇／前置／結果差異；當人物被迫無視生計；當原句直接變世界事實；或當舊存檔／回放無法解釋時，M3 失敗。

## 有限 Sprint 與決策點

| 階段 | 交付與停止條件 |
|---|---|
| Discovery（本輪） | 確認「玩家研究委託」是 M3 首要主題，鎖 P0 只做研究題目及一個專門方向；提供上面例子的預覽與失敗語義。只交規劃文件。 |
| Sprint 0（M2 修復及批准後） | 封存 30 句語料、30 seed fixture、M2 修復後的行為／效能／舊檔基線；鎖支持的題目、影響上限和候選門檻；完成輸入／hash／版本契約。先決 PR 或基線未就緒即停止。 |
| Sprint 1 | 實作輸入預覽與確認、修訂日誌、單一題目狀態機、既有研究行動的有限偏好和前置驗證；先用純規則與固定 seed 跑小 fixture。 |
| Sprint 2 | 增加專題成果及有限 `修習` 效果、Dashboard 原因／歷史、30 seed 配對、Chrome 與遷移回歸；獨立 PR review。若只剩文字效果或回放不一致，不宣告完成。 |

**待使用者確認：**M3 是否以這個「有限、可解釋的玩家研究委託」取代組織演化作首要主題？是否接受 P0 先支援「靈氣與身體技法」一個專題，其他自由題目先要求確認／標示不支援？本提案預設「是」，不因此開工。
