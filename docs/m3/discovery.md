# M3 備選探索：Living Institutions

狀態：**先前備選，待產品確認；不開工、不寫 M3 規則。** 使用者後續提出推進前輸入大方向、由人物自己想的需求，現優先評估 [Creator Directions／開放方向與角色自主探索](creator-briefs.md) 作 M3 主題；若採用，組織演化延後另評。兩份提案不能同時成為同一輪 P0。本提案仍以 [M2 未結驗收](../m2/implementation-review-retro.md) 和 [PR 審核計畫](../m2/contribution-review-plan.md) 為入口。M2 P0 重要記憶、目標分布、版本／回放契約尚未收斂，M3 實作須等修復 PR 通過及 A1–A10 重驗後再排期。

## 建議的產品問題

目前五個組織有會員、資源、研究數值，但月底只按存活會員研究技能加研究進展，資源按**存活會員人數**作固定增減，`activity` 為同一類敘述；組織沒有可觀察的取捨，也沒有由知情會員傳入的有限情報。這是由 [`m2.py` 的組織結算](../../earth_ascension/m2.py) 推出的產品缺口。原始願景要求自主 NPC、組織與文明演化，但不要求本輪立刻做完整經濟或全球政治。

**建議 M3 主題：**讓現有五個組織在既有城市中作少量、有資源代價且可追溯的選擇，讓人物與組織互相影響。優先觀察「同樣資源但不同成員與知識的組織是否走出不同路徑」，而非增加事件數量。

## 有限 P0 候選與可見流程

1. 每組織一個已保存的四月週期焦點，限「研究／招募／維持服務」三種；由上月會員能力、已知情報及預算選擇，每四個月或資源危機時檢查。焦點可保持不變；轉換有來源及原因。
2. 組織只取得會員已知且願意分享的結構化發現；不能把全局 `world.knowledge` 視為組織自動知情。會員加入或離開須有時間與原因，組織不能回頭知道入會前尚未傳入的資訊。
3. 資源支出、會員貢獻與研究成果採清楚的存量流量帳。競逐同一稀缺機會時基於同月凍結快照、明示容量與固定用途抽樣；不得以遍歷順序決勝。
4. Dashboard 組織頁顯示焦點、資源收支、已知發現、會員變動及來源事件；歷史月只顯示當時資訊。保留沒有突破、資源不足或成員流失的普通結果。

**本階段非目標：**新城市／大量新增 NPC、完整宏觀經濟、家庭與跨世代、戰爭／外交、複雜組織圖、宗門劇情保證、LLM 自動策略、付費模型、公開部署。若純規則已足夠，不做 LLM 影子實驗。

## 事前驗收草案

| 面向 | 檢驗設計 | 通過／失敗判準 |
|---|---|---|
| 成員與情報確實作用 | 30 seed，每 seed 配對「完整組」與「無組織情報作用組」，保持成員能力、資源、世界 seed；另交換組織標籤及插入順序。 | 有來源的情報至少在部分組織月改變焦點分數或選擇，且沒有提前知情；固定 seed 同版重播一致。作用率門檻在基線試跑後預先鎖定。 |
| 有意義而非強迫的路徑差異 | 比較四月週期焦點分布、持續月數、研究／招募／服務實際產出及零突破月份；逐個 seed 公布分布。 | 焦點不是全員永遠同一類，也不靠無原因每次檢查就換；是否設定集中度數值上限需先校準。不得用固定「重大事件」觸發來製造差異。 |
| 資源與同月公平 | 小型 fixture 測雙組織競逐、會員同月轉入、同月研究發現、資源不足；反轉遍歷順序及邏輯身份。 | 資源不負值、不重複花費，同月新情報次月才可用，身份交換後相應結果不變。 |
| 存檔與可觀測性 | M1 0／12／60 月與 M2 0.2.0 存檔按已核准路徑讀取／遷移；Chrome 走組織頁→來源事件→歷史月份。 | 不默默覆寫舊檔；未知版拒絕；來源 ID 可追；M1 六頁、M2 人物觀察與 A1–A10 回歸。 |
| 成本 | 100 NPC、5 組織×60 月，與完成修復後的 M2 同機配對 30 seed，公布逐 seed 耗時、DB 及 API 大小。 | 速度／大小上限在量得修復後 M2 基線後鎖定；先前未校準的 M2 逐 seed 3× 線不能被當成 M3 已達標。 |

## 有限研究與 Sprint 草案

| 階段 | 產物與停止點 |
|---|---|
| Discovery（僅此備選獲選時） | 與產品方確認是否以「組織選擇」為 M3 主題；定義待修復 PR 合併後如何封存 M2 基線，並盤點組織資料契約與 2–3 個玩家可觀察情境。只做規劃。 |
| Sprint 0（待批准） | 封存相容存檔、固定 seed 與效能；定資源帳、情報可見範圍、四月週期決策 fixture、未校準候選線。若 M2 版本／回放仍未穩定，停止。 |
| Sprint 1（待批准） | 最小組織焦點、有限情報與資源結算，附決策 trace、來源與消融；先通過順序／守恆測試，再擴 UI。 |
| Sprint 2（待批准） | 組織頁歷史回放、30 seed 配對、Chrome 操作、M1／M2 回歸及獨立審核；未通過時保持 M3 未完成。 |

## 需產品方先決定

1. M3 是否採目前較直接回應玩家需求的[開放方向與角色自主探索](creator-briefs.md)；「Living Institutions」及**儲存與回放健全性**均為備選。若舊檔、快照或 API 增長阻礙 60 月使用，應先解決該阻擋。
2. 五個既有組織是否足夠，玩家本里程碑是否只觀察，仍不直接下達策略指令？本提案預設兩者皆是。
3. M2 哪些剩餘候選門檻必須達成才允許開 M3；至少須先解決有效記憶、目標／計畫一致、舊檔與回放契約，並誠實處置 A4 0／0 及 A7 異常。
