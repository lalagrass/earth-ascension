# M2 有限 Sprint backlog、依賴與決策

狀態：**僅規劃，尚未開工**。每個 Sprint 必須有可演示輸出、驗收與停止條件。依賴順序從上到下；不得藉 M2 提前啟動 M3。產品範圍見[PRD](prd.md)，技術契約見[技術方案](technical-design.md)。

| 順序 | 工作包（最小實作） | 依賴／完成證據 |
|---|---|---|
| Sprint 0：基線與契約 | 封存 M1 0／12／60 月測試存檔、固定 seed 與 canonical hash；量測 100 NPC×60 月時間與 DB 大小；敲定結構化事件／版本／遷移契約、資料限制、實驗 fixture 與未校準門檻。 | 使用者批准 M2 後才開始；產物是經 review 的契約與基線。未取得基線不得調 M2 效果門檻。 |
| Sprint 1：可信月結算 | 分離 schema／rules 版本與 RNG 流；凍結決策快照、intent、衝突解決、統一提交；保留 M1 legacy 路徑。先用社交／研究衝突 fixture 驗證順序與回放。 | 依賴 Sprint 0；[A6、A9、A10](acceptance.md#可執行案例與通過線) 的硬性測試通過。若同步管線破壞回放，停止加人物功能。 |
| Sprint 2：持續人物狀態 | 加一個活躍長目標、短計畫、明確重規劃；結構化事件記憶與有限情報；定向信任；有界人格／價值變化。每項有行為消融開關與決策 trace。 | 依賴 Sprint 1；[A1–A5](acceptance.md#可執行案例與通過線) 的 fixture 通過，禁止僅用事件文字作證。若 plan template 相對 utility+commitment 無增益，保持較小版本。 |
| Sprint 3：整合與產品驗收 | Dashboard 當月／歷史的目標、記憶、關係、原因及遷移後 `legacy_custom` 目標的明確重選操作；M1 存檔遷移或明示唯讀路徑；30+10 seed 實驗、100 NPC×60 月、瀏覽器 12 月流程、M1 回歸與獨立 review。 | 依賴 Sprint 2；[A1–A10](acceptance.md#可執行案例與通過線) 全部硬性條件通過，行為門檻按 Sprint 0 鎖定版本判斷；未通過則修正，不宣稱 M2 完成。 |

可選 P1（不阻礙 M2）：整理少量真實決策快照供離線影子比較，統計方案、成本與盲評；不接 API、不讓影子結果修改世界。若規則基線已足夠或增益不足，即不開啟 LLM 項目。

## 風險與對策

| 風險 | 對策／停止訊號 |
|---|---|
| 舊資料文字缺少來源，遷移時捏造過去 | 原快照保留；legacy 記憶唯讀顯示，不參與因果分數。未知版本拒絕；先用副本驗證。 |
| 同步結算後仍有資源競爭偏差 | 在凍結快照上計算意圖，另設容量與獨立 seeded tie-break；交換順序／ID fixture。 |
| 目標僵化或工作被錯誤懲罰 | 只處罰無收益停滯；健康／生計緊急可打斷；觀測完成率、重規劃率與收益。 |
| 事件與人格變化過度戲劇化 | 白名單、有界、累積規則；無事件不漂移；與凍結人格／記憶消融比較。平淡結果合法。 |
| 記憶爆量、追溯斷鏈或 60 月變慢 | 每人活躍記憶設界、原始事件保留；驗證引用、時間與 DB 大小；超過效能門檻先剖析。 |
| LLM 幻覺與成本擴張 | 正式基線無 LLM；影子只看受限資訊、提既有 action ID；付費呼叫保持零。 |

## 待使用者確認的決策

1. M2 產品範圍是否以上述 P0 為界，延後家庭／完整職涯／組織策略與敘事生成？
2. 舊 M1 存檔偏好：**預設複本單向遷移後在 M2 續玩**，或成本過高時採 M2 唯讀、原 M1 legacy 模式續玩並另評估遷移？不得默默覆寫原檔。
3. M2 驗收通過後是否另開一輪評估少量 LLM 影子試驗？本輪不呼叫付費模型，也不承諾上線。

這三項待使用者批准後才進入實作；本輪到文件提交為止。
