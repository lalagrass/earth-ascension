- M1 引擎原檔保持不變，資料庫依保存的版本分派。新資料庫預設 M2；`python3 -m earth_ascension.migrate SOURCE DESTINATION` 複製 M1 SQLite，轉換最新快照，保留原檔及較早 M1 歷史。未知規則版本與未知遷移來源拒絕。遷移測試實際建立 M1 0、12、60 月存檔並接續 M2 一月。

- 自動化：`python3 -m unittest discover -s tests -v` 通過 19/19（含 M1 原五測）；`node --check earth_ascension/static/m2.js` 通過；`artifacts/run_m2_http_demo.py` 在全新本機資料庫通過建人、12 月推進、重複月保護、歷史及決策資料。[HTTP 與瀏覽器驗證限制](../../artifacts/m2-ui-verification.md)。

## 獨立 review 與修正

獨立唯讀程式審查指出未知 `rules_version` 未拒絕、同月雙人分享只保存先到來源、完成目標丟失因果、信任逐筆截斷、里程碑歸因偏向較小 ID、投影欄位未核對，以及事件來源不可點選。上述已逐項修正，加入定向回歸測試；最後唯讀 spot check 重跑 seed 21 的雙向信任反例，確認正向里程碑歸給實際成功的 ID 6，本次未再發現阻擋。審查也指出 A3 原 probe 僅與全部刪除記憶比較；現加入等量無關記憶對照並在實驗說明其限制。舊版 A2 首輪結果前六個月僅 5/30，未達候選門檻；之後修改了事前介入情境，最終結果須標明調整並以保留 seed 檢查，不可把首輪當通過。

## 設計取捨、剩餘風險與下一步

- P0 只維持一個活躍目標，完成後轉為穩定生活；沒有候選目標池、職涯／家庭、通用傳聞或自動故事導演。健康與生計透過分數及既有資源成本影響選擇，未另造緊急目標類型。這比事前技術方案的上限更窄。
- 實際 `last_decision` 用 `action/scores/noise` 等欄位保存原始數值，與方案中的示意名稱 `selected_action/candidate_scores` 不同；追溯功能以實際資料為準。事件無通用的公開可見範圍欄位，M2 將知識取得限定為本人發現及直接交流，不能據世界事件表推斷所有 NPC 都知情。
- 記憶保留最多 24 筆，但完整事件與人物 chronicle 隨每月 SQLite 快照重複保存；長期檔案增長是已知成本。參照 A7 的實際比率決定是否需要下一輪不改規則的儲存優化。
- 固定 seed 與 canonical hash 已在相同 Python 執行環境驗證；跨 Python 版本的 `random.Random` 重播一致性尚未聲稱。長期存檔應記錄執行環境並保留原始快照。
- 尚須在可用瀏覽器中完成 A8 與 M1 六頁截圖／點擊，補 A3 自然事件、A4 人工原因與 A9 故障矩陣，才可宣稱 M2 P0 完整驗收。候選門檻未在 Sprint 0 事前正式校準，報告只作工程診斷。
- 未完成項目由使用者確認優先順序後另輪處理；本次不擴張至 M3、LLM 或部署。
