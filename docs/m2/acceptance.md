# M2 驗收與實驗方案

這是**將來實作後**可執行的驗收規格，不是本輪已跑的結果。測量遊戲機制的內部一致性，不能推論真實人類行為。所有標「待校準」的數值是事前候選門檻：Sprint 0 先鎖定 M1 基線、fixture 與機器環境，開發前定稿；不得看完 M2 結果才調整通過線。原始結果、失敗 seed、腳本版本與 canonical state hash 均要留存。

本輪僅為修正不合理候選上限而做一次 M1 測量：此機器／預設 seed 2026／100 NPC／60 月，`Store.advance` 共約 1.28 秒，SQLite 約 79.75 MiB、世界事件 6659 筆；這**不是**多 seed 效能驗收，也不是 M2 結果。Sprint 0 仍須在固定機器與 30 seed 重測。

## 共同設定、對照與防混淆

- 固定 30 個事前列明的 seed（候選：0–29，**待校準**）作 100 NPC×60 月主樣本。另保留 10 個未調參 seed 作確認樣本。每組從相同月 0 或同一 checkpoint 複製，能力、年齡、區域、工作、起始資源、組織、世界靈氣路徑一致；只改指定自變量。相同 `actor_id/purpose/month` 隨機流配對，使新增抽樣不改外生環境。報告每 seed 配對差、分布與 bootstrap 95% 區間，不以單一精彩案例判定。
- 對照：A＝M1 legacy（現況與效能基線），B＝M2 規則完整，C＝M2 去持續計畫，D＝M2 去記憶對決策作用（保留事件紀錄），E＝M2 凍結人格演化；另用明確 fixture 檢查局部機制。M1 與 M2 規則版本不同，不能以逐月 state 完全相同要求跨版結果。消融組須保持其餘 M2 規則與亂數鍵一致。
- 預先聲明核心指標：目標延續月數與有原因重規劃率；行動占比與路徑差；無收益重複率（連續 ≥4 月同動作、無生計／技能／目標進度收益且未重規劃）；事件後 6／12 月的可追溯記憶／關係／目標／行動；人格單月與年度變化；公平性；執行時間與檔案大小。另人工盲看固定抽樣的平淡及有事件人生，評「原因可由狀態驗證」比例，評估者不能知道組別。
- 校準不能改動確認樣本。記錄任何死亡／資源枯竭等競爭事件；對存活條件的統計應同時報完整樣本與存活子集，以免選擇偏誤。角色名字與人物 ID 對調測試順序偏差。不要為通過門檻注入特殊事件。

## 可執行案例與通過線

| ID | 做法／對照 | 通過線或失敗條件 |
|---|---|---|
| A1 相同能力不同人格 | 同一 checkpoint 複製指定人物（相同能力／環境／起始經歷），只改社交對探索、盡責對安全等預先定義的人格／價值維度；30 配對 seed 跑 24 月。比較目標、研究、社交、工作占比與計畫延續；對照 M1 及 C。 | 指定偏好方向在至少 75% 配對 seed 的相關行動占比同向，配對中位差 ≥10 個百分點（候選，**待校準**）；至少一個目標／計畫指標在 B 相對 C 有改善且不靠無效行動。方向錯、效果只由能力／外生條件造成、或每個角色都走同一路徑即失敗。 |
| A2 相同人格不同經歷 | 月 6 checkpoint 複製同一人物。對實驗支施加規則允許且有 event ID 的重大關係挫折／研究失敗或成功；對照支不施加或給等資源的中性事件。起始人格、能力、資源及其後外生抽樣相同；跑到月 18，另設 D／E。 | 至少一個**事前指定**選擇情境在 6 月內出現可解釋分岔，原因引用事件／信任／知識鏈；沒有事件時不得憑空出現。差異不要求每 seed 都分岔，候選 ≥70% 可行 fixture seed（**待校準**）。報告經歷對資源的直接效應，不能誤當人格效應。 |
| A3 重大事件後 6–12 月 | Sprint 0 事前列三種事件：研究突破、重大關係挫折、目標失敗；各用至少 30 個 fixture seed，事前指定月 6／12 的可行行動選項及決策機會條件。自然發生事件也逐件記錄，全部符合條件者進分母，排除者列原因，不事後挑精彩案例。probe 同一決策快照：完整記憶、只移除目標記憶、移除等數量無關記憶。**保持信任、技能、資源、人格及亂數不變**；另跑整段「不更新記憶」消融與 D。 | 完整與相關記憶移除組在事前定義的機會中有決策分數／排序差，無關記憶移除組不應有同方向效果；6／12 月的 trace 能鏈回真實 event ID。候選 ≥80% **全部合格 fixture probe** 引用正確且能解釋差異（**待校準**）；自然事件另報合格率與效果，不納入此門檻。只剩信任效果卻宣稱記憶直接生效、或無因果事件引用即失敗。允許事件影響消退。 |
| A4 目標與重複 | 對比 B／C，從 60 月樣本量化目標連續性、完成／放棄原因和無收益重複；審查連續工作／研究個案。 | 有實際收益的持續工作不得被懲罰成無理由頻繁跳轉；無收益重複率 B 不高於 C，候選下降 ≥25%（**待校準**）；至少 90% 目標切換有明確觸發事件或檢查月（**待校準**）。變成每月換目標或全員同一目標即失敗。 |
| A5 人格演化 | B／E 成對跑 60 月；fixture 驗證單事件、重複經歷、無事件 12 月。區分短期需求／情緒、關係信任、慢速人格／價值。 | 所有變化有事件引用並符合有界上限；無事件不漂移；單次事件不能瞬間翻轉 0–1 維度；重複經歷可漸進且在事前選擇情境造成行動差。上限候選每維每月 0.02、12 月 0.10（**待校準**）。此數值為遊戲設計，不稱心理測量常模。 |
| A6 同月公平 | 人物插入順序反轉、ID／姓名交換；測試 fixture 注入按「邏輯身份」鍵控的相同抽樣值，以免換 ID 同時換隨機數；造 2 人競逐同一稀缺機會、多人社交和研究發現 fixture，測同月與下月知情差異。 | 共同快照下兩人候選意圖不受遍歷順序影響；同月發現不得先惠及後遍歷者，未觀察者跨月也不得自動獲知；無系統性 ID 勝率，30+ 配對競爭 seed 各方勝率候選落在 35–65%（**待校準**），隨機決勝可重播。若資源有能力優先規則，應另控制能力並解釋。 |
| A7 100 NPC／60 月 | 30 seed 無玩家干預，逐月 `validate_world`；重啟／分段運行、事件與快照核對；與 M1 相同硬體及資料配置量測。 | 無崩潰、負值、懸空事件引用、記憶越界或時間倒退；完整 state hash 同版重播一致；候選每 seed 60 月 ≤30 秒且 ≤M1 3 倍、SQLite ≤M1 3 倍（均**待校準**，M1 單 seed 已約 79.75 MiB）。若慢或成長過快，先量測主要瓶頸，不犧牲一致性。 |
| A8 Dashboard | 以真實 M2 世界用瀏覽器建人、推進 12 月，切換現況／歷史月並檢查目標、步驟、進度、關鍵記憶、定向關係、決策分數與原因；測無記憶／無關係與已故人物。 | 顯示值與該月保存快照一致；所有原因點選可到真實事件，無外洩 NPC 未知情報，無空欄編造；M1 原六頁及「推進一個月」可用。截圖和操作紀錄留存。 |
| A9 舊存檔／回放 | 使用從 M1 0、12、60 月真實建立的 SQLite 複本，含玩家自訂目標人物與死亡案例；遷移方案測兩次、故障中斷、未知版本，檢查原檔位元 hash、舊歷史與新推進。 | 遷移方案：原檔不變；遷移冪等或重複拒絕有明確訊息；自訂目標原文保留、採中性短步驟且提示可重選；舊歷史可讀，續玩從正確月開始，無捏造的舊記憶；未知／損壞版安全拒絕，同 M2 初始狀態+seed+版本重播 hash 相等。若選唯讀替代：M2 可看 M1 現況及歷史、不可在 M2 續玩且清楚提示，原檔可在 M1 legacy 模式繼續；不把不存在的遷移工具寫成已提供。 |
| A10 M1 回歸與代價 | 跑既有 `python3 -m unittest discover -s tests -v`，另 HTTP／瀏覽器 12 月流程；M1 legacy 存檔在原版模式重播 12 月。 | 原五測及流程通過；M1 legacy 同版本 hash 不變；既有建人／點數／三人上限／重複推進／原子保存無退化。M2 禁止付費呼叫，測試網路斷開仍可完整跑。 |

## 判定流程

先封存基線、fixture、seed 與門檻，再做單元／整合測試，接著跑多 seed 實驗及消融，最後在未調參確認樣本與實際 Dashboard 做驗收。硬性一致性／資料安全任一失敗直接不通過；行為指標若只在開發樣本達標或仰賴故事性事件亦不通過。報告須列每組樣本數、均值／中位數／區間、失敗 seed、混淆控制、未校準門檻及人工作業成本。P1 LLM 影子評估不阻礙 P0 驗收。
