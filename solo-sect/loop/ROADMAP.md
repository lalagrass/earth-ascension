# Loop Engineering 路線圖（solo-sect，codex/solo-sect-grok）

> 起於 2026-10-30，基底 `b7647bf`（v2.1）。每輪：定一個 milestone（範圍／驗收／不做）→ 小步實作＋測試 → 驗收（最多修 2 次）→ LOG.md 迷你回顧。每 2 輪一次 retro。

## 4. Retro #1（loop 1–2，2026-10-30）

- **方向：** 對。願景裡最缺的是「侵擾↔防禦↔修補」循環，M2 已補上最小版本；Sims 需求、建造、武學本來就有，不需要重做。
- **路線調整：** M3 明確改成「山賊上地圖撞柵」，不新造一套戰鬥；M4 併入「修柵經濟」（loop2 長跑發現修柵會把木頭吃光）。M5 以後不變。
- **流程調整：**
  1. 全套測試一律用 `node --test test/*.test.mjs`（node 20 直接給目錄會失敗）。
  2. 每個新系統都要「預設不啟用時零影響」，用既有 golden 測試當護欄：golden 沒重產＝沒動到既有玩法。
  3. 驗收除了單元測試，再加一段 3 種子 × 5 日的小長跑，看副作用（這次就是靠它發現木頭歸零）。

## 5. Retro #2（loop 3–4，2026-10-30）

- **方向：** 塔防循環（野豬／山賊 → 撞柵 → 守柵／修柵 → 升石牆）的骨架已成形，而且全部是「玩家築柵後才啟用」，既有玩法零影響。夠用了，下一輪轉回願景的另一半：人格與社交。
- **證據：** 3 種子×5 日、9 人：沒柵拱菜 3–4 畦、山賊上門 3/3 付錢；木柵拱菜 1–3、石牆 0–3、山賊 6/6 打退、0 重傷。
- **新問題：** 料停在底線（木 4–5、石 4–5），弟子不會因為柵壞而去砍柴採石，石牆最後常常是 0。屬「需求→採集」訊號缺口，排入 M9。
- **路線調整：** M5（16 型接創角／招募）、M6（外向／強者吸引）接著做；M9 合併防禦經濟收尾與「築柵走工地流程」（loop4 刻意延後，避免一輪做兩件大事）。
- **流程調整：**
  1. 調參一律用小長跑「有／無功能」並排比較（loop4 靠它看出連撞 3 下＝等於沒柵）。
  2. 日誌類驗收要先分清「新功能的日誌」和「原有日誌」，不要把原有日誌算進去（loop4 第一次測試寫錯）。
  3. 下一次完整 retro 在 loop 6 之後。

## Retro #3（loops 5–6，2026-10-30）
- **成果：** 16 型從資料變成可玩（創角選用＋弟子卡顯示「參考」）；M6「人以群分」以開關（開局勾選，預設勾）接上聊天評分與選伴，強者引發「仰慕」。
- **好的：** opt-in 慣例繼續守住 golden（6 輪零重產）；每輪都有對照長跑。
- **教訓：** 3 種子×5 天對「好感度」這種慢變量雜訊太大（loop6 三種子顯示開關後好感 −3，十種子反而 +6／+0.4）。之後社交類驗收改看 10 種子，或看直接計數（聊天 tick、仰慕次數）。
- **欠帳：** M6 原訂「請教→小量武學經驗」未做（會動到成長數值，併入 M8 同修一起設計）；8 題 MBTI 問卷 UI 未做；M9 仍背著材料需求訊號與築柵走工地流程。
- **路線：** M7 領悟 → M8 同修＋請教經驗 → M9 遠征與防禦經濟收尾 → M10 平衡長跑與總結，不變。

## Retro #4（loops 7–8，2026-10-30）
- **成果：** 天下霸圖味的「自悟／觀摩偷師」（M7）＋「同修／請教／練功搭子」（M8）上線，兩者皆開局選用（預設勾），8 輪 golden 零重產。
- **好的：** 「新路徑另加一小筆、不改既有倍率」讓成長類功能也能守住 golden；10 種子社交指標穩定（M8 好感 43.5→43.7，無副作用）。
- **教訓：** 5 天太短看不到切磋觀摩（M7 偷師 0 次）；M10 長跑需拉到 15–20 天並計數各路徑。開局頁勾選框已 3 個，M10 前要收成「江湖規則」一區。
- **欠帳：** M7 變式領悟未接；M9 材料需求訊號＋築柵走工地；8 題 MBTI 問卷 UI。
- **路線：** M9 遠征與防禦經濟收尾 → M10 平衡長跑（15–20 天、開關全開 vs 全關）與總結。

## Retro #5（loops 11–12，2026-10-30）
- **成果：** 柵牆走工地搬運（藍圖→搬料→施工）；江湖規則下山賊門檻 4，第 8 日起上門。golden 仍零重產（12 輪）。
- **問題：** 有柵時「地圖山賊」勝率遠低於無柵的一次勝率公式（14/55 vs 37/59），柵常被野豬削弱且守柵者趕不到；兩次調整無效已還原 → 待使用者選方向（見下）。長跑天數標示錯（tick→日換算），已更正。
- **選項（待決）：** A) 山賊撞破柵時改走原本勝率公式而非直接判敗（柵＝加分不是負擔）；B) 山賊對柵傷害降低／柵耐久提高；C) 守柵者用「哨塔」就近駐守（新建築）。建議 A（最小、不違反長通勤）。
