# 山門紀（solo-sect）設計：從破道館到同圖武學的門派

> 單一作者（Grok Bot）在 `codex/solo-sect-grok` 的獨立實驗。不改 dev 既有檔案、不取代 `experiments/water-carry/demo`、未經 PO 審核；所有內容都是候選設計，不是已批准決定。
> 思路沿用 #314 總覽與 #315–#321（A1–A7）提案，並參考 #182/#184 美術、#309/#330 已交付的 HOME01/02 數值手感。

## 願景（擁有人 2026-10-25 原話整理）
天下霸圖的生活層（弟子在地圖上奔走、練功變強、學新武學）＋模擬市民的生活感（技能、聊天、親密到成家）＋同圖塔防式後山狩獵（不切換戰鬥畫面）；門派從一間破道館一處處擴建。

## 架構（五層，皆為純資料＋純函式，可在 Node 測）
| 層 | 檔案 | 內容 |
|---|---|---|
| 資料 | `src/data.mjs` | 路網節點/邊、設施與階段、活動、武學、怪物、波次、角色、關係階段。改平衡只動這裡 |
| 模擬 | `src/sim.mjs` | 單一權威 `tick(state, dt)`；狀態是可 JSON 化的單一物件 |

| UI | `index.html`/`style.css` | HTML 面板：資源、建造、狩獵、弟子卡、人際、紀事、存讀檔 |
| 測試 | `test/sim.test.mjs` | `node --test`，只驗核心反例 |

無依賴：瀏覽器原生 ES module；截圖腳本用 box 既有 playwright-core，非遊戲依賴。

### 1. 設施／階段（smart object, A1/A7）
每個設施 = `{id, node, stages[]}`，每階段宣告 `offers`（提供的活動）、`restRate`、`cost`、`work`。弟子不知道「宿舍」是什麼，只問「誰提供 rest、效率多少」。擴建＝推進 stage，新活動自動可用。
建造是真搬運：`startBuild` 開工地 → 原子預約院倉木料 → 弟子扛到工地（在途）→ 料齊後到場施工累積工時 → 完工。取消時已扛的木頭歸還、預約釋放（有測試）。

### 2. 弟子決策（效用 AI, A3）
優先序：**玩家指派 ＞ 必要自理（精力<15/飢餓<10）＞ 效用評分**。
每個候選活動依需求（精力/飽足/交流）、門派狀態（存糧、木料、工地缺料）、個性（勤奮/社交/貪玩）、可學新招評分，加小量個性雜訊，取最高且可行者；`reason` 欄把理由顯示給玩家。需求：精力（活動消耗、歇息回復，破道館地鋪 3/s、小寢舍 8/s）、飽足（隨時間降，用飯 +60 耗 1 糧）、交流（隨時間降，聊天回復）。

### 3. 技能與武學（A4）
技能表：掌法、腳力、力氣、農、藥。做事長對應技能，邊際遞減（`1 - v/130`）。**腳力 = 速度**：負重長路交付時依實走距離成長，保留「長通勤、看得出速度差」的手感；負重 ×0.7、疲憊 ×0.8。
武學資料化：`{range, cd, dmg, aoe, req}`。掌法達門檻→「可學」→弟子自主回大廳向師父求學→學會。基礎拳(0)→推山掌(25)→迴風掌(60, 範圍)。射程/傷害隨掌法放大。

### 4. 人際（A5）
關係圖 `rel[a|b]` 0–100，聊天累積；階段 陌生/相識/好友/知己/道侶，跨階段寫紀事。**只有兩位成年人可到道侶**並登記為一個家（`families`）；堂弟是未成年，上限 89。

### 5. 同圖狩獵（A6，塔防式）
同一張地圖的後山：狩獵隊上山到守點，到齊後波次（山鼠×3＋野豬）沿山路往院子推進。弟子在守點自動挑最強可用招、打射程內最殘的目標，畫面直接演出招名與軌跡；怪物咬人扣 HP，HP≤25 退回院中歇息；溜過守點算逃走。結束出戰報，野豬給糧，出手給掌法經驗——「練了有用」與「打了也會變強」形成循環。

### 6. 存檔
`save(state)` = JSON（含 `v: 1`），localStorage；`load` 對壞檔/版本不符回 `{ok:false}`，失敗不動當局。新核心自有格式，不讀不寫舊 life-save。
