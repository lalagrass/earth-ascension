## 第一部分：M1→M2「組織進展」事件唯讀核對與回放影響量化

### 1.1 程式碼逐行核對（`engine.py` vs `m2.py`）

對照 M1 [`earth_ascension/engine.py:196-203`](../earth_ascension/engine.py) 與 M2 [`earth_ascension/m2.py:540-545`](../earth_ascension/m2.py)：

| 欄位／邏輯 | M1（`engine.py:196-203`，`0.1.0`） | M2（`m2.py:540-545`，`0.2.0`–`0.2.2`） | 可驗證核對結論 |
|---|---|---|---|
| 活躍成員篩選 | `researchers = [world["people"][str(i)] for i in org["members"] if world["people"][str(i)]["alive"]]` | 完全相同 | 一致 |
| 單月研究進展計算 | `progress = sum(p["skills"]["研究"] for p in researchers) // 30` | 完全相同 | 一致 |
| 組織狀態更新 | 更新 `org["research"]`、`org["resources"]`、`org["activity"]` | 完全相同 | 一致 |
| `progress >= 3` 事件 | `if progress >= 3: _event(world, "組織", None, f"{org['name']} 研究進展 {progress}", [f"活躍會員 {len(researchers)}", "會員研究技能累計"])` | **未呼叫 `_event`（無 `"組織"` 事件）** | **M2 未保留 M1 的組織事件** |

- **可驗證事實說明**：M2 保留了 `org["research"] += progress`、`org["resources"]` 與 `org["activity"] = f"會員累計研究進展 +{progress}，維持服務"` 的狀態更新，但未保留 M1 的 `if progress >= 3: _event(...)` 事件紀錄（目前無證據判定當初是意外遺漏或有意取捨）。因此 M2 世界中五個組織每月照常更新 `org["research"]`，但不在 `world["events"]` 產生 `"組織"` 事件。

### 1.3 第一部分結論與待決策選項〔提案〕

1. **不可回填修改 `0.2.0` / `0.2.1` / `0.2.2` 既有規則分支**：因為 `m2:{month}:{len(world["events"])}` 使用全域陣列長度編碼，加入 `"組織"` 事件會使所有 seed 從第 7–12 月起改變 **86.22%** 的 `event_id` 與 `canonical_hash`，破壞 `test_golden.py` 與既有存檔的因果 ID 對照。
2. **未來新 `rules_version` 是否記錄組織事件及觸發形式〔待後續決策〕**：
   - 若沿用 M1 `progress >= 3` 每月記錄，60 月會產生 ~200 筆重複度高的事件；
   - 候選替代方案為在未來新 `rules_version` 中改採「組織研究跨越里程碑門檻」時記錄，或維持現況僅顯示於組織分頁 `activity`。是否採納及門檻設定待維護者決策。

## 第二部分：玩家 60 月路徑的最小身分／組織歸屬候選規格（待決策）

### 2.1 現況問題與兩個設計邊界（為何不能憑最高技能授職、為何不能直接授予專業職稱）

1. **現況（`0.2.2`）**：[`store.py:83`](../earth_ascension/store.py) 創建玩家人物時固定寫入 `age=20, job="學生"`，且未加入任何 `world["organizations"][oid]["members"]`。推進 60 個月（25 歲）後，即使玩家人物已完成多次階段目標、技能達 30–45，畫面仍顯示 `25 歲 · 學生`，組織名冊也永遠沒有玩家人物。
2. **邊界一：為何不能「只看最高技能自動轉職／入會」（反例證明）**：
   - 以 `artifacts/run_m2_org_job_audit.py` 中的對照人物 **「張緩步」**（`unqualified_student`：初始目標「探索靈氣」，但 `悟性=3, 感知=3, 意志=8, 盡責=1.0`）為例：
   - 在 `seed 2026` 推進 60 個月後，張緩步因研究計畫停滯（觸發 `目標受挫`），計畫行動被改為「工作」（[`m2.py:371`](../earth_ascension/m2.py)），60 月累積 `工作=45, 研究=5, 社交=7`，但**整整 60 個月從未完成過任何一次「探索靈氣」階段目標（`goal_history = []`）**。
   - 若規則只看「某項技能 ≥ 門檻」就自動變更身分或入會，張緩步會在目標受挫、從未完成人生目標的情況下被憑空變更身分並塞入產業協會，違背玩家設定的「探索靈氣」生命敘事與因果可追溯性。
3. **邊界二：為何不能由通用技能直接授予 `工程師`／`醫護`／`教師`／`研究員` 等專業職稱**：
   - 在現有 `0.2.2` 規則中，`學習` 行動僅固定提升通用 `skills["工作"] += 1`（[`m2.py:449`](../earth_ascension/m2.py)），並無醫學、工程、教育等專業學歷／執照進修機制，亦無組織正式考核或任命事件。
   - 因此，若僅依「完成階段目標＋通用工作／社交／研究技能達標」觸發第一次身分轉變，**只能授予中性的候選組織成員身分（如 `研究成員（候選）`、`實務成員（候選）`、`社區成員（候選）`、`協力成員（候選）`）**；若要授予 `研究員`／`工程師`／`醫護`／`教師` 等專業職稱，**必須額外具備領域專業進修事件或組織正式任命事件**（屬後續里程碑待決策項目，不得在現有通用技能下直接授職）。

### 2.2 最小可追溯候選規格（待校準／待決策）

#### 層次 A：純 UI 語義澄清（零規則變更候選）
- 在未升級 `rules_version` 或人物尚未觸發任何身分轉變事件前，Dashboard 應將玩家創建時的 `"學生"` 明確標示為 **`學生（初始身分）`**（或在創角／觀察頁註明「初始身分：學生；尚無所屬組織」），不得暗示已就職或已具專業職稱。

#### 層次 B：未來新 `rules_version` 最小候選身分／入會規則（待校準／待決策）

1. **觸發時機與前置條件（四項必須同時滿足，參數皆待校準）**：
   - **檢查時點**：月末結算 `_progress()` 完成後，僅對 `person["alive"] == True`、仍處於初始身分 `person["job"] == "學生"` 且 `person["months_lived"] >= 12`（至少生活滿 1 年）的人物檢查一次。
   - **事件前置（Causal Milestone）**：`person["goal_history"]` 中必須存在至少一筆 `stop_reason == "target_reached"` 的已完成目標 `G`，且個人編年史 `person["chronicle"]` 中存在對應的 `kind == "目標完成"` 事件 `E_complete`（`E_complete["effects"]["goal_id"] == G["id"]`）。
   - **領域技能門檻與中性候選身分映射（待校準，基準值 `12`）**：

| 已完成目標 `G["type"]` | 領域技能條件（待校準） | 中性候選身分標籤（待決策） | 候選歸屬組織 `org_id`（`org["name"]`） | 必要因果事件來源 `causal_event_ids` | 若需授予專業職稱之額外條件（待後續設計） |
|---|---|---|---|---|---|
| `探索靈氣` | `skills["研究"] >= 12` | `研究成員（候選）` | `1`（`市立新現象研究所`） | `[E_complete["event_id"]]`（若已有 `practice_basis`，併列其 `source_event_id`） | 須另具本人獨立 `發現` 突破＋研究所正式聘任事件，始得授 `研究員` |
| `累積財富` | `skills["工作"] >= 12` | `實務成員（候選）` | `3`（`灣區產業協會`） | `[E_complete["event_id"]]` | 須另具工程／商務專業進修與機構任命事件，始得授 `工程師`／`商務` |
| `服務社群` | `skills["社交"] + skills["工作"] >= 12` | `社區成員（候選）` | 河港 `2`（`河港醫療聯盟`）／學園 `5`（`學園教育網`）／其餘 `4`（`舊城互助會`） | `[E_complete["event_id"]]` | 須另具醫護／教育專業訓練與機構任命事件，始得授 `醫護`／`教師` |
| `建立關係` | `skills["社交"] >= 12` | `協力成員（候選）` | 學園 `5`（`學園教育網`）／其餘 `4`（`舊城互助會`） | `[E_complete["event_id"]]` | 須另具組織行政歷練與正式任命事件，始得授 `行政` |

2. **事件紀錄與因果鏈（Event Source）**：
   - 達標當月由引擎產生一筆 `important=True` 的可追溯事件：
     - `kind`: `"入會"`（或 `"身分轉變"`，待決策）
     - `actor` / `subject`: `person["id"]`
     - `text`: `f"{person['name']} 完成階段目標，成為{org['name']}{candidate_role}"`
     - `causes`: `[E_complete["event_id"], ...]`（使 `causal_event_ids` 精確指向觸發該次轉變的 `"目標完成"` 與 `"發現"` 事件 ID）
     - `effects`: `{"role_before": "學生", "role_after": candidate_role, "org_id": org["id"], "goal_id": G["id"]}`
3. **名冊一致性不變量（Roster Consistency Invariants）**：
   - 轉變時將 `person["id"]` 加入 `world["organizations"][str(org_id)]["members"]`（若尚未在列），並維持 `members` 依 `pid` 升冪唯一（`len(members) == len(set(members))`）。
   - `validate(world)` 驗證：任何被事件寫入 `effects["org_id"] = k` 的人物，`person["id"]` 必須存在於 `world["organizations"][str(k)]["members"]`，且同一人物至多屬於一個組織。
4. **Dashboard 呈現方式**：
   - **人物觀察（`observer`）**：未達標前明確顯示 `20 歲 · 學生（初始身分） · 尚無所屬組織`；達標後顯示中性身分與所屬組織（如 `22 歲 · 研究成員（候選） · 市立新現象研究所 · 學園 · 在世`）。
   - **組織分頁（`organizations`）**：成員名單中對 `p.player === true` 的成員加上 `✦ 玩家` 標記。
   - **生命歷程（`chronicle`）**：轉變事件具備 `causal_event_ids`，可點擊跳轉至觸發的 `"目標完成"` 歷史月快照。
