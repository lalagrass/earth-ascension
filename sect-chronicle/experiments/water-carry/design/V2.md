# SG-EXP-01 V2：架構盤點與 PixiJS／Godot 同場景比較

實際主筆：Claude。Base：`dev` `102e424`。工作單 [#155](https://github.com/lalagrass/earth-ascension/issues/155)，工作包見 [EXPERIMENT_WATER_CARRY.md](../../../docs/EXPERIMENT_WATER_CARRY.md)。本階段只交兩個極小試作與這份選型紀錄，不接正式世界、存檔或 viewer。

## 結論

**推薦 V3 走 PixiJS＋HTML/CSS。** 兩邊都做得到本輪要驗的事（同一組操作與遮擋時刻全部通過），差別在接線與發行成本：

1. **接正式程式的距離最短。** 正式 viewer 已把畫面切成 `viewer/scene.js`（Canvas 2D，`draw`／`hitTest`／`screenOf`／`pulse`／鏡頭），檔頭就寫明「日後若改用 PixiJS 等套件只需換掉這個檔案」。PixiJS 版可以只換這一層，世界、`View.describe`、controller、actions、storage 與 HTML 面板都原樣沿用。Godot 版要嘛用 JavaScriptBridge 把 JS 世界接進 wasm（每幀跨語言傳資料、兩套 UI），要嘛把規則改寫成 GDScript；後者工作包明文禁止。
2. **下載小一個數量級。** 程式本體 gzip 後 PixiJS 約 0.2 MB，Godot Web 匯出約 9.2 MB（wasm＋js＋html，不含共用素材的 pck）。素材兩邊相同（約 1.7 MB）。
3. **中文字與介面免費。** PixiJS 版的介面是 HTML/CSS，直接用系統中文字型、瀏覽器焦點與無障礙。Godot Web 不會退回系統字型，必須隨專案帶字型子集，改一次介面文字就要重產子集；子集外的字（例如 ❚ ▶）會變成方塊。

**次選 Godot 的代價與優點**：它的場景編輯器、AnimationPlayer、TileMapLayer、Control 主題在「美術要大量擺場景、調動作」時比手寫 JS 省力，原生發行（桌面／手機）也是現成的。若之後真的要做大地圖編輯或原生版，值得另提案重估；本實驗的規模用不到這些。

**保留現況（原生 Canvas 2D）的代價**：零依賴、已在正式 viewer 上線，但 sprite 動畫、批次繪製、紋理圖集、濾鏡（選取發光）都要自己寫；V1 的人物多幀與遮擋在 Canvas 也做得到，只是每一項都是手工。

## 正式程式盤點（dev `102e424`）

| 層 | 檔案（行數） | 責任 | 與換 renderer 的關係 |
|---|---|---|---|
| 世界 | `js/realtime.js`（2455） | `createWorld`／`advanceTicks`／`dispatch`、序列化、hash；唯一會改世界與讀 RNG 的地方 | 不動。挑水的腳力成長若要正式化，屬新規則，另提案 |
| 存讀 | `js/storage.js`（432） | 雙槽 localStorage＋SHA-256 檢查、Web Locks | 不動 |
| 控制器 | `viewer/controller.js`（316） | 牆鐘→tick（1× 每秒 4 tick）、暫停／背景、保存點、`intent()`＋`dispatch` | 不動；新 renderer 照樣只呼叫 `frame()`／`dispatch()` |
| 畫面資料 | `viewer/view.js`（893） | `describe(world)` 把世界讀成純資料；`render()` 畫 DOM 面板 | `describe` 不動；HTML 面板沿用 |
| 操作文字 | `viewer/actions.js`（418） | 地點選單、不能做的原因、命令回饋，純函式 | 不動；本試作的 `scene.json` 選單就是同一形狀 |
| 場景 | `viewer/scene.js`（555） | Canvas 2D 斜視繪圖、命中、鏡頭、浮字補間 | **唯一要換的檔**：PixiJS 版保持同一組介面 |
| 接線 | `viewer/app.js`（977） | DOM 事件、rAF、可見性、localStorage | 只改建立 scene 的幾行 |

#154 定下的邊界（世界只經 controller 推進與下令、畫面狀態不進世界、背景自動暫停）兩個試作都照做：播放片段只用固定步進（1/60 秒），開選單、按暫停或分頁轉背景時不推進。

**未來接線責任圖（PixiJS 路線）**

```text
Realtime 世界 ──advanceTicks/dispatch── controller ──frame()── app.js（rAF、DOM 事件）
                                                         │
                         View.describe(world) ──純資料──┼─→ HTML 面板／名冊／選單（沿用 view.js、actions.js）
                                                         └─→ scene-pixi.js（取代 scene.js：sprite、遮擋、命中、鏡頭）
```

缺口（V3 或之後才補）：正式世界還沒有「挑水分段、腳力等級」這種逐趟資料，V3 依工作包用展示模型；人物多幀素材目前只有主角一套。

## 試作做了什麼

兩邊吃同一份 [`spikes/shared/`](../spikes/shared/) 輸出，不各畫各的：

- `export.js` 用 V1 來源 [`v1-board.html`](source/v1-board.html) 的同一組繪圖函式，以 2 倍解析度輸出 38 張透明 PNG：背景、4 松 4 叢 2 石、師父與師兄、三種水位的水缸、主角 11 幀（空桶走 4、負重走 4、待機、取水、倒水，各有選取發光版），全部記腳底錨點，再寫 `scene.json`（座標、路線、地點、鏡頭範圍 0.6～1.6、播放片段、選單與介面文字）。
- `playback.mjs` 是共用播放規則：空桶下山（4 幀×110 ms）、取水 4 秒、負重上山（4 幀×130 ms，走得較慢）、倒水 4 秒、水缸變滿，循環；「本趟後休息」在倒完水後停下。Godot 版 `playback.gd` 逐行照抄同一規則。數值是示意，不是正式模型。

| 驗的項目 | PixiJS 8.14.0 | Godot 4.5.1（Web 匯出） |
|---|---|---|
| 人物動畫 | `Sprite` 換貼圖，1 秒內看到 4 幀 | `Sprite2D` 換貼圖，同 |
| 前後遮擋 | `sortableChildren`＋`zIndex = 腳底 y` | `y_sort_enabled` 節點 |
| 平移縮放 | 容器位移／縮放，滑鼠拖曳、滾輪、+/-/0 鍵 | `Camera2D`，同一組輸入 |
| 選人／點設施 | 同一套命中規則（人物身體框、地點橢圓），點水缸開選單並暫停 | 同一套規則逐行照抄，同 |
| 面板與選單 | HTML/CSS，鍵盤焦點用瀏覽器原生 | `Control` 節點，焦點樣式自己設 |
| 背景分頁 | `visibilitychange` 暫停 | `JavaScriptBridge` 監聽同一事件 |
| 自己的程式 | `main.mjs` 263 行＋CSS 37＋HTML 30 | `main.gd` 564＋`playback.gd` 85＋場景 27 |

`compare.js` 在同一個 Chromium 打開兩邊，用真的滑鼠與鍵盤做同一組操作：看動畫幀、點主角、點水缸（選單開著時 tick 不動）、Esc 關閉恢復、Enter 下「本趟後休息」、拖曳平移、滾輪放大、縮到下限、0 重設、console 乾淨；再用 `?at=<tick>` 把兩邊跳到同一遮擋時刻，比對主角位置與共用規則相差不到 1e-6。**最後一次結果：兩邊共 26 項全部 ok，結束碼 0**（完整輸出 [v2/compare.log](v2/compare.log)，數字 [v2/results.json](v2/results.json)）。

## 實測（少量，只當相對參考）

環境：Linux 容器、Node v22.22.0、Chromium 141.0.7390.37 headless、WebGL 走 SwiftShader 軟體算圖、本機 `python3 -m http.server`（未壓縮）。

| 項目 | PixiJS | Godot Web |
|---|---|---|
| 開頁到第一幀 | 約 0.5 秒 | 約 1.8 秒 |
| rAF 間隔中位數／p95 | 66.7／117 ms | 50／83 ms |
| 程式下載（原始／gzip -9） | 716 KB／202 KB | 37456 KB／9194 KB（其中 wasm 37143 KB／9113 KB） |
| 共用素材（原始／gzip -9） | 1700 KB／1675 KB | pck 1567 KB／1536 KB（同一批 PNG 匯入後＋場景與字型） |
| 執行時要另外帶的東西 | 無（系統中文字型） | 中文字型子集 44.8 KB（339 字） |

rAF 數字在軟體算圖下兩邊都慢，Godot 稍快；這不足以代表真實 GPU，不據此決定。點擊到畫面反應沒有列：Godot 版每 3 幀才把狀態寫給頁面，量出來的是寫出間隔而不是反應時間。

## 重跑方式

在 `sect-chronicle/experiments/water-carry/` 下：

```sh
# 1. 共用素材（已入庫，改了 V1 繪圖或場景才需要；要 Playwright＋Chromium）
NODE_PATH=$(npm root -g) node spikes/shared/export.js

# 2. PixiJS
(cd spikes/pixi && npm ci)
python3 -m http.server 8770      # 另開一個終端機；8770 被占用就換埠並設 BASE_URL
#   打開 http://127.0.0.1:8770/spikes/pixi/

# 3. Godot（需 Godot 4.5.1 與 Web 匯出範本）
cd spikes/godot
GODOT=/path/to/godot sh tools/sync-assets.sh             # 複製共用素材進 res:// 並匯入
node tools/font-subset.js                               # 介面文字有改才需要
/path/to/godot --headless --path . --export-release "Web" build/web/index.html
cd ../..
#   打開 http://127.0.0.1:8770/spikes/godot/build/web/

# 4. 比較（兩邊都準備好後）
NODE_PATH=$(npm root -g) node spikes/shared/compare.js /tmp/v2-compare   # 任一項失敗結束碼 1
```

## 實際踩到的成本

- **PixiJS**：幾乎都在一般網頁範圍內。要自己做的是命中判定、鏡頭與 HTML 標籤跟隨世界座標；HTML 面板直接沿用 V1 的樣式。
- **Godot**：
  - `res://` 看不到專案外的檔案，共用素材要先複製進去再匯入（`sync-assets.sh`）。
  - Web 版沒有系統字型，中文要帶子集；子集外的符號變方塊，只好拿掉 ❚ ▶。
  - `Vector2` 是單精度，位置和共用規則差約 5e-6；改用雙精度 `sqrt` 計算才一致。日後若和 JS 世界逐幀對帳，這種差異要先想好。
  - `Control` 版面要逐項設錨點與 grow 方向；預設主題的焦點／hover 字色是近白色，淺色面板上整行字會不見；`HBoxContainer` 不會換行，要改用 `HFlowContainer`。三項都已修好，但每項都是在截圖裡才發現。
  - 匯出要另下範本；正式發行還要處理 wasm 的 MIME、壓縮與（若要多執行緒）跨來源隔離標頭。本試作用 nothreads 範本避開了後者。

## 未驗與限制

- 沒有真實 GPU、手機、Safari、Firefox；沒有量 Godot 原生執行（工作包允許，但本輪的比較對象是瀏覽器）。
- 背景分頁只驗了 `visibilitychange` 會暫停的程式路徑，沒有在真實瀏覽器切分頁長時間觀察。
- 只有一個可動人物、一條路線；多人同場、紋理圖集與大地圖都沒試。
- 兩邊都沒有接正式世界；接線成本是依上面的盤點估計，不是做出來量的。
- 擁有人對 V1 的三個問題（不讀說明能否看懂工作與介入、宗門生活感、同倍率下能否看出成長步態）尚未回覆；V3 開工時會再看一次 #155。
