## 1. 設計目標與問題診斷

### 現狀痛點
1. **頂部 HUD 與卡片堆疊**：原有頂部 HUD 塞入 10 餘個標籤與按鈕，野豬卡（`#boar`）無論是否有危機均固定展開並橫跨頂部（在 390px 手機上高達 126px），嚴重壓縮垂直觀察空間。
2. **人物因果與下一步未在小卡突出**：原面板雖已有 `next` 與 `why` 欄位，但夾雜於進階開關與掌法設定中；LP-14 將工作、精力、下一步與狀態原因整合至小卡頂部專區（`job-card`），使「為何停在座位上」與「下一刻會做什麼」一眼可見。
3. **鏡頭控制依賴鍵盤**：拖曳進入自由觀察後，原介面依賴鍵盤 `'0'` 鍵恢復跟隨，在手機或觸控裝置上缺乏直觀恢復入口。
4. **進階自主政策干擾日常觀看**：自主整理、自主清鼠、自主護院及掌法 fixture 等設定直接鋪平在面板上，造成日常觀察雜亂。

### O1–O4 解決方案
- **O1 觀察優先**：HUD 精簡聚焦於時鐘、倍率、存量與角色快捷；野豬／鼠群／護欄收納為**可展開的「院落近況」摘要卡片**，平時僅佔一行精簡摘要（~28px），點擊展開完整明細與派遣。鼠群摘要精準對應 `clean.phase`（等待出發、清理中、返院中），不冒稱在清理。
- **O2 人物小卡**：選人時小卡優先呈現「工作、精力、**下一步與停止原因**、腳力與成長」，常用切工／本趟後停工一鍵可達。
- **O3 進階按需**：自主政策與掌法 fixture 收納於「進階設定」折疊區；新增清楚可見的「跟隨 / 自由視野（點擊恢復跟隨）」按鈕。
- **O4 單純 UI 切片**：100% 保留原模型、路線、命令語義與時鐘，UI 折疊操作零模型副作用。

## 4. UI 操作純粹性與 390 視區幾何保證

1. **零世界副作用**：
   - 點擊「展開/收起院落近況」僅切換 DOM class（如 `.boarcard.collapsed`），不呼叫 `model.dispatch()`，不推進世界 tick。
   - 點擊「展開/收起進階設定」僅切換 DOM class（如 `.adv-section` 展開），不改變任何政策數值或觸發 `change` 事件。
   - 暫停狀態下進行上述 UI 展開/收起操作，世界狀態快照前後 100% 相同。
2. **390 手機視區優化與相機避讓幾何**：
   - **HUD 精簡**：手機寬度下隱藏副標與冗餘文字，將 HUD 壓縮至 2 行（~50px）。
   - **橫幅重排**：暫停橫幅 `.banner` 緊貼 HUD 下方（`top: calc(var(--hud-h) + 6px)`），不再置於野豬卡下方佔據中央空間。
   - **野豬卡高度上限**：展開時上限為 `min(30vh, 180px)`，內部超長時滾動；折疊時僅 28px。
   - **底抽高度上限**：人物抽屜上限為 `min(36vh, 260px)`，內部超長時滾動。
   - **中央淨視野區**：在 390×844 視口下，暫停且兩區同時展開時，上方障礙 ≤ 256px、下方障礙 ≥ 540px，**中央保留至少 284px 淨可視區**。
   - **相機跟隨**：`follow()` 以人物中心（`p.y - 30`）對齊淨區垂直中心（`targetY = (top + bottom) / 2`）。人物全身高（含頭頂動作標籤與腳下名牌）在 0.85 縮放下約 90px，在 284px 淨區中上方與下方均有超過 80px 餘裕，徹底消除遮擋。
