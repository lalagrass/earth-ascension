## V1：畫面與素材必須具體

- **觀察畫面**：道館、山路、泉水與水缸有一致比例／光影／材質；人物位置、工作與路線可辨識。頂部時間／資源、底部人物列、按需展開的詳情與名冊，不讓全量 debug 資料搶主畫面。
- **介入畫面**：選中主角的輪廓／名牌、點泉水或水缸的操作、暫停狀態、目前工作／待執行指令／成長回饋清楚。操作選單含可做／不可做及理由，完整畫出「選人→點設施→看動作→下令→看狀態」的順序。
- **人物與動作**：至少設計待機、空桶走路、取水、負重返回、倒水、成長後輕快步態；列實際路線需要的朝向與遮擋。步頻、身體傾斜、腳落地、挑擔與桶擺動、空滿水配合，不只有同一張角色圖滑動。
- **素材計畫**：列可復用的角色／地表／道館／植被／UI 圖示，以及需原創補繪的道袍、水桶、姿態和動作。設計稿可用原創繪製或授權素材組合，記來源；概念圖需再成為可用素材／動畫，不能把一張概念插畫稱作完成 sprite sheet。最低可讀尺寸、主色、字級與動畫狀態先說清楚，不一次建立全套美術規範。
- 只做本小場景需要的素材。PNG 等共用輸入盡量讓兩套技術試作沿用；可編輯來源一併保存。原創／第三方／示意標清，不沿用原作遊戲素材。

## V2：選型按製作與接線成本比較

先讀 [既有 UI 研究](UI_2_5D_PROPOSAL.md)、`docs/ui-research/`、正式 `viewer/`／`js/` 及 #139／#154；區分哪些已存在、哪些是 UI 差異、哪些會改產品規則。舊 Canvas 在小灰盒的效能證據可作基線，但不能推論貼圖／動畫／場景製作流程已定案。

| 候選 | 本輪比較重點 | 適配限制 |
|---|---|---|
| PixiJS＋HTML/CSS | 場景／sprite／動畫與命中測試，HTML/CSS 的經營面板；接現有 JS 資料與指令的 adapter | 編輯地圖／動作的工作量、素材打包、UI 焦點／事件及維護成本需實際列出，不能只因語言相同就判勝 |
| Godot 2D／2.5D | 場景編輯、TileMapLayer、動畫／相機、Control 面板的製作流程；同小場景輸出與執行 | 原型可用其工具與小模型；接既有 JS 核心、Web 匯出／原生發行是不同成本，不能偷偷把正式引擎重寫成 GDScript |

比較用同一小場景、素材、鏡頭範圍、人物數量、資料與互動任務，先不做兩套完整遊戲。可用共同 JSON fixture／播放片段比較呈現與輸入意圖，不要求建立跨語言世界服務。若 Godot 使用原生執行結果，與瀏覽器結果分欄，不直接比較不同平台的數字。Web 匯出若失敗，記環境／錯誤、給可驗的原生短展示並標 Web 未驗，不編造比較結果。

短紀錄包含推薦路線、保留現況／次選的代價；版本／commit、程式與素材 license、安裝與重跑方式、需要補的素材／製作步驟，以及少量對決策有用的實測（載入／輸入反應、素材體積、編輯或整合步驟／實際投入）。沒有量到就標未量／估計。不要設大型 benchmark／大量設備樣本，不因幾 KB 或單次 FPS 就決定整個製作流程。

依 [#145](https://github.com/lalagrass/earth-ascension/issues/145)先復用。可在原型專用環境取得 PixiJS、Godot 標準版與必要工具，記精確版本／取得來源；依賴／lockfile 留原型資料夾，不覆蓋全域環境／修改 root 依賴。Phaser 只在兩者有具體未滿足缺口時作書面次選，不新增第三套試作。Tiled 等編輯器依實際需求評估，不把工具清單變成安裝任務。

一手入口：[PixiJS](https://pixijs.com/8.x/guides/getting-started/intro)、Godot [TileMapLayer](https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html)／[AnimationPlayer](https://docs.godotengine.org/en/stable/classes/class_animationplayer.html)／[Web export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)、[Tiled](https://doc.mapeditor.org/en/stable/manual/introduction/)。本輪只保存已查閱的入口，具體採用時重核版本／授權／維護與可用性，沒有宣稱已安裝或完成試作。

## V3：可操作展示與極小模型

**UI 情境**：觀察自主挑水→平移／縮放→選主角→點泉水／水缸→查看工作與成長→暫停下令→恢復看接續→比較成長前後→重來。至少支援「開始／持續挑水」與「本趟完成後休息」，顯示何時生效；休息是停止此工作，不需要新增疲勞系統。指令不是假按鈕，暫停時可以改意圖但不推進路程／收益。新模型的語義在 README 寫清，不冒充正式 D9 全套人工覆寫。

**畫面驗收**：場景為主、HUD／人物列／名冊／詳情與操作回饋完整；人物動畫可辨、前後遮擋和選取一致；主要操作有鍵盤替代，窄視窗仍能完成短流程。選取／面板焦點保留，輸入不被每幀重建吃掉。示意背景人物若有，標明不是已實作的村民自治或多人指揮。

**模型只支撐這段 UI**：一人、固定路線、空桶下山→裝水→負重返回→倒水→整趟完成一次入帳／腳力成長，新速度下趟使用並有上限。水量與裝倒水時間固定，腳力只影響移動；速度有限且大於零，途中不跳位置。demo 常數集中、明標非正式平衡。記實際整趟及移動段耗時，不能把移速倍率當產量倍率。

**成長表現**：固定播放倍率下能看出更輕快，姿勢／步頻與實際移動一致。初始能力對照可用同條件淡色影子或短對照回放，明示無收益，不能再產水／成長；畫面分開個人速度與播放倍率。以一兩分鐘可看到變化為體驗目標，不凍結工期或正式遊戲時間尺度。

**時間與重來**：選定路線只有一個原型模擬時間，固定步進；render、補間、特效不入帳／抽 RNG。暫停凍結移動／工作／成長／對照，背景自動暫停、返回保持暫停且不補算；重來清除模型、意圖與舊 callback。沒有隨機就不用新 RNG／seed 系統。

架構保持「展示模型／唯讀資料→場景與動畫／HUD→使用者意圖→模型驗證」。V2 是兩個替代呈現試作，V3 只保留一條運行路線，不同時讓兩個引擎結算同一世界。選型附一張未來接正式 world／View／controller 的責任圖與缺口即可，不建通用跨引擎框架。

## 測試、輸出與效果評估

V1 只核對圖片可開、字體／素材／連結與來源、設計完整性，不跑遊戲測試或世界 seed 實驗。V2 只驗共同小場景與實際安裝／輸出，留一份比較；不做雙引擎完整玩法驗收。V3 才補受影響的局部反例：抵達／裝倒水先後與每趟單次入帳成長、同條件速度／上限、指令與暫停／背景／重來、不同 render 頻率同固定步進一致。

V3 用真實目標執行環境走一次完整操作與初期／成長後對照，確認鏡頭、遮擋、選取、面板／鍵盤、代表性窄視窗與 console／引擎錯誤。圖片或錄影是效果證據，不能替代可操作入口；示意、fixture、真實模型各標明。自動檢查若有，失敗需非零退出；不堆逐幀 snapshot、重複單測或大型跨裝置矩陣。保留必要 CI／根基本檢查，未變正式引擎／存讀／golden／長矩陣證據可復用，不逐段重跑；有新失敗或實際受影響再擴驗。

完整 stdout／stderr 放本機 log 或可存取 artifact，只回報 head/base、命令 exit、版本／執行環境、少量實際耗時／體積、截圖與失敗／未驗項。不以測試數量、美術稿交付或產量上升宣稱 UI 好玩。

擁有人回饋聚焦三件事：不讀長說明能否認出工作與介入方式；場景／人物／介面是否有想要的宗門生活感；在同播放倍率下是否看出成長與行走質感。完成工程交付與正式採用分開記。
