# 公版武學模板：定義、人物所學與演出分層

狀態：2026-10-26，擁有人提出「武學是否需要另一個公共模板」後整理的**評估提案**，主[#340](https://github.com/lalagrass/earth-ascension/issues/340)，PR #341。先定共用語義／資料投影，不建共用引擎、改招式或移植三版規則。研究接受不代表工程授權。擁有人追加的入門／理解、承載、控制、特殊前提及不足後果，見[條件分層補充](#8-入門承載控制與特殊前提條件不足如何表達)；本輪只補評估契約，不新增規則或數值。

本輪已確認以[十二人／十八條目](CLASSIC_TWELVE_TEMPLATE_COMPARISON.md)作紙上適配，先審模板再對照；新增的粒度／領域、合用組件與資源描述見[第9節](#9-十二人適配條目粒度合用與資源)。不是新增18種攻擊功法或改各版規則。

## 1. 建議要有，但不是一份萬用武學JSON控制全部遊戲

公版人物卡回答「誰」，公版武學模板回答「這是什麼武學、如何取得與練習」，人物所學記錄回答「這個人練到哪」，呈現模板回答「這次真施展怎麼畫」。

| 資料 | 擁有的內容 | 不放在這裡 |
|---|---|---|
| 武學目錄／定義 | 穩定身份、名稱、分類、學法、前置的語義與來源、招式列表、特色與限制 | 某一人的熟練、傷勢、已用精力 |
| 人物所學記錄 | actorId＋本版artId、已學／階段、原生理解／熟練／體悟、師承、已解鎖招式與真成長來源 | 複製整份武學設定、動畫影格或另一套總戰力 |
| 核心規則 | 真學習／門檻／突破、可用招式、命中／傷害／耗能／位移與時間 | 共用畫面自行結算 |
| 武學呈現模板 | action／move引用motion、效果外觀、人物相容族及缺圖回退 | 修改數值、以動畫播完決定命中或授予技能 |

共用元件可先展示資料，各版adapter轉接既有狀態；不要求三版先合核心。分類相同可以比較資訊，數字是否等價仍須同規則、同量尺證明。

## 2. 公版定義的最小欄位目錄

以下是研究欄位，不是已發佈或可執行schema；不是每門都必填全功能。缺項／未知／未實作分開，不填假0。

| 欄位組 | 想表達什麼 |
|---|---|
| identity／provenance | 本版命名空間＋artId、來源HEAD／規則版本、展示名、參考作品／本作變體、權威來源路徑；同名不自動同ID |
| category／tags | 拳、掌、腿、劍、棍、內功、步法等展示分類；原生school／技術分類另保留。剛／巧／柔是路數，不能當人格 |
| acquisition | 老師、秘籍、任務、觀察／事件等取得方式與可見程度；未知機緣不直接公開名字 |
| curriculum | 入門／理解、承載、控制、特殊前提分層，另記作用於理解／演練／完整運使／突破的哪一階段、軟硬性質、未滿足後果與改善／替代途徑；all／any與偏好助益不混。核心有判定就讀結果，不在UI另算 |
| growthModel | 原生進度項、單位／量尺、階段標籤、有效練習類型、能提升什麼；不把GPT U/F/I和Grok xp硬壓同一百分比 |
| moves／effects | 招式ID與已知核心效果／條件／限制；武學熟練不等於每招已解鎖，效果是否受身體／特性影響需有來源 |
| presentationRef | icon／敘事說明／motion或姿態家族的引用，與真武學規則分開；沒素材／沒phase如實標未支援 |

天賦支系可引用武學ID或路數；武學亦可引用原核心已存在的條件。**本輪先用條件摘要＋來源／核心判定結果**，不建立公版任意公式語言、全域effect engine或互相遞迴的天賦／武學大圖。原版有all／any條件就保留結構與語義，不能扁平化成全部必需；沒有機器判定就標未驗，不從中文提示猜公式。

## 3. 人物所學記錄另存，不寫回定義

| 項目 | 例子與限制 |
|---|---|
| actor／art binding | 哪一人學哪一版本；同名名俠或同名武學不合併記錄 |
| access／learning state | 不知此學問、已知但未取得教法、可求學、入門、正在練、突破受阻等由核心提供；不同狀態不能都叫locked |
| native progress | GPT理解U／熟練F／體悟I；Grok arts.xp／突破；Gemini原生階段／前置。缺項顯示不支援，不造公共熟練分 |
| learned moves／variants | 真已學招式／變式與來源；圖譜有招名不代表角色會用 |
| current execution | 本時點可理解／可練／可施展的範圍、強度、限制／拒絕原因，以及已有核心提供的效果與風險；未評估不冒充安全，不用卡片理想最大值冒充 |
| history／visibility | 有來源的學習／突破／傳授事件與已知程度；沒歷史不能反推，不為投影先改保存格式 |

人物卡只顯示：已學什麼、為何進展／受阻、可以怎樣繼續。武學詳情可共用顯示取得／入門／精通／施展四層；天賦面板從同一來源顯示助益，不能在兩處各加一份倍率。

## 4. 九劍／降龍為何不能只用同一套數值

| 層 | 九劍研究例 | 降龍研究例 |
|---|---|---|
| 取得 | 相應師承／教法、認識出手變化 | 相應傳授／掌法教法 |
| 入門／精通 | 劍術基礎、原理與可驗證的觀察／交手進展 | 掌法基礎、勁力控制、內息與有效演練 |
| 特性助益（待評） | 識隙／臨機可改學習方式或已會招的選擇 | 守一／厚積可助深修與穩定發揮 |
| 地圖可見差異（待評） | 距離、出手窗口與應變，遇快招／佯攻也可能失效 | 起手、勁力／衝擊、消耗與進退；不是永遠群攻最強 |

兩路不是互相排斥的「高悟性／低悟性」二選一；有些角色可以兼修，差異在如何學、練多深、遇到什麼與當時能施展什麼。不因想共用模板，就把所有武學改成根骨≥X、悟性≥Y、隱藏ID必須相同。

[完整經典武學清單與三版前置核讀](CHARACTER_TRAIT_PATHS_PROPOSAL.md#5-先列經典武學再看是否都是同一組條件)包括九劍、降龍、打狗、太極、內功、輕功、譚腿等19組。

| Gemini：art.dugu_nine_swords／art.xianglong_eighteen_palms | v07資料各有不同前置／minStats；另有v04／legends的相關名目 | 同名／別名與規則權威須作者核對；定義存在不代表運行路徑已驗收 |

同一參考武學可登錄成三個source entry，透過「參考家族」連到同一詳情群；不是先宣稱三者數值等價或合成一條真記錄。原始ID不得因公版改名就消失。

## 6. 動畫在呈現模板，規則仍在核心

武學定義可列招式與presentationRef；人物視覺設定決定哪個body／rig／spriteFamily相容，按已有action／phase／朝向演出。出掌、踢腿、持劍不因共用一張卡就共用所有圖格。

已有phase就讀真phase；Grok評估指出當前同tick結算、沒有windup／active／recover，公版不能假造三階段再當戰鬥權威。未提供phase先用簡化演出，是否補phase是另案工程。核心握有真命中、落空／取消（若有）、耗能與位移，UI不按動畫重扣或跑root motion改座標。

技能特效、人物外觀與素材仍依[公版原案](CHARACTER_CARD_PUBLIC_PROPOSAL.md#6-武學動畫放哪裡不同人物要不要各做一套)與[素材規劃](CHARACTER_SHARED_ASSETS_PLAN.md)；不要求每角色×每招重畫，亦不宣稱立繪能生成全套動作。

## 7. 可借鑑開源與下一步

[CDDA Martial arts and Techniques文件](https://docs.cataclysmdda.org/JSON/MARTIALART_JSON.html)將武學style、所含techniques、使用條件與效果分層。可借這種組織方式，不搬回合制、四維屬性、JSON執行引擎或現成倍率；資料可配並不代表適合直接安裝。

追加[金庸社群／公開源碼可重用研究](JINYONG_COMMUNITY_REUSE_RESEARCH.md)：優先評jy-skill靜態人物／武學資料與MUD分階段學習，jynew／kys-cpp實際授權另核。已核固定版本、可直借的分類與待評轉接，不導入外部公式／數值／素材／第三方skill，也不新增本輪評估必做工作。

本輪依十二人紙上表，每方沿用#340舊報告、最多三組合併案例；原碼核讀至多兩門現有武學，補來源、粒度／領域、合用／資源、取得／入門／精通／施展與缺項。不重貼原碼、不跑世界矩陣，沒有的角色／功法不新增。

先由擁有人選首批公共欄位與一條可見流程，再決定實作人物卡／武學卡及adapter。暫不新建package、通用條件引擎、三版共用存檔或全套武學。保存升版與手機末位、既有開發不停。

## 8. 入門、承載、控制與特殊前提：條件不足如何表達

**不是所有入門條件都應是死門檻，也不是所有不足都只扣威力。** 分開記「領會、演練、完整運使、精通／突破」；已得到教法或能模仿外形，不代表已練成配套功法、能安全全力施展。原版已存在的硬門檻仍如實記錄，本提案不擅自軟化或強化。

### 8.1 四類條件的效果、風險與改善途徑

下表是可容納的**候選機制目錄**，不是三版已實作或每門武學必有的效果。各門需要真來源才能填；風險未驗就標未知／未支援，不填0。

| 條件類型 | 條件不足時的效果候選 | 風險候選／邊界 | 改善或替代途徑候選 |
|---|---|---|---|
| 入門／理解 | 看過或記住招形但未懂原理；只能模仿、學習較慢、部分招式未解鎖，或在指定階段受阻 | 誤用可能造成錯招／失手；不自動等於受內傷，也不以高悟性跳過未取得的教法 | 教師解說、補基礎、拆招觀摩、慢速演練；真缺傳承就先取得，不用任意高數值抵銷 |
| 承載 | 理解／招形可能已會，但只能低強度或短時間運使；全力效果受限、消耗或恢復成本增加 | 超出目前身體／內息承載，在疲累或有傷時可能更危險；不從低根骨單獨推出每次必傷 | 鍛鍊已有身體能力、相關內功／調息、休息復原、減力／縮短練習或分段；是否真有效由本版規則證明 |
| 控制 | 力量足夠卻不穩、時機不準、精力浪費；可出招不等於能有效命中／收放 | 失手、失衡、反震或誤傷只是可選機制，不能從命中失敗反推必有內傷；對手避開也不等於自己控制差 | 正確慢練、低輸出、師長指導、練發勁／收勁與實際熟練；原版沒有控制值就用已有技能／判定，不先新增通用屬性 |
| 特殊前提 | 在指定環節不能正確運行完整功法；可能只知外形，相關內功／特殊招式仍不可用 | 原版可定為禁止、失敗，或強練有明確反噬；不能一概當「威力較弱」，也不能預設人人可無視限制強練 | 核對真正前提與版本；只有存在已核實的替代教法才列。也可停留在可安全分離的部分、轉修或放棄；**不保證總能靠訓練／藥物繞過** |

根骨可影響適應／潛力，但目前承載還可能由身體能力、已修內功、精力、傷勢、強度與控制共同決定；**本輪不訂這些因素的公式或強迫每版都有它們**。高悟性不自動增加承載，承載提高也不自動增加招式理解；後天改善不倒寫出生值。

「特殊前提」與一般可鍛鍊能力分開。辟邪／葵花只作配套功法具有特殊前提的敘事研究例；需核作品版本與本作採用規則，不把前提不足直接簡化成減傷，不由性別／情感身份推出合格與否。本輪不新增其修煉或代價機制。

### 8.2 每條條件的最小描述

不做可執行條件語言，先用下列欄位供三方評估，已有資料才填：

| 描述項 | 要分清什麼 |
|---|---|
| conditionId／類型／來源 | 條件對應哪門／哪招／哪版本，原核心權威路徑；同名不假設同義 |
| appliesTo／作用階段 | 取得教法、理解、低強度演練、完整運使、特定招式、突破；一階段失敗不自動否定其他階段 |
| policy／條件性質 | 硬前提、效率／效果軟限制、承載／安全界限、偏好助益或未驗；各類不可單從數值大小推定 |
| evaluation／目前判定 | 滿足／不足／未知／未實作，及核心允許的練習範圍；未知不視作通過，也不偽稱原核心已拒絕 |
| unmetEffect／risk | 確定的限制與可能的風險分開；風險是必然或機率、何種強度／疲勞等情境才適用、有何來源。無已驗機率只寫定性／待評，不造百分比 |
| remediation／alternative | 可改善的能力／教法、可用替代路徑、不可繞過或待核；可替代不等於公版擅自改all為any |
| knowledge／feedback | 本人／玩家合理知道的原因與可讀提示；核心掌握未知資料，UI不收到祕密值再隱藏 |
| attempt handling | 現有核心是拒絕、允許限強度、或允許帶風險嘗試；沒有該指令／強度模式就標缺項，不在評估中補程式 |

同時不足多項時保留全部適用原因，但效果／風險不由UI自行相乘。條件改善後，依核心新結果解除限制，不默認舊傷或控制問題也同時消失。只把開卡顯示變成「可學」不能取得武學、扣精力、授予特性或判定受傷。

### 8.3 三個紙上案例

1. **高理解、低承載的降龍研究例**：有教法且理解招理，可在本版若支援的低強度模式練動作；全力運使可能超限。提高相關身體／內息能力或降低強度，是候選改善路徑，不能直接把高悟性視為全階段通過。降龍不因此被定成必須低悟性，也不宣稱三版已有內傷結算。
2. **承載夠、控制不足**：出力可達，但已有技能未穩或時機錯誤。候選改善是正確慢練／收放與指導；不是繼續堆根骨。九劍被快招／佯攻破局也可能是對抗條件，不一概歸為角色控制不足或內傷。
3. **理解高但特殊前提仍缺**：可理解／記憶外形，不能據此宣稱完整功法可安全運行；如原版不允許就保留拒絕，如有風險嘗試則記真後果。不存在已核替代法就寫無／待核，不臆造任何人格、隱藏天賦或藥物作通用通行證。

自主練習的未來建議是依角色合理已知的疲累／不適與核心可用選項減力、休息或換練基礎；人格可影響取捨，但不給AI全知。玩家若有合法強練選項，先顯示已知限制與代價，再由核心受理；本輪不新增按鈕、越權指令或保證玩家可繞過硬前提。未知風險以「未明」表達，不假稱安全。

不採「所有條件不足都每次練必傷」的公版預設；單一功法若原規則明定必然反噬則另記，不能擅自改為隨機。反覆受傷也不自動算有效修煉／解鎖天賦，既有特殊劇情沿原授權；發現潛質與獲得新效果仍分開。

### 8.4 本輪評估與成本
