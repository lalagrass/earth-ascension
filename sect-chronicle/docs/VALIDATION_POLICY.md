# 遊戲局部驗證政策：必要、直接、可復用

依[D30](DECISIONS_AND_SOURCES.md#d30桌面生活優先平台末位與精簡驗證2026-10-23)，由擁有人要求精簡遊戲開發的冗餘驗證。適用生活版切片、畫稿與PO review；根[貢獻契約](../../CONTRIBUTING.md)／[測試政策](../../docs/testing-policy.md)的必要CI、Earth高風險與正式發布驗收保留。本文件不修改workflow、分支保護、根測試或既有驗收結論。

## 每類改動只驗直接風險

| 改動 | 本地最小證據 | 不逐包重做 |
|---|---|---|
| 純Markdown／排序／prompt | 改動段落的連結、批准／前置／白名單一致、diff空白；必要CI照跑 | 不另跑遊戲行為／瀏覽器／root53或世界seed；未變程式證據復用 |
| 靜態畫稿／分鏡 | 真正看過完整桌面圖、尺寸／來源／示意標註、與接受場景及要求相符 | 不為每張圖寫存在性測試，不要求手機稿、播放器或遊戲矩陣 |
| 設計專用互動頁 | 變更JS語法＋一段桌面點選流程；有播放器才核暫停／到期／重播 | 不將未連模型的熱區當世界驗收，不測不存在的遊戲行為 |
| 純UI／鏡頭／局部動畫 | 變更JS語法／diff；一段桌面真操作覆蓋所改控制、資料／拒絕理由、暫停與選人；只補會重現具體缺陷的必要回歸 | 模型／路線／RNG／存讀未變就復用原證據，不重跑全工作×人物×等級×政策、手機或世界seed |
| 模型／結算／RNG／存讀 | 受影響單測／原失敗反例、必要相容／回放證據；按原風險與既定樣本升級 | 不事後縮減原定正式樣本、不改閾值追綠；高風險不套純UI豁免 |

純UI的短流程通常可同時回答：玩家看到什麼→操作原指令→真結果／等待原因→暫停純UI無額外命令→返回觀察。只驗這次變更涉及的步驟；不用每輪把所有舊功能重演，也不硬造2～5分鐘等待或固定截圖數量。

## 刪除重複與自證要求

- 不新增只斷言初始常數、檔案／截圖存在、測試自建布林切換或複製實作公式的測試作為驗收。已有這類測試記為低價值候選，原作者有空可局部移除／合併；不另開大拆前置，也不以「測試數增加」衡量完成。
- 141／365等總數是執行資訊，不是每個UI包必須本地重跑的目標；Node模型測試不稱DOM／按鈕／鏡頭真驗收。反例無法以合理成本自動化時，一次可重現桌面流程與少量圖足夠，不強制新runner。
- 同一head／實際合併結果的CI已覆蓋未變SG／root時，可引用當前run與結果；作者、遊戲PO、Earth不各自再本地重跑相同套件。必要CI本身照原設定執行，SG dev快驗／root jobs不刪；只有差異／失敗／風險理由才擴本地驗證。
- 審查者仍讀受影響diff、真作者／範圍、實際head與合併結果；五check狀態一次核對，明確CI／tree風險才查詳細checkout log，不逐輪重複下載整份綠燈log。合併後CI成功與接受結果仍由queue確認，不要求每位PO重新取同份全log。
- 交付只留命令／exit／摘要、失敗重現、必要少量完整圖／URL與已知限制。未變證據附來源；不製造大型輸出、冗長「全綠」報告或為湊時間新增任務。

## 手機與平台適配延後

手機390／平板響應式、觸控專用、全裝置／瀏覽器組合與像素矩陣移至[FUTURE_BACKLOG末位BL-P01](FUTURE_BACKLOG.md#bl-p01平台適配與全面驗證末位)。當前不作開工、完成或合dev門檻；已有適配保留，不為了延後而刪程式。桌面普通視窗的可讀／可操作、錯誤資料與暫停等實質問題仍要修。手機數字若只是設計假設就標示意／未驗，不能繼續冒充實測保證。

## 單一正式試玩版本

擁有人於2026-10-23明確要求「不用保留試玩回退入口，留一個版本就好」。本節即日起覆蓋舊工作包／prompt中保留LP14／上一版的要求。

- 正式試玩只用同8800的當前接受版；不做第二入口、版本選單、常駐舊可執行目錄或部署備份tar。
- 工程非作者接受、Earth實際合dev及postCI成功後才由遊戲PO更新。必要staging可在更新中短暫存在，核對新接受版與HTTP來源後清掉前次自有部署副本與staging，不持續保存作回退入口。
- Git提交／原作者branch與worktree、來源檔、PR／CI紀錄與必要少量截圖／摘要照常保留；清理只針對PO自己建立且已辨識用途的部署副本，不能刪他人工作、使用者存檔或整批tmp檔。
- 真有缺陷沿正常修復／revert PR與唯一queue處理，不為每包維護另一套舊renderer／服務。臨時驗證仍最多一頁一服務、結束即清，不因單版本政策提前把未接受程式上正式入口。

## 統一執行步驟與資源上限

擁有人在2026-10-23因多個測試分頁使Mac變慢，要求「please normalize the testing method in documents」。本節是所有遊戲作者／PO共用的操作標準；工作包只列本次風險與例外，引用此文件，不再複製一整套指令／設備清單。

1. **先規劃再開工具**：確認實際head與改動類型，在交付列本次要驗的一個玩家流程／直接風險，以及哪些未變證據可引用。純文件不開瀏覽器，靜態稿用既有圖片檢視；需要互動／render才開一個桌面頁。
2. **一次一個本地工作**：一般最多一個測試分頁、一個臨時預覽服務、一套本地測試程序。重用同一分頁切URL／reload核新head，不為每個head、尺寸、對照圖另留活頁；不平行跑多個遊戲renderer、錄影或本地長矩陣。遠端必要CI照原設定，不因本地節流而刪job。
3. **只驗本次風險一次**：沿上表選語法／局部反例／一段桌面真操作，未變部分與當前CI引用。需要擴驗就先寫具體失敗／差異理由，不因「再保險」重做整套；不另造永久runner或新增依賴作小UI前置。
4. **觀察完立即暫停並保存**：遊戲／動畫測完先暫停；證據用少量靜態圖與短結果，畫面來源／尺寸／head與示意或真實分清。不要留著播放只為等review／CI，不以自動背景暫停假設分頁已停止渲染。
5. **結束一定清理**：成功、失敗、額度或時間到都關閉本輪自己建立的測試分頁、停止自己啟動的臨時服務／測試程序、還原臨時viewport覆寫。預設不markDeliverable／markHandoff保持遊戲頁常駐；只有使用者明確要留可看頁時保留一個且暫停。確認已關閉／停止，不能只發關閉命令就宣稱完成。
6. **清理有界限與失敗處理**：記錄自己服務的PID／port／目錄與分頁身份，只停止自有資源；不動使用者頁、其他作者服務、正式8800或整個Codex／Chrome。逾時／Mac變慢先停止新增測試；做一次最小狀態確認／清理，仍失敗就回報未清掉的資源與限制，不重複開新頁或重試整段測試。不要為取得清理截圖再開分頁。

清理完成以分頁列表／程序狀態即可驗，不另啟一次遊戲測試。瀏覽器工具session重設時先刷新已啟用表面的身份，再按已知URL／自有資源確認；不能拿過期browser/tab ID操作無關頁，也不因恢復而建立新測試頁。這是資源收尾，不擴成全機效能audit。

## 最小交付格式

```text
head／改動與直接風險：…
本次驗證：命令或一段桌面操作 → 結果／exit；失敗或限制：…
復用證據：原head／CI或既有驗收；未覆蓋範圍：…
清理：自建測試分頁0；自啟臨時服務／測試程序0；viewport已還原。
例外保留（只在明確需要時）：資源／原因／擁有人與停止方式。
```

交付寫清理摘要，不每分鐘打卡、不把相同證據貼多份、不硬規定截圖或測試數量。非作者讀必要差異與證據，Earth唯一queue核當前CI／合併結果，避免三方重複本地執行；發現具體新風險才擴驗。

## 集中review時如何復用

依[D31完整工作包流程](PARALLEL_HANDOFF.md#d31單一主筆完整工作包與集中審查)，作者在同一PR整理驗收／head／方法／結果與限制，審查者讀受影響diff並核對可信度。證據已回答的流程不逐人重演；缺口以最小反例或一段必要操作補足，不另造全套對照／runner。補修只重驗新差異及連帶風險，其他引用原結果。

遊戲PO集中判斷玩家流程與原驗收，Earth唯一queue復用該結論並核當前合併結果／必要CI及postCI；新差異、失敗或證據疑點仍可補查，不因復用免除非作者審核。一般美化建議不擴驗收，排backlog；必要CI與高風險完整要求照舊。

## 什麼時候擴驗

只因新差異、重現失敗、邊界／相容風險或實際支持平台決策擴驗，記一句原因。#215只做有限健康回訪，不逐包全架構audit；#113的跨產品CI優化另走根契約單一作者，不混進生活切片。新功能批准、非作者review、Earth唯一dev queue與main發布權限不變。
