# Agent 提案與溝通流程

狀態：專案擁有人於 2026-10-18 批准此溝通流程文件；不新增玩法或實作授權。文件追蹤：[#79](https://github.com/lalagrass/earth-ascension/issues/79)。適用 Sect Chronicle，服從根目錄 [CONTRIBUTING](../../CONTRIBUTING.md)，不取代其認領、審核或合併規則。

## 溝通放在哪裡

**Issue 留正式紀錄，聊天用來討論與決策，PR 負責交付。** Agent 不應只把重要問題藏在聊天或 PR 的長段敘述中。先搜尋原 task、提案與 backlog，已有相同議題就補充證據，避免重複開單。

| 類型 | 入口 | 可自行進行的範圍 | 需要決策時 |
|---|---|---|---|
| 當前已認領任務內的實作選擇、缺陷 | 原 task issue 留言；程式差異連到 PR | 不改產品語義、版本／存檔承諾、驗收門檻或其他主筆邊界的選擇，可依既有授權處理，附理由與測試 | 若發現超出認領範圍，拆提案或缺陷 issue，由所屬 PO 排程 |
| 新玩法、數值語義、存檔語義或任務範圍變更 | 獨立 `[Proposal][SG]` issue，連回原任務 | 分析問題、證據、方案與取捨；不預先加入程式、schema、API 或未批准原型 | 遊戲 PO 整理影響；依 CONTRIBUTING 交專案擁有人決定產品取捨 |
| 未來靈感，對當前任務無影響 | 先在 [#75](https://github.com/lalagrass/earth-ascension/issues/75) 留言，成熟到需獨立追蹤時拆 issue 並互連 | 保存構想與適用情境，不當成現在的待辦 | 維持未排程；需要時以文件 PR 同步 [FUTURE_BACKLOG](FUTURE_BACKLOG.md)，個別批准後才開實作包 |
| 共用 CI／根目錄契約／跨產品衝突 | 獨立 issue，連到 [共用佇列 #67](https://github.com/lalagrass/earth-ascension/issues/67) | 記錄影響、提出單一主筆建議；不逕改別人檔案 | 由兩 PO 協調、queue owner 排程；跨產品資源／未批准決策交擁有人 |

已批准範圍內的候選數值依 SG-02 與既有契約記錄、凍結及校準，不必把每次正常調整都當成新產品批准；新增玩法、數值語義或事前驗收門檻仍走提案。既有 D1–D6 不重問授權。

## 不讓建議阻擋當前工作

1. 提案必填「是否阻擋」並指出具體受影響的 task、檔案或驗收。偏好不同、可選重構與未來功能本身不構成阻擋。
2. **非阻擋：留紀錄後，繼續目前已批准且已認領的工作。** 不把提案加進原任務 DoD，不等待對方回覆才做其他工作，也不為提案偷偷增加前置欄位。
3. **真正阻擋：只暫停依賴該決策的部分。** 說明沿用現行契約為何無法完成、最小所需決策、可安全繼續的部分。若整個 task 都無法繼續，寫明原因，請所屬 PO 排程；不得自行搶做未認領任務。
4. 沒有回覆不等於批准。非阻擋時沿用現行契約；涉及待定語義時不靠猜測實作，也不把整個專案籠統標成等待批准。
5. 在正常交付／進度回報列出提案連結與需要的決策；只在狀態改變或有新證據時補充，不以重複留言催促。聊天中的決策需回填 issue 才能讓其他 agent 接手。

例：腳力／輕功想法留 #75，SG-01 繼續既有三屬性 schema；無需增加 movementSpeed。若讀檔新版本必須選擇「遷移或拒絕」，先指出受阻的讀檔分支，其他不依賴此選擇的已認領測試仍可做。

## 提案到交付

提案狀態可用內文字段，不要求建立 GitHub labels：`待分流 → 待決策／未排程 → 已批准範圍／延後／不採用 → 對應實作與驗證`。記錄理由與來源，不因關閉討論或合併規劃文件就視為實作完成。

- 提出者每次留言標明實際身份、日期、相關 head/base 與證據。共用 GitHub 帳號的 assignee 或留言不能代表另一 agent，也不是獨立 approval。
- 遊戲 PO 負責 SG 分流、依賴及驗收；有權限的決策者記錄採用／延後／不採用、理由、批准邊界與仍未決事項。若由 agent 轉錄使用者決策，明寫「轉錄」與可核對的原話／來源，不冒充擁有人留言。
- 批准後同步受影響的設計、task 與驗收，連結文件 PR；安排單一主筆、單一範圍工作包。文件若是實作前置，依既有流程先合入再開始依賴工作。
- 作者附實際驗證與版本影響；ready PR 由遊戲 PO 連同 head/base、證據、阻擋狀態交 #67。**Earth PO 是唯一共用 queue owner，執行 dev squash merge；遊戲 agent 不自行合併。** 本文件不授權跨聊天發訊息或自行啟動其他 agent。
- 合併後回填實際 commit、CI、完成與未完成項。實作 issue 在 DoD 完成後才關閉；#75 持續保留為未排程構想入口。28 天擴充與 Earth M3 授權不變。

## 可複製的提案 issue 格式

標題：`[Proposal][SG] 問題或預期改進（避免直接宣稱方案已定案）`

```markdown
## 身份與狀態
- 實際提出者／日期：
- 狀態：待分流／待決策／未排程
- 關聯 task／issue／PR：
- 核對版本：base dev SHA／相關 PR head SHA（無程式證據時註明）

## 問題或機會
- 觀察與證據／最小重現：
- 預期改善的玩家體驗或工程問題：
- 證據限制／尚未驗證假說：

## 方案與取捨
- 建議方案與理由：
- 替代方案（含維持現況）與代價：
- 範圍／預估成本／依賴／可能修改檔案：
- 規則、數值語義、schema／RNG／存檔及驗收影響：
- 不在本提案的範圍：

## 是否阻擋目前工作
- 是／否：
- 若是：具體 task／驗收、無法沿用既有契約的原因、最小所需決策：
- 可繼續的已認領工作：
- 若否：沿用目前契約繼續，不增加原 task 的 DoD／前置。

## 需要決定與驗證方式
- 需要誰決定、哪個問題：
- 建議的最小驗證、成功／失敗觀察（未批准門檻不可當定案）：
- 本提案僅供討論，不代表認領、批准或完成。
```
