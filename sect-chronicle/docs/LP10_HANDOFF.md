## 點選狀態與三條短路徑

| 狀態 | 玩家看見與可點位置 | 設計需交代 |
|---|---|---|
| S0 生活 | 原生活場景；點人物看面板 | 仍顯示原工作／精力／人工來源；不要假裝已有武技等級 |
| S1 發起 | 點「清理鼠群（設計示意）」與有限範圍預覽 | 明確是玩家發起；忙碌／恢復／已停工時如何合法出發仍是待決，不暗示無條件打斷工作 |
| S2 接近 | 目標鼠編號、前往路線與目前意圖 | 不瞬移／全圖追擊；移動腳力與出手熟練分開 |
| S3 起手與接觸 | 所選目標、站位、起手／接觸／收勢分鏡 | 設計稿中的「示意命中」不是權威判效；接觸前失效有下一狀態 |
| S4 換目標／逃離 | 有效下一鼠；警覺鼠逃跑方向與邊界 | 出界／無有效目標停止追；不把逃走說成擊殺或遷徙 |
| S5 停止與返院 | 隨時可讀的叫停入口；結束原因與返回路 | 區分示意擊倒、逃離、取消；回生活保留最新有效意圖／必要恢復的需求，精確接線待下一包定案 |

三條就好，不做全敵人×招式×命令矩陣：

- **A 連續處理**：S0→S1→S2→S3→S4→下一隻→S5。初學／熟練同情境分段對照，弱鼠一掌解決可作已標示的結果示意，未定HP不畫成已驗傷害。
- **B 目標先逃**：S2／S3→察覺威脅→鼠逃出有效範圍→取消這次接觸／換下一有效目標；無目標便S5。不能隔空補中、立即補鼠或追出範圍。
- **C 玩家叫停**：前往或出手流程按叫停→有明確取消／完成邊界的設計提案→S5返院；已發生結果不重複結算。標出「起手後叫停何時生效」是下階段待決，不用HTML假定正式語義。
