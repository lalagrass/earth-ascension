# 《山間道：靈氣復甦》長期願景草案

狀態：**擁有人來稿整理，未定案／未排程**。日期：2026-10-20；整理：Codex（遊戲 PO）。[討論入口](README.md)／[Proposal #152](https://github.com/lalagrass/earth-ascension/issues/152)／[完整原稿](sources/2026-10-20-shanjiandao-original.md)。遊戲名稱、雲隱道觀與現代社會設定都先作工作名稱／候選，不替代現有 Sect Chronicle 身份或批准契約。

## 希望玩家感受到什麼

一座現代山村，在靈氣復甦後，因師徒的生活、傳授與選擇，逐漸走向不同的未來。主角可以隱居修行，也能教人、看診、巡山或協助建設；村民與弟子有自己的生活與反應。太陽能板、快遞、藥圃與護山陣並存，讓現代生活與古老道法的碰撞成為辨識度。

原稿提出三根支柱：同一生活空間中的連續活動；世界生態自主變化並回應玩家；工作與修行帶來可觀察的成長。PO 建議先驗證玩家能看懂「誰在做什麼、為何這樣做、介入後改了什麼」，再擴大地圖與系統。無縫世界是體驗願景，不預先承諾全地圖同精度模擬。

## 公式與資料範例如何看待

原稿的工作速度、身法、技能倍率、平方遞減、凡人上限 25／傳功至 50、傷病等均是候選，不是已凍結數值。遞減公式本身不定義如何到達上限、何時鎖定或如何突破；需另定成長單位與取整。負重公式可能產生零／負移速，健康修正也可能導致零速，未來需先定義無法開工、最低速度或停止的語義。

接近瓶頸應顯示成長變慢的原因、可選途徑，以及繼續工作仍有的產出價值；不能因重複勞動突然懲罰玩家，逼每人都走修行。靈氣改變世界與個體收益的速度、免費恢復是否仍成立，都需要小型配對情境再定。

角色與 MountainZone JSON 只保存構想，不是現行 schema。工作意圖、活動、路徑與畫面位置需各有責任，不能以 `Maintain_Generator_And_Patrol` 字串默認一人同時工作與巡邏。SQLite／JSON／Resource／mod 能力是選項，不由這份範例自動立項。

## 與現有切片的差異

已批准可沿用：村莊復甦、師父與主角起步、援村後固定候選、可暫停即時自主生活、玩家介入、單一 JS 權威世界、正式存讀／回放。採集、建設、修行、煉丹與突破已有有限基礎，不因願景草案重寫。

新增／擴大而未批准：現代文明與外界社會、連續大圖、生活能力成長與新先天屬性、做飯／挑水／食宿、醫療經濟、電力工藝、可變生態、巡防、即時戰鬥、輕功捷徑、授課社交、完整村莊自治。人格／命格延伸見[另一份草案](PERSONALITY_DESTINY_DRAFT.md)。

技術上先沿既有 JS 世界與視覺 adapter。Godot／Unity 是遠期候選，不因本稿變成遷移決策；開源比較沿 #145 與[既有方案評估](../FUTURE_BACKLOG.md#門派經營與開源方案參考)。原稿 TileMap 用詞的版本限制亦已在該評估說明。

## 建議的驗證順序（非排程承諾）

1. 先完成當前生活 UI 與真實試玩，觀察師徒自主、暫停介入與原因回饋。
2. 依試玩缺口另挑一個小實驗：生活成長、傳授、現代村民互動，或人物命譜呈現。先看同一個十分鐘場景是否更有意思。
3. 再評估外出風險／巡山與村莊反應，先用少量區域與明確因果；戰鬥內容另批。
4. 輕功可達性、多人社會、完整無縫生態、外交／大地圖更後面，允許延後或留其他產品。

原稿「生活→生態戰鬥→授課輕功→村莊自治」四階段、每階段四週共十六週，保存為來稿內容順序；沒有完成人力、素材、既有能力與技術成本估算，不作交期。PO 建議保留生活優先，但讓低成本的傳授／村民互動候選也能先於完整戰鬥評估，不把階段串成固定長依賴。

## 接下來值得討論的決策

| 待決策 | PO 初步建議與取捨 |
|---|---|
| 現代山村是正式世界觀嗎？ | 有辨識度，值得優先討論；需界定外界政府、物流、醫療與技術可用程度，解釋道觀存在的價值，不先做完整現代國家模擬 |
| 第一個十分鐘的主角選擇是什麼？ | 在清修、照料師徒生活、幫村民三者間選一個可見差異，先驗證一個，不增加十項家務 |
| 成長是專長還是全能累積？ | 先做少量專長與環境影響，避免工作越多者所有能力都壓倒其他人 |
| 村莊是否可能沒有主角也能自立？ | 保留此路線，使傳授、資源與組織真正有意義；代價是需要可見的村莊能力與因果資料 |
| 什麼算完成一段生活？ | 用角色／村莊的階段性成果與回顧提供滿足感，仍可繼續觀察；不先恢復固定第十四天獸患結局 |
