## 精力示意值

所有速率以**遊戲秒**計，1秒＝60固定tick。倍率只決定餵多少tick；render／wall clock不直接扣回精力。內部保留精度、UI可取整，不能用顯示值判斷門檻。

| 項目 | 本輪設定 | 說明 |
|---|---|---|
| 範圍／新局 | 0～100；兩人都是100 | clamp在範圍內；不因圓潤／精瘦改起始精力 |
| 工作消耗 | 每遊戲秒1（每tick 1/60） | 只在挑水／採藥的去程、採集、回程、交付四段扣；較快完成同路線較省精力 |
| 自主恢復條件 | 院中閒置且精力≤30，或當趟交付後≤30 | 比滿庫等待優先；不打斷半趟／丟資源。精力>30可開始下一趟 |
| 去／回休息點 | 精力不扣、不回 | 往返有權威移動時間，採出發時既有空手速度；不是工作、不產出、不成長 |
| 坐下恢復 | 每遊戲秒5（每tick 5/60） | 只有實際到座位後恢復；去程、回程、庫存滿等待都不偷偷恢復 |
| 自主續工門檻 | 精力≥80 | 結束自主恢復，返回共同院中端點，再檢查最新工作／容量並決定出發或等待 |
| 玩家明確停工 | 可坐到100，但維持停工 | 到80或100都不解除；需明確「開始挑水／採藥」才解除 |
| 降至0 | 本趟仍完成，完成後恢復 | 不負值、不傷病／死亡／降速，也不另開一趟；不改當趟鎖定腳力 |
| 無操作／等待 | 無每日衰減；庫存滿等待不扣、不回 | 原水每60秒耗1擔、藥架不耗用保持；本包不添加消耗製造工作 |

每tick依步前活動計一次扣／回，再結算進度與轉場：工作完成那步只扣工作精力，到座位的步不額外算恢復；下一個座位tick才回精力。不在單步同時扣工作又回休息，不按人物重複推全域時間／耗水。

紙上節奏（沿LP03現有 `tripSteps`，不含往返休息路）：主角先挑水兩趟38.45＋34.77＝73.22遊戲秒，100降至約26.78，坐下恢復到80約10.64秒。熟手Lv3三趟約95.65秒，降至約4.35，恢復約15.13秒。這只是公式推算／示意節奏，非新實作實測；4×便於2～3分鐘內看懂循環，不能把倍率當能力增長。

## 休息點與狀態

院中共同工作端點沿LP03 `(962,512)`。作者依可讀性在附近設一個可見休息區、兩個固定座位（每人一席），路線接回此端點；不建通用名額／排隊系統，不拉長通勤湊內容。座位、蹲坐／倚坐姿態與精力回升看得見，可復用現有休息素材／暫用動作並標明，不整套重畫人物。

最少分清「工作／院中等待」「走去休息」「坐下恢復」「回院中」，以及恢復來源**自主**或**玩家停工**。原工作種類獨立保留，單一pending只代表最新指令，不當多層任務堆疊。休息流程無材料／工作容量預約；返回院中才重新檢查並預約。水／藥滿庫就明示等待，不強制改做另一工作。

所有休息往返座標、進度與花費都由同一模型tick決定，renderer只顯示。每段出發鎖空手速度，不能切job／精力狀態就重置到院中或座位。新增一條路／少量階段即可，不重建導航、碰撞／門禁或第二個walker。休息不授予腳力、修為或工作趟次。

## 指令與邊界（本輪採用）

| 當前情境 | 玩家指令與結果 |
|---|---|
| 正在工作途中 | 改工作／本趟後停工仍是最後指令覆蓋單一pending；當趟交付與釋約一次後才生效。改工作不能跳過必要恢復 |
| 交付／院中決策 | 先完成入帳／成長與釋約，套最新指令；玩家停工則走去手動休息，否則精力≤30走去自主恢復，否則按工作容量續做／等待 |
| 正走去休息 | 改工作更新保留工作，叫停改來源為手動；走完本段才處理下一步，不瞬移／在半途反覆折返。已進休息流程須恢復至80才返工 |
| 已坐下自主恢復 | ≥80自動返回，回到院中才開工；改工作更新返工種類，不重設精力／恢復進度 |
| 自主恢復途中被叫停 | 轉為玩家停工；繼續到座位／保持坐下，可回滿但不自動離開 |
| 玩家停工時按開始工作 | 解除手動停工並保留新工作；精力<80先恢復至80，≥80則開始返院。指令當下不移動、不加精力；需返回端點後才可出發工作 |
| 正在返院中 | 最新改工作只更新種類；玩家叫停則本段走完後去座位手動停工，不再出工作。後續開始工作可覆蓋先前叫停，不疊加舊指令 |
| 取消待執行 | 沿原pending語義，只取消尚未生效的工作／停工指令；不能靠取消抹掉精力低的恢復需求。已生效的手動停工以開始工作解除 |
| 暫停／背景 | 可更新意圖／零進度狀態，但tick、位置、精力、產出與成長不變；不可命令時直接跳到座位／院中。沿既有背景停止與不補時語義 |
| 重來 | 精力100、兩人原Lv1/Lv3／挑水，清休息來源／路程／pending／所有預約，水3／8、藥0／8；不保留前局手動停工 |

本輪手動持續工作也允許必要恢復，但工作種類及最新意圖不能丟失；這是D14對生活runtime的有限規則，不暗改舊RT00手動鎖。不能以「自主」為由永久覆寫手動停工，或因庫存滿而解除它。

## 畫面與驗收

面板／名冊最少顯示：精力值與條、工作種類、現在工作／走去／恢復／返院／等待、恢復來源、下一步。自主時寫「恢復至80後返回採藥」等；玩家停工時寫「已停工，需下令開始」，不能用同一個「休息中」掩蓋不同結果。往返與坐姿看得見，390px可選兩人、看精力／原因及下令，保留鏡頭／44px選取與原控制。

2～3分鐘可見出口：兩人自主挑水→4×看一人交付後走去恢復，另一人繼續→點他看精力與原因→恢復至80後自行返院續原工作→途中暫停改採藥，恢復後遵守最新工作→對自主休息者明確叫停，回滿後仍不開工→明確開始後返回→重來清狀態。無需真人等升滿或跑完所有人生。

必要驗收（局部組合反例，不按每格表格寫鏡像單測）：

1. 精力依固定模擬時間消耗／恢復、正確clamp與門檻（30會恢復、略高不強制恢復、80可返工）；休息往返、等待、暫停／背景不回精力，工作完成與到座位的同tick不雙算。
2. 精力低或到0仍完整交付一次、釋約／成長一次；下一趟不搶先開。休息不產出／成長、無在途預約，返院重查容量；兩人可同時恢復且不串狀態。
3. 自主恢復到80會返工；玩家停工到100仍保持，含自主轉手動、低精力時解除停工、最新工作覆蓋與取消pending；不用完整命令組合矩陣。
4. 走去／回來及雙向工作切換位置連續、每tick位移受鎖定速度限制；暫停改令位置不動。沿LP03反例，不能僅驗狀態字串。
5. 同固定模擬時間的不同render分段／1、2、4×得相同模型結果；背景原handler未改時復用舊證據，只驗新精力沒有旁路；新局清精力／來源／路程／意圖／預約。
6. 一條真實桌面與390px流程，開截圖看精力／來源／可選人與可介入；保留必要基本檢查與dev CI。與本包無關的舊世界長矩陣／全裝置／幀快照不重跑。
