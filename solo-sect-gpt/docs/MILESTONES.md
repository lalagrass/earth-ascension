## 2. 驗收證據與節奏

每一可見出口用一段 2–5 分鐘可看懂的操作摘要或其關鍵連續畫面，長遊程可另保完整命令／事件紀錄。新局起走，透過正常表單、點地圖／面板、時間控制；不得 console 塞資源／設等級／跳完工／直接呼叫模型當作 UI 通關。單元 fixture 可直接設狀態測反例，但要與玩家證據分開命名。

固定新局種子在正常 UI 可填／顯示，開發冒煙 3 個固定 seed（候選 11、29、47）；一般局部行為 5 個（另加 71、101）。這只是開發回歸，不能拿它宣稱正式分布。spec 先列第一章完成、控制權、守恆、狹路、同圖戰鬥、儲存的代表場景；必要單測與 golden 保留。正式效能或分布報告另訂足夠樣本，不以 3 seed 充當報告。

正常 UI 最少覆蓋：

1. 預設自創從零開始至立匾，包含雇工轉身份、基礎深修、真遠征和救人結果。
2. 另一新局完成保糧結果；三經典模板各走一段正常開局，驗證同預算與差異理由。
3. 成年結伴／同住、義學／慕名／奇遇三入口、五名俠的已定節點與成熟作客互斥各可到達；可用保存後分叉測試，原始存檔由正常遊玩取得。
4. 一次改派、站位競爭、狹橋相遇、九劍失敗、負重／受傷召回和壞檔載入的可見反例。

上述可合併流程，不要求每個組合做一份錄影。每段記版本、種子、倍率、操作、預期／實際、失敗與證據路徑。工程通過、作者體驗判斷、真人回饋分開；沒有真人試玩就明寫未驗。

## 3. 完成條件與交接格式

規劃 ready：四份規劃＋可檢視 SVG/HTML＋尺寸／來源／自校，先 commit 完整成果，再以另一 commit 寫 `handoff/planning.ready.json`，`artifactCommit` 指完整規劃 commit；本階段的 `remainingDecisions` 只放真正阻塞。本版沒有需要先詢問的外部決策。

spec ready：讀規劃指定 commit，交 `docs/SPEC.md`、`docs/ACCEPTANCE.md`、`docs/ASSET_CONTRACT.md`、`docs/IMPLEMENTATION_ORDER.md`；先查設計座標與 source gaps，補齊安全室內動線、操作拒絕／恢復、保存一致性及時鐘。不能把圖上的線直接視為已驗導航。提交完整文件後再提交 `handoff/spec.ready.json`。spec 不實作 runtime，不替本階段修改 ready 指向。

development done：SL0–SL7 開發範圍全過才寫 `handoff/development.done.json`，附 `artifactCommit`、驗收證據及實際限制。半完成留 checkpoint，列已做／未做／下一步，不用 `done` 混淆。不能用「時間到了」「測試全綠」「已畫圖」代替完成。一般可逆問題自行補修，受阻才停相依部分。

所有階段保留 BRIEF 與上游 commit；只改 `solo-sect-gpt/`。不 push、PR、merge、部署，不使用 8800 或原存檔 key。未來正式整合另按當時契約，不把這次設計等同 dev 已採用。
