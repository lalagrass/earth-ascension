# M12 選擇說得清楚：實作前規格

base `54ede04`（GPT / Codex 新增 M12–M16 規劃文件，未改程式）；實際主筆 Claude Opus 5.5（Anthropic，經 Claude Code），單一作者。本節先 commit；結果與補修另列在「實作紀錄」，不回改。M10 的 `done_with_exception` 與其失敗方向保留原樣，本階段只補新的情境與說明。

## 盤點

- M9 比較的兩個起點都沒有已開工工地，「修屋」量不到；新局換 seed 結果相同，不是獨立情境。
- 經營頁的方針卡只寫固定說明，不告訴玩家「現在選它有沒有作用」：沒有工地時修屋沒有加成可用、最終膳房前備糧不會囤乾糧。
- 遠行預估已算出精力，但沒有說清楚每份乾糧會怎麼被用掉：營地用糧在精力接近上限時不增加精力；抵達補餐只在精力低於 60 且手上多於 1 份時發生；多帶的糧佔包裹，會擠掉帶回物。M10 的「3 份比 1 份抵達精力高」在滿精力出發時不成立，正是這個上限造成。

## 有限實作

1. 經營頁方針卡加「此刻」一行，讀真實狀態：修屋＝已開工工地數、各自缺的木／石與倉中可取量；備糧＝餐／水對目標、最終膳房與乾糧儲備；修行＝外功場樁位數與今日成人平均修行秒。沒有作用時明寫（例如「目前沒有已開工的工地，修屋不會改變任何人的安排」）。
2. 遠行預估每人加「用糧計畫」：營地吃不吃、抵達會不會補、回程剩幾份；並在下列情況加提示：營地那份糧不增加精力（上限）、抵達補餐條件不成立、多帶的糧佔掉帶回物空間。預估仍標「以實際移動結算」。
3. 只有在比較或 UI 發現選項在指定情境沒有可見差異時，才查原因做最小修補；不新增方針、需求或懲罰數值。

帶糧說明另有模型比較（沿 M10 fixture，不改 M10 結論）：滿精力出發 1 份慢休 vs 3 份用糧、出發精力 42 時 1 份 vs 3 份、3 份採藥的包裹限制；檢查預估的用糧計畫與提示和實際結果一致（營地那份糧在上限時實際未增加精力、抵達補餐實際發生與否、帶回株數）。

## 事前驗收

1. 三情境×三方針完整跑完落檔；三個方向逐一判定。
2. 方針卡「此刻」行：沒有工地、膳房未到最終、無外功場時都顯示具體文字；數字與 World 一致（模型測試直接比對）。
3. 用糧計畫與提示：上述三種帶糧情境中，預估的「營地是否加精力」「抵達是否補餐」「帶回株數」與實際一致。
4. 缺料、滿包、滿精力反例、取消、中途存讀、M7–M11 與審查修補的既有測試全部照常通過。
5. 正常 UI（1440×900、1280×800）：A 起點匯入→建設頁下令修靜室→經營頁看到修屋「此刻」從無工地變成有工地並選修屋→實際施工進度增加；另一段遠征頁選 3 份與 1 份比較預估提示→出發→返院報告與預估一致。

## 第一次比較後的追加註冊（B2，結果出來前寫定）

第一次比較（comparison.json）中 B 情境三種方針結果完全相同：24000 tick 都沒人做事、桌上一直無餐。原因不是方針，而是起點存檔裡兩位成人都已被玩家「停工＋關閉自主」（該存檔來自第一版 UI 測試的收尾），所以方針沒有任何人可以影響。B 的事前方向因此判為「起點無效、未通過」，結果保留。

追加 B2：同一存檔，比較前以人物頁同樣的操作讓兩位成人「恢復自主」並「開啟自主」（指令 resume＋auto），其餘不變；三方針各 24000 tick，指標與方向同 B（備糧的桌上無餐 tick 低於另兩種）。A、C 不重跑。
