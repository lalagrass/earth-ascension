# M8 看懂人物：實作前規格

base `6ce2816`；Claude Opus 5.5（Anthropic），單一作者。M7 已封存才開始。本節先 commit，實作補記另列，不回改標準。

## 盤點

- 人物頁把四十多個按鈕一次列出（勞作、相處、試招、同堂、器械、武學三軌、職務、方針、庫存目標），不論此人正在做什麼。M2 的「現在／原因／接著」只有日課開啟時最完整；共享安排（M7 的擁有者）不在面板上。
- 阻擋原因多為內部字串，例如「候位：kitchen.cook／阿木」「目的倉滿：water」「缺料：veg」，畫面標籤只寫「候位」。
- 畫面上人名下方的狀態字（11px、無底色）直接疊在草地上，對比不足；搬運、行走、休息、修行、交手只靠一個字詞，沒有形狀提示。
- `--muted #7b816e` 疊在 `#f5efdf` 約 3.8:1，低於 4.5:1；人物清單的選取只靠底色。
- 已有低動態開關（停止人物擺動）、跟隨鏡頭與剖屋頂。

## 參考（2026-10-26 實讀）

[Game Accessibility Guidelines 完整清單](https://gameaccessibilityguidelines.com/full-list/)：採用「重要資訊不只靠顏色」「足夠對比與可讀字級」「關閉背景動態」「清楚表示可互動元件」「簡單清楚的語言」「提醒目前目標」。不採用字級／介面自由縮放與重排（需另建設定系統，超出本階段）；只是作者對照，不宣稱通過任何認證。

## 有限實作

1. 新增純函式 `src/person-view.mjs`：`situation(w,p)` 產生情境卡（現在、原因、接著、所屬共享安排、阻擋原因與可做的事、最多六個情境操作）；`blockedAdvice` 把已知阻擋字串轉成玩家語言並附建議操作；`predict` 用 M7 的 `ownershipGate` 與 `beginError` 乾跑，讓按鈕顯示「為何不能按」。不改 World。
2. 人物頁改成：人物清單（選取者加 ▸ 與粗體）→ 狀態列（精力／生命／傷勢文字＋條）→ 情境卡 → 情境操作 → 可收合的次要分組（勞作與修行、與人相處、試招、同堂授課、器械、武學三軌、職務與方針）。收合狀態存在 view，換人與重繪後保持。
3. 不能執行的情境操作照樣顯示，旁邊寫原因；共享安排中的人，卡片直接提供該擁有者的恢復操作（遠征：前往遠征頁／全隊召回；同堂：退出或結束同堂；交手：叫停；相處：叫停；約定：取消；遠行同伴／救援／其他約定：說明要等什麼）。
4. 畫面狀態：人名下方改成有底色的狀態膠囊，前置形狀符號：搬運▣、行走➤、休息／睡眠☾、修行◆、交手✕、受阻⚠、遠征⚑、倒地✚；受阻時寫短原因（例如「⚠ 等灶」）。符號與文字並用，不只靠顏色。選取者多一圈虛線環。
5. 調整 `--muted` 與狀態字顏色到 4.5:1 以上；按鈕停用時保留可讀文字與原因。

## 事前驗收

1. 模型：對 M7 的每一種擁有者（遠征、同堂老師／學生、切磋、演武、教習、門風、約定、遠行同伴、救援、其他約定），`situation` 都給出擁有者名稱與至少一個恢復操作或「要等什麼」的說明；按照卡片提供的恢復操作送出指令後，該人物在有限 tick 內 `commitmentOf` 為 null 或擁有者改為合法的全隊返程。
2. 模型：`blockedAdvice` 對原始碼中所有固定阻擋字串前綴（候位、缺料、目的倉滿、來源用盡、無路、先建、乾糧不足、成品目的倉滿、原料已預約、精力／傷勢等）都輸出具體對象與建議，不輸出只有「候位」「忙碌」「不可用」的文字。
3. 模型：`situation`／`predict` 執行前後 World hash 相同；固定 5 seed 回放與完整回歸不變。
4. 對比：面板正文、muted、狀態膠囊文字與其底色的對比 ≥ 4.5:1（測試直接讀 style.css 與 render 常數計算）。
5. 正常 UI（1280×800、1440×900 各一次）：新局與既有 showcase 存檔；點畫布選人、人物頁情境卡、展開／收合分組後換人仍保持、鏡頭跟隨、剖屋頂、低動態開關；收起掌門簿後截圖能辨識至少搬運、行走、休息或睡眠、修行、交手五種狀態；面板無水平捲動。
6. M7 拒絕在 UI 可理解且可恢復：遠征準備中的人物卡顯示「遠征隊」與「全隊召回」，按下後卡片回到一般狀態；同堂學生卡顯示同堂與「退出同堂」，按下後只退自己。
7. 既有回歸、M7 測試、根檢查照常通過。
