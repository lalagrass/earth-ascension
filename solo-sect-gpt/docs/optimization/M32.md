## 玩家問題與來源

想知道「水夠不夠、菜還有幾份、有沒有人正在搬」要在設施卡、經營簿、人物卡之間來回找。

- 新公版固定 dev `6f959f534e9a00994f1cea7c230b4110e60db8c6`（以 `gh api` 依 SHA 讀）：`resource-view/contract.mjs`（五欄 amount／capacity／incoming／reserved／available，各欄自帶 source／unit／availability）、`resource-view/render.mjs`、`public-ui/values.mjs`（`publicValueHtml`）、新版 `character-card/contract.mjs`。`resource-view/gpt.mjs` import `scene-shared/sources/gpt` 舊核心——**不採用**，但它對本核心的說法照收：`dest:` 預約只是容量、`availableQty` 是同 tick 供料查詢、不猜淨額。
- 本核心權威：`sourceFor(item)`（水→`vat`、餐→`table`、其他→`store`）、`qty`、`inventories[inv].capacity`（採集時按「容量－該品項現量」判斷）、`reservations` 的 `source:`／`dest:`、`availableQty`、`RECIPES`、`FACILITIES` 施工需求、M31 的可靠在途查詢（送回階段＋背包實物）。

## 修改範圍

1. 新增 `src/resource-view.mjs`：水、木、藥、菜、餐五項，只讀各自公開倉位（缸、倉、桌），不加總野外、背包或尚未發現的物資。amount＝現地實物；capacity＝該倉容量（本核心每品項口徑）；reserved＝`source:` 預約精確加總；available＝`availableQty` 原值（不改稱可自由支用）；incoming＝M31 可靠在途（誰、什麼、往哪裡都可查），預留入庫容量另寫在說明裡、不當在途。用途讀 `RECIPES` 與正在施工的需求。
2. 連結：每項連回 M27 設施卡（缸→膳房、倉→倉庫；餐桌不屬三張卡之一，連結標不適用），按下只開卡、不派工；派工仍從設施卡或人物卡送既有命令。
3. 介面：建設頁頂端加「資源總覽」（採用的 `resourcesHtml`），在設施卡之上。總覽不進存檔。經營簿照舊。

## 事前驗收

1. 讀總覽前後世界 hash、RNG 不變；同命令序列有讀／沒讀總覽的兩個 twin 結果相同。
2. 口徑：0 是 known 0；amount 與核心 `qty` 相同；reserved 與 `source:` 預約加總相同；available 與 `availableQty` 相同（含同 tick 已被開局快照限制的情況）；出發時預留不算在途、回程才算；目的地滿時採集被核心擋下、總覽沒有在途；途中改派（停工）後在途消失、預留釋放；做飯預約菜後 reserved 增加、取消後回落。
3. 正常 UI（1440×900、1280×800）：缺菜（實際做飯用完）→ 總覽看到菜 0 → 按「倉庫」開設施卡 → 派人採菜 → 回程時總覽有在途 → 交付後實存增加 → 做飯、出餐，總覽跟著變。
4. 回歸全過。
