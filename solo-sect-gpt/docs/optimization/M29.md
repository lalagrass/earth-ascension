- `sect-chronicle/assets/shared/`（#348）：三份獨立 manifest；GPT 那份 `gpt-1.0.0`（`coreCommit` 寫 6cbd3e6 舊核心）列出 5 筆：

  - `scene.bamboo`、`scene.boulder.large`、`scene.boulder.small`：場景裝飾，「不是碰撞或世界權威」。
  - `person.adopted-girl.portrait`：**缺**（來源、權利未知），映射 `gpt:child`，不得拿別人頂替。
- 權利：「owner-reuse-documented; third-party-rights-unverified」——擁有人帳號生成、同 repository 內使用有記錄，沒有 repository 授權檔，也沒有第三方權利的最終結論。
- 以 `gh api` 依固定 ef823ac 取回 hero.png、hero.json、bamboo.png、boulder_l.png、boulder_s.png，五個檔的 sha256 都與上游 manifest 一致（7a0f42ac…、e324ecee…、23bed590…、5757f2b1…、f18764f0…）。

## 修改範圍

1. **本地資產**：把上述 5 個檔原樣複製到 `assets/shared/ef823ac/`（不改位元組、不另存裁圖）；新增本地 manifest `gpt-local-1.0.0`（`coreCommit` 寫本分支 base 提交 a1bb5be…，不沿用 6cbd3e6），每筆保留上游原路徑、原提交（ac7148d…）、作者、權利、用途、腳錨與 sha256；本地 pin 鎖 manifest 檔的 sha256。採用上游 `resolve.mjs` 的驗證、`resolveAsset`、`portraitFor`，只把「合法本地路徑」由 `sect-chronicle/` 改為本目錄的 `assets/shared/`。執行時不連網、不跨 worktree。
2. **外觀綁定（明確規則）**：hero `idle-0` 只用在「自創掌門」範本的掌門（沒有既定經典外貌）；郭靖、令狐沖、岳不群範本的掌門維持文字替代，不共用同一張臉；小禾維持「收養女孩正式立繪尚缺」；其他人維持色塊姓氏。人物卡卡首用裁圖，地圖上的人物仍是原本的程序人物（idle 裁圖不是走路／出招圖集）。圖片載入失敗就回到文字替代。
3. **場景素材**：竹叢放在林緣、兩塊大小石頭放在石場旁，依腳錨與 y 排序跟人物、樹一起畫（可被前方人物遮擋），純裝飾、不影響通行與碰撞。
4. **原生動作呈現**：新增 `src/motion-view.mjs`，把核心的 `action.phase`（起手／出招／收勢）、招式所屬家族（拳、推掌、棍、劍、九劍、短步）與當下活動（行走、搬運、練功）對成一份呈現意圖，給地圖繪圖與人物卡「此刻動作」共用；內容包招式回到它的基礎招家族；家族對不上（例如沒有對應兵器畫法）就用中性出手並標明是回退。不改命中、耗能、位移或任何階段長度，不另跑時鐘。

## 事前驗收

1. 資產：本地 5 檔 sha256 與 manifest 相符；pin 鎖住的 manifest 被改一個字就驗證失敗；未知 assetId→unsupported、缺圖→missing 並有可讀替代；腳錨在 0–1。
2. 綁定：自創掌門有裁圖；三種經典範本的掌門、小禾、阿木都沒有；人物身份與權限不因外觀改變。
3. 動作：掌門與阿木各實際出一招，motion-view 的階段與核心 `action.phase` 每 tick 一致；暫停時切卡、重繪不推進 tick；呈現呼叫前後 hash 不變。
4. 正常 UI（1440×900、1280×800）：自創掌門的人物卡有裁圖、郭靖範本新局的掌門沒有；地圖上看得到竹叢與石頭；能辨認搬運、練功與同圖出招（截圖），人物卡寫出此刻動作與核心階段。
5. 回歸全過；`render.mjs` 變更後資產清單雜湊同步。
