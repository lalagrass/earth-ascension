# M41 自然退場時凍結演練截止：實作前規格

base `1f2181b`（d9c7810 加上原樣提交的 GPT / Codex M41–M44 計畫）；實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。

## 玩家問題（P2）

聯合演練兩波自然打完時，`combat.sessionsTick` 把演練改成 `exiting`、清掉參加者的 `combatSession` 與動作；`jointTick` 只在 assembling／running 偵測離開，M37 的 `jointCut` 又只在命令處理完才跑。所以自然退場後，沈禾第一次朝空地試拳先耗精力（7779→7579），命令結束時才凍結 `bodyAt`，回顧多算 200（規劃者正常 UI 證據：應 1215、記 1415）。

## 真實順序

一個 step 內：`sessionsTick`（自然完成 → exiting、清 session）→ `jointTick` → `combatAI` → 移動／戰鬥／活動。命令在 step 之間處理。

## 修改

`jointTick` 在偵測離開、併入紀錄之後、回顧之前，對已不在 assembling／running 的演練呼叫同一個 `jointCut`：還沒離開的參加者在這一刻記 `bodyAt`，演練記 `closedAt`。因為這發生在同一個 step 的 `sessionsTick` 之後、`combatAI` 與活動之前，也在下一個命令之前，任何場外試招、自主生活、新活動都在截止之後。沿用 M37 的 `closedAt`／`bodyAt`／`cut`，不加新欄位、不升存檔版本。

- 截止前最後一招／命中照算（同一次 `absorb` 先併入）；之後的招式、命中、精力、傷勢都不算。
- 已人工退出的人保留自己的 `cut`／`bodyAt`；`closedAt` 一旦記下不覆寫（`jointCut` 開頭就檢查），重複 tick 或重複終止不改第一次的快照。
- 不禁止試招、不保留假 session、不停自主生活。
- 舊檔：在 exiting 中、還沒有 `closedAt` 的舊檔照讀；讀入後第一個 `jointTick` 就截止（最早可安全截止點），讀檔前已發生的消耗無法分辨，不反推、不拒讀，寫進限制。

## 事前驗收

1. 模型（M23 示範存檔＋標註休養 fixture，兩翼包抄）：自然兩波打完、exiting 當下不下命令 → 回顧＝截止快照；exiting 同 tick 試拳 → 不算；exiting 後恢復日課／坐休走動 → 不算；先人工退出一人、其餘自然完成 → 各自截止；終止（`endDrill`）與全員退出仍沿 M37；最後波次的擊退、出手計數與截止前相同；exiting 當下存檔（未下命令）解碼續跑與原局 hash 相同、回顧相同；去掉 `closedAt`／`bodyAt` 的舊形 exiting 檔（標註 fixture）照讀、在讀入後第一個 tick 截止。M37 全部舊斷言照過。
2. 修前同一份測試在 base 上失敗的紀錄。
3. 正常 UI（1440×900、1280×800）：兩波自然打完 → exiting 時暫停 → 沈禾試拳（精力下降、tick 不變）→ 繼續到回顧；回顧耗精力＝開打時精力－截止時精力（以暫停快照實測，不硬填數字）。
4. 完整回歸全過。
