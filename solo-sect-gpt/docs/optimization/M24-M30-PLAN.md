## M24 — 活動與 session 所有權修補（小至中）

**玩家結果：** 取消真的取消，退出演練後不會被舊演練打斷新切磋。

1. `mentor.mjs`：談定方向期間執行 `mentorDirectionCancel`，完成 callback 仍會把方向改回 set。取消須終止對應活動，或以有效身份／世代檢查拒絕舊 callback；取消後重新提議不得被舊活動覆寫、送信任或授予目標完成。
2. `combat.mjs`：聯合演練全員退出後，cleanup 遍歷原 actors 清掉已退出者的新 `combatSession`。重現順序：amu＋shen 演練→shen 退出→shen 與 leader 切磋→amu 退出→舊演練取消。取消與正常結束清理都必須按所屬 session；外部切磋兩端、target、路徑與統計不得遭舊 owner 寫入。

**出口：** 兩條正常命令序列、取消／重提、退出／另開活動、自然結束皆有針對性回歸。保留前次失敗證據，不只驗最終布林值。

## M25 — 補完演練與自主生活的玩家結果（中）

**玩家結果：** 守線有可理解的用途，弟子受阻／恢復後能回到原目標。

M20 的四次比較未證實守線價值；M21 部分案例只觀察一天，不能把未發生恢復當已證明恢復後續作。本階段明確接回這些未完成出口。

- 限原演練區、最多三名成年角色、兩波。允許調整這個有限演練的敵人抵達間隔、路徑配置與遭遇參數；先寫 spec 與合理範圍，再實驗。不改全域玩家傷害／成長以製造勝利，不加無限入侵或新戰鬥引擎。
- 預先固定至少兩個可正常達到的隊伍／來路情境；每組從同一狀態分叉比較前攔與守線。記漏敵、攔截位置、受傷、能量、時間及出手。至少一個守線有用途的案例與一個代價／不適用反例，另檢查深修隊伍不被刻意削弱。保留失敗比較，不事後只挑成功 seed。
- 重現 M21 的無效候選重選及傷後恢復情境。沿既有合法權限修選擇／活動所有權；若時間不足，按真治療規則延長事前觀察窗，不為過測試加快治療。用日課、自主武學及休息後回目標的正常 UI 流程收尾。

**出口：** 分工比較成立，恢復後真實續作有證據；限制或未完成與實際通過項分開。核心玩家出口未達不能自行用 `done_with_exception` 解除。

## M26 — 當前核心的人物／武學公版接入（中）

**玩家結果：** 人物生活、成長與下一招資訊一致；既有新功能不因套公版消失。

- 建本地來源清單：上游 commit、檔案、版本／hash、依賴閉包、採用／改寫／不採用理由。只攜入必要純契約／呈現與其授權註記；本地 adapter 明記本核心來源，不能繼續標舊 `GPT_SHA`。不直接 import `scene-shared/sources/gpt` 或公版 harness。
- 擴充既有 `public-view.mjs` 而非並存兩套投影。保留生活方針、師徒方向、聯合演練與後續故事；穩定 ID 不含版本 SHA，來源資訊另存。角色切換與命令仍指向同一原生 ID，執行時由現核心重驗。
- 五項 stats 是創角基線／目前常態；沒有獨立成長或起始記錄就明示缺項。energy 顯示除以 100 僅單位轉換；U/F/I 與 sources 分開保留。
- 武學四類條件只映射確有規則的 entry／capacity／control／special，標作用階段；學會、下一招可學與當下能出招分開。未有腿法不把 step 改名腿法；無法計算的風險為 unknown。

**出口：** 開卡／切頁不改世界、RNG、物品與事件；known 0 保留，hidden 值不進 DOM／序列化快照，unknown／unsupported／notApplicable 可區分。舊 M19 正常流程及資料包缺失回退仍通。

## M27 — 從設施卡看懂派工與缺料（中）

**玩家結果：** 點設施知道誰真的在用、缺什麼，以及能採取哪個合法行動。

先做三個既有設施：倉庫、膳房、練功區；以本核心實際 ID 為準。若其一缺少足夠權威資料，spec 說明並選一個既有施工點替換，不新增建築系統。

- facility／interaction point 分開；門口、站位、建築外框與裝飾 anchor 不混。到場者與路途中角色分列；只有核心真的有容量／預約／排隊才顯示該值。
- 庫存、正在運送、已保留物資不能重複加總；沒有歸屬到該設施的庫存就標未提供，不能套全門派資源當現地存量。
- 從現有命令接派工／查看角色／定位；過期卡片、角色忙碌與施工取消時由核心拒絕並回報原因。只可抽共用純查詢，不複製第二套可用性公式。

**出口：** 正常 UI 完成一段「缺料／受阻→看到原因→合法派工→實際搬運→設施或工地進展」；同一角色能從地圖、人物卡、設施卡互相定位。滿位／未知容量、途中取消、讀回後失效引用都有處理。

## M28 — 可追溯的近期門派紀事（中）

**玩家結果：** 看懂剛才誰做了什麼，能回到該人物／設施；不知道的事不被編出來。

- 接現有 journal，以 event 自身的結果與原因投影；不得拿目前 `reason` 或相鄰事件反推歷史因果。M20–M22 新事件先列實際支持目錄，未知類型保留未知結果。
- 沿公版有界快取（最多 120 筆、畫面最多 24 筆），原生 `event.N` 加世界 epoch，處理 ring rollover／重複讀取。只有現有可見 actor／facility 才能連結；回顧不授予獎勵、不重跑事件。
- hidden 事件不留下列、數量、時間、篩選或 ID 洩漏。讀取游標可消費，但不可成為可見統計。不能假定現在可見代表過去事件可公開。
- 換新世界、成功載入及時間回退重設 epoch／快取；載入失敗保留原世界與快取。近期快取不進存檔，不假裝永久人生履歷。

**出口：** 過量紀事有界、同 tick 多事件、成功／失敗讀檔、離開／未知人物、隱藏事件有反例。正常 UI 串事件→人物→武學或設施，開關紀事不改核心結果。

## M29 — 有限素材與原生動作呈現（中）

**玩家結果：** 卡片與地圖更有辨識度，走路、搬運、練功和出招仍忠於真正活動。

- 先核固定 manifest 的來源／使用範圍，僅採已接受的少量 hero idle crop 與竹、石場景素材；必要檔案複製到本分支本地資產目錄，保留原 commit／hash／provenance，更新來源清單。不跨 worktree 連結、不 runtime CDN、不整包搬 art 庫。
- 明訂 actorId→design／skin→portrait／sprite。hero crop 只可用於外觀相符的模板，不讓所有自創／經典掌門突然共用同一張臉。女孩素材仍缺就維持中性或既有回退，不拿另一角色頂替。來源或 BRIEF 例外不明的特定素材先保留缺圖，不因此聲稱素材已採用。
- 保留 Canvas 與現有程序人物；公版場景語義透過小 adapter 對齊腳錨、遮擋、選取。沒有必要不引入 Pixi 或統一座標系。
- 一招先驗 leader 與另一位原本有權限的成年角色：native action.phase→呈現模板→相容動作族→外觀。缺兵器／體型圖格用明示相容回退。idle 裁圖不等於走路／出招圖集；不生成新圖、不更改命中、耗能、位移與 phase 長度。

**出口：** 資產 hash／本地載入／缺圖回退、腳錨與遮擋可核；暫停、快轉、切卡不推動第二個戰鬥時鐘。正常 UI 至少可辨搬運、練習與同圖出招。完整新角色動畫、全場景重繪仍列後續。

## 建議公版後續補充（本批只記本地建議，不修改上游）

1. GPT adapter 提供注入目前核心查詢／命令的邊界與 capability 宣告，避免每次 release 綁死舊展示核心。
2. 初始快照／目前常態／當下值及結構化 U/F/I 維度可保留原生單位，不只字串熟練度；無歷史明示缺失。
3. 設施把已到場、路途中、容量、排隊及物資歸屬分清；unsupported 不是數值 0。
4. 事件補世界 epoch、原生 ID 穩定性與歷史可見性能力說明；不要把 adapter 暫時序號宣稱永久人物經歷 ID。
5. motion manifest 宣告體型、兵器、腳錨、原生 phase 綁定與缺圖回退；portrait 與動作圖集分工明確。

這些是 GPT 使用端的需求，不代表其他版本已有同樣核心能力，也不預占 #339 等共用工程。
