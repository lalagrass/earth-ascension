# M17 修復交付邊界：實作前規格

base `422139a`（GPT / Codex 的 M17–M23 規劃與公版轉接設計，原樣 commit）；實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。M12、M15 的 exception 與原比較結果不改寫；不借機調招式。

## 玩家問題與已重現的缺口

1. **練不到的方向**：熟練上限是 100，但 `proposeDirection` 不看可達性——弟子拳熟練已 91 以上時仍可定「深修 +10」，練成驗收永遠約不到；方向一旦成立又不能取消或改方向，只能卡住。器械 +6 同理（F95 以上）。另外完成驗收後也不能再定下一個方向。
2. **聯合演練壞檔**：`save.mjs` 只檢查 `drill.joint.stats` 的鍵屬於參加者，不檢查每人的 `moves`／`hits`／`received`；`stats` 子物件為空也能讀入，演練結束時 `Object.values(s.moves)` 崩潰。歷史回顧的每人紀錄也沒有逐項檢查。
3. **上手提示倒退**：M16「經營」那則讀 `opsPlan.days`（只留 4 日）；工地完工又過 4 日後，打勾會消失。

## 修改範圍

1. 可達性在兩個時點都檢查：提出方向時，以及「定向之約」真正記下基準時。不可達時提出被拒並寫出原因（目前熟練、上限、需要的增量）；若在答應後才練到不可達，定向之約完成時不記基準，方向改為「無法達成」並寫紀事。
2. 明示出口：師父或弟子可「取消這個方向」（提出中、已答應、已定向但未驗收，或無法達成時）；練成驗收完成後方向視為「已完成」。取消、無法達成或已完成後，師父可再提新方向；新方向重新走答應→定向之約→真練習→練成驗收，舊方向與其三段後續的紀錄移入方向歷史（最多 4 筆），不刪除、不再領取。不授予任何成長或驗收。
3. 保存：方向狀態增加 `unreachable`／`cancelled`／`completed`，方向歷史有版本、狀態、時點與引用驗證；仍是師徒 v2（不升版，新增狀態值在 M17 之前不存在於任何存檔；舊 v2 檔照常讀入）。聯合演練進行中與歷史回顧逐項驗證：參加者、分工、每人 moves（招式 ID→正整數）、hits、received、時點；不合法就拒絕，正在玩的世界不被覆寫。
4. 提示：「經營」那則改讀永久的指令紀錄（採用經營簿之後是否真的下過建設指令），不讀 4 日經營資料。其他三則改讀永久事實（定向之約曾完成、已學進階招、演練回顧存在）。

## 事前驗收

1. 深修：弟子 F 89、90 可提出；91、100 被拒並寫原因；F 85 答應後練到 F 95 才約定向之約 → 方向成為「無法達成」、不記基準、不加成長。器械：未學或 F 94 可提出；F 95 被拒。
2. 取消／重定：每個可取消狀態都能取消；取消後可提新方向，新方向的三段後續可再約一次；已完成的方向不能取消；舊方向與後續紀錄保留在歷史；取消與重定不改武學數值。
3. 拒絕的提出、取消都不改世界（去掉指令紀錄後 hash 相同）。
4. 存檔：空 stats、缺 moves、moves 值非正整數、hits 為負、歷史回顧人物不一致都被拒絕；原有效存檔與 M15 回顧照常讀入；以 UI 匯入壞檔時正在玩的世界不變。
5. 提示：模型中工地完工並過 5 日後「經營」仍打勾。
6. 既有 M7–M16 回歸全部通過；M13 的完整弟子路線與 M15 演練照常完成。
7. 正常 UI（1440×900、1280×800）：新示範存檔匯入 → 林青的方向（深修，尚未驗收）由師父取消 → 改提「學棍」→ 林青答應 → 定向之約完成，路線顯示新方向與舊方向歷史；另以 UI 匯入一個 stats 被清空的演練存檔，看到拒絕訊息且原局不變。

## 實作紀錄

`mentor.mjs` 新增 `reach`（F100 上限可達性）、`cancelDirection`、`archiveDirection`；提出方向與定向之約都檢查可達性；練成驗收完成後方向為 `completed`，可再提下一個方向；舊方向與它的三段後續移入 `directionHistory`（≤4）。新指令 `mentorDirectionCancel`；師徒分組新增「取消這個方向」，取消／無法達成／完成後可再提方向；成長路線多一列「過去的方向」。`save.mjs` 驗證新狀態值與方向歷史，聯合演練進行中與回顧逐人逐欄驗證（moves 招式→正整數、hits、received、不允許多餘欄位、分工與人物一致）。`guide.mjs` 改讀永久事實：採用經營簿後是否下過成功的建設指令、定向之約是否曾完成（含方向歷史）。
