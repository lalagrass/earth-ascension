# M21 自主生活有個性且能回到目標：實作前規格

base `3e6060e`（M20 交付）；規劃 GPT / Codex（M17-M23-PLAN），實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。

## 重讀程式後查到的問題

1. 閒暇找人聊天時，對象一律是排序第一個有空的同門，與關係、性情無關。
2. 作業受阻 30 秒後只冷卻 10 秒，同一件做不成的事會反覆被選回來。
3. 武學練滿（熟練 100）後，日課照樣排「練功」，什麼也不會增加，等於空轉。
4. `p.reason` 文字附帶性情原始分數（「勤勉2／顧人2」），對非掌門是隱藏值。
5. 人物卡的「原因」只寫接單理由，看不出目標來自日課時段、補給地板、門派方針、職務或自由選擇。

## 修改範圍（自主生活 v1，明示採用）

1. 日課頁新增「採用自主生活 v1」（需已採用建議日課），`w.autonomyPlan={version:1,adoptedAt}`，標記 `chapter1-autonomy-1`（最高優先），舊 reader 拒絕；未採用的局行為不變。
2. 採用後：
   - 閒暇交談對象依既有關係（信任高者優先，同分依 id），不新增數值；顧人傾向（性情第二軸 ≥1）的人在閒暇時，若身邊有受傷同門，多一個「照料」候選。
   - 同一件作業受阻後的冷卻改為逐次加倍（10、20、40、80、160 秒），成功做完一次就歸零；冷卻次數記在既有的 `lastBlockedTask`，並納入存檔驗證。
   - 練功時若選中的武學已熟練 100，改練另一門未滿且可練的武學；全都練滿就不排練功，原因寫「所學已練滿，可改選方向」。
   - 原因文字不再附性情分數。
3. 人物卡（不論是否採用，只讀）：「原因」下多一行「目標來源」：補給地板／日課修行時段／工作時段／自由選擇／門派方針加成／職務加成／玩家指令／臨時指令。
4. 危急補給優先、單一活動所有權、臨時命令與回日課都沿用原規則，不改。

## 事前登記的比較（模型；結果出來前寫定）

新局 seed 29、採用建議日課與武學方針；兩種人物配置只差掌門範本：G＝郭靖（勤勉 2、顧人 2）、L＝令狐沖（勤勉 −2、顧人 1）。每格各跑「未採用」與「採用自主生活」兩次，同一起點分叉，跑一個模擬日（12000 tick），不做任何玩家介入。

| 場景 | 起點（標註 fixture） |
| --- | --- |
| P1 正常供給 | 新局開工後的狀態，不加料 |
| P2 工地缺料 | 宿舍開工，但倉內與野外的石材歸零（等同已採完） |
| P3 傷後恢復 | 掌門傷勢 70 |
| P4 練滿 | 掌門基礎拳熟練 100（等同長期練成） |

指標：每人各類活動 tick、活動切換次數、受阻 tick、同一受阻作業被重新選回的次數、補給低於地板的 tick、最後一餐日數、「需要介入」（同一人連續 60 秒無進展且非休息／睡眠）次數。

事前方向：
- A1（不在失敗任務打轉）：P2 採用後的「受阻作業重選次數」與受阻 tick 都少於未採用。
- A2（不挨餓）：四個場景採用後的補給低於地板 tick 都不多於未採用，且每人當日至少吃到一餐的比例不降低。
- A3（個性看得出來）：採用後，P1 的 G 掌門在練功＋施工的 tick 多於 L 掌門；L 掌門在散步＋坐休的 tick 多於 G。
- A4（傷後回到目標）：P3 採用後，掌門在傷勢降到 60 以下後，同一模擬日內回到非休息的日課活動。
- A5（不空轉）：P4 採用後掌門練「已滿的基礎拳」的 tick 為 0；未採用時大於 0。
- A6（關係影響對象）：採用後，閒暇交談對象的平均信任不低於未採用。

介入次數若兩組皆為 0，只照實寫 0，不宣稱改善百分比。

## 事前驗收

1. 未採用的局 hash 與行為不變（既有回歸）；採用拒絕條件（沒有建議日課）不改世界。
2. `lastBlockedTask` 冷卻次數存讀雙軌相同；不合法值被拒；`autonomyPlan` 未知版本被拒。
3. 人物卡與原因文字不含非掌門的性情原值。
4. 回歸全過。
5. 正常 UI（1440×900）：新局 → 採用建議日課與自主生活 → 4 倍速觀察一個完整模擬日，記錄模擬時間、倍率與牆鐘時間；中途下一次臨時指令，看到完成後回到原日課；人物卡顯示目標來源。1280×800 另截人物卡可讀性。

## 第一輪比較（結果照實記錄）

`m21-model/comparison-r1.json`。A1 **不成立**：P2 兩種掌門下，採用前後的受阻作業重選次數（3、14）與受阻 tick（3428、3514）完全相同。逐 tick 追查：受阻多半是工地等石材「來源用盡」，人物多數不是靠「受阻 30 秒」那條路離開，而是換時段時交接；加倍冷卻幾乎沒有被觸發。A2 成立。A3 成立，但與未採用時完全相同（性情加分原本就有，不是本包的效果）。A4 **不成立**：掌門傷勢 70 在一個模擬日內沒有降到 60 以下（休養速度如此），採用前後都沒有回到日課；這是場景長度不足，不是自主行為的差異。A5 成立（練滿的基礎拳：未採用 6939／2953 tick，採用 0），但出現新問題：採用後掌門在修行時段沒有可練的武學，修行時段又只允許練功，於是**閒站 4550 tick**，介入次數從 0 變 1。A6 成立（新局關係幾乎都只有初始信任，差異很小）。

## 第二輪設計修正（第二輪結果出來前寫定；場景、指標與 A1–A6 不改）

1. 所學全練滿時，修行時段不再只允許練功，改從閒暇選擇中挑（散步、交談、坐休、照料）。
2. 採用後，作業因「來源用盡」受阻時立刻放下，並在當日剩下的時間不再選同一件（來源隔日才會再生），不必等 30 秒。

## 第二輪比較（結果照實記錄）

`m21-model/comparison-r2.json`。A1：郭靖局成立（重選 3→2、受阻 3428→3328）；令狐沖局**不成立**（重選 14→16、受阻 3514→4269）。追查重選明細：工地相關的重選已消失（阿木不再回頭做缺石的宿舍），剩下的全是**小禾的院內散步**——未成年人的散步走另一條自主分支，每 10 秒換一個散步點，不看受阻紀錄；其中一個點常有人站著擋住，未採用時也有 12 次。A2、A3、A5、A6 成立；A4 仍不成立（理由同第一輪）。練滿的掌門在無事可做的時段閒站（原因寫「所學已練滿，可改選方向」），介入次數回到 0。

## 第三輪設計修正（第三輪結果出來前寫定；最後一輪，結果不論如何都交付）

採用後，小禾的散步也看受阻紀錄：剛受阻的散步點跳過，改走下一個安全點。

## 第三輪比較與最後採用的版本

`m21-model/comparison-r3.json`。小禾散步跳過受阻點之後，令狐沖局的重選次數反而從 16 增加到 28，P4 又出現 1 次需要介入。原因：散步點輪流換，三個點陸續都進了「曾受阻」名單，之後每走一次都被算成重選；這項改動讓結果變差。所以**撤回第三輪改動**，交付的是第二輪設計；撤回後重跑的 `comparison-final.json` 與第二輪逐格完全相同。

## 實作紀錄

- `life-policy.mjs`：`adoptAutonomy`（需建議日課；`w.autonomyPlan={version:1,adoptedAt}`、`chapter1-autonomy-1`）；閒暇交談對象依信任排序；所學全練滿時修行時段不再限練功；`goalSource` 只用已知理由產生「目標來源」；修行時段已滿 60 秒時原因改寫「今日60秒已滿，加練」（原文寫「保留今日60秒」不對）。
- `activities.mjs`：受阻冷卻逐次加倍並記在 `lastBlockedTask.n`，做完同一件就清除；「來源用盡」立刻放下、當日不再選；顧人傾向的人閒暇多一個照料候選；`trainableArt` 跳過已滿或此刻練不了的武學；原因文字不再附性情分數。以上只在採用後生效。
- `save.mjs`：`autonomyPlan` 版本與欄位、`lastBlockedTask` 形狀與次數範圍驗證。
- UI：日課頁的採用鈕與說明；人物卡情境多一行「目標來源」。
