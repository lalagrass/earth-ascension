## 修改範圍

1. **唯讀游標（不改核心事件 id 或歷史）**：feed 的游標改成「最後一筆數字 `event.N` ＋ 之後已讀的非數字筆數」，從 journal 實際順序找新事件；每筆事件給 adapter 自己的遞增序號，唯一 id＝`來源:epoch:序號:原生 id`，原生 id 只當來源引用。若最後看到的 `event.N` 已被 500 筆 ring 捲掉，所有 `event.N` 更大的事件與其後的非數字事件都算新的；ring 開頭、在第一個更大 `event.N` 之前的非數字事件無法判斷是否看過，保守不收（寫進限制）。世界 epoch、成功／失敗讀檔沿 M28。
2. **參與截止快照**：v2 演練記錄參加者離開時（同一個偵測離開的 tick）的精力與傷勢 `j.bodyAt[id]={energy,injury,tick}`；回顧對已離開者用截止快照、對留到最後的人用結束時的值。舊途中檔已離開但沒有快照的人，回顧該人的 body 寫 `null`（畫面寫「退出前的消耗無法從舊存檔重建」），不反算假值。出手／命中／受擊仍沿 M24 的離開 tick。新欄位 `bodyAt` 有版本內驗證，舊檔沒有此欄照常讀入；回顧 body 值允許 `null`。
3. **設施卡物資分三種**：「預留入庫容量」＝`dest:` 預約（只是容量保留）；「已被預約取走」＝`source:` 預約（不變）；「正在送來」只在能證明「誰、帶著什麼、往哪裡」時才列：該 `dest:` 預約所屬活動正處於送回階段（`deliver`），且那人背包裡真的有這件物品，數量取背包實數與預約數的較小者。查不到就是空，不是 4。

## 實作紀錄

- `event-feed.mjs`：游標＝最後一筆 `event.N`＋其後已讀的非數字筆數；每筆給 adapter 遞增序號，唯一 id＝`來源:epoch:序號:原生 id`；原生 id 只作引用，核心事件不改。
- `joint-drill.mjs`：v2 偵測到參加者離開的同一 tick 記 `bodyAt[id]`（精力、傷勢、tick）；回顧對離開者用快照、留到最後的人用結束值；舊檔離開者沒快照寫 `null`。`save.mjs` 驗證 `bodyAt`（只能是已離開的參加者）與回顧 body 的 `null`。`ui.mjs` 對 `null` 寫「退出前的消耗無法從舊存檔重建」。
- `facility-view.mjs`：新增「預留入庫容量」（`dest:` 預約）；「正在送來」只取送回階段且背包有貨的那筆，數量取背包與預約較小者。`ui.mjs` 分三欄顯示。
