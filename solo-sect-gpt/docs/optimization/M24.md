# M24 活動與 session 所有權修補：實作前規格

base `0a1a625`（fa203b2 加上原樣提交的 GPT / Codex M24–M30 計畫）；實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。

## 玩家問題與已重現的缺口

1. **取消的方向被復活**（`mentor.mjs`）：師徒正在談「定向之約」時按「取消這個方向」，方向變成「已取消」；但那段談話照樣走完，完成時 `completeEvent` 把方向改回「已定向」、記下基準、加雙方信任。取消後若立刻改提新方向，舊談話完成時也會把新方向當成已定向。
2. **退出演練後的新切磋被舊演練清掉**（`combat.mjs`）：已重現——阿木＋沈禾聯合演練 → 第一波入場後沈禾停工退出 → 沈禾與掌門切磋 → 阿木也退出 → 舊演練判定全員退出，清理時對**原名單上每個人**清空 `combatSession`、目標與出招：沈禾的切磋 session 被清成 null、目標被清掉，掌門那端還留著切磋 session 與到期時間，兩端不一致。正常結束（退場）路徑也有同樣的整份名單清理。
3. 統計：聯合演練 v1 的出手／命中／受擊照「名單上的人」計，退出後在外面切磋的出手也會算進舊演練（v2 已在 M20 修，v1 沒有）。

## 修改範圍

1. 取消方向時，正在進行的方向相關談話（定向之約、練成驗收、歸來相談）一併終止（兩端都停、不完成、不記事件、不加信任）。另在完成時再檢查一次方向狀態與方向「世代」：談話開始時記下方向的提出時點，完成時若方向已不是同一個或狀態不符，整段不算（存讀後的舊活動也一樣）。
2. 演練的所有清理（全員退出、正常退場、終止）只動 `combatSession` 仍是這場演練的人；已退出、正在別的 session 的人，其 session、目標、出招、路徑與停工狀態都不碰。
3. 聯合演練 v1 的統計只計當時仍在這場演練中的參加者（v2 規則不變）。
4. 不改存檔格式；談話活動多帶一個方向世代引用，存檔驗證會檢查這個引用。

## 事前驗收（正常命令序列，檢查雙方完整狀態，不只布林值）

1. 定向之約談話中取消：談話兩端的活動都結束、方向維持「已取消」、無基準、無「定向之約」事件、雙方信任不變。
2. 取消後立刻改提學棍並答應：舊談話不存在；新方向的定向之約要重新約，完成後基準來自新方向；舊方向留在歷史。
3. 存讀：在定向之約談話中存檔、讀檔後再取消，結果與不存讀相同（雙軌 hash 相同）。
4. 演練序列：阿木＋沈禾 → 沈禾退出 → 沈禾與掌門切磋 → 阿木退出 → 舊演練結束：沈禾與掌門兩端的切磋 session、到期時間、目標、出招保持原樣，之後切磋照原規則結束並寫入兩人的切磋紀錄；舊演練回顧中沈禾的出手數停在退出時。
5. 同一序列換成「舊演練由玩家按終止」與「舊演練自然打完」各一次，結果相同。
6. 回歸全過；M15–M20 的演練與 M17 的方向測試照常通過。

## 實作紀錄

- `mentor.mjs`：取消方向時，終止師徒兩人身上正在進行的方向相關談話（定向之約、練成驗收、歸來相談）；`completeEvent` 對這三種談話再檢查方向狀態與世代（談話帶 `dir`＝方向的 `proposedAt`），不符就寫「這段談話對應的方向已取消或換了，不再算數」，不記事件、不加信任、不記基準。
- `world.mjs`：約這三種談話時在活動帶 `dir`；`save.mjs` 驗證 `dir` 只能跟師徒後續一起出現且是合法 tick。
- `combat.mjs`：演練的「全員退出」與「退場完成」清理只動 `combatSession` 仍是這場的人。另外修到一個同類錯誤：切磋結束原本只關掉先被輪到的那一方，另一方會留在半關的 session（被擊敗的一方旗標先被清掉）；改成兩端一起結束、各記一筆切磋紀錄。
- `joint-drill.mjs`：v1、v2 都記參加者離開的 tick（v1 新增可選欄位 `left`，存檔驗證），回顧只計離開前發生的出手／命中／受擊。舊存檔沒有 `left` 照常讀入。
