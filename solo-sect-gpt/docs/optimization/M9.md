# M9 經營有選擇：實作前規格

base `5f0ca0e`；Claude Opus 5.5（Anthropic），單一作者。M8 已封存。本節先 commit；實作補記另列，不回改標準與實驗設定。

## 盤點

- 物資帳本 `w.ledger` 只有每種物資的 initial／produced／consumed 總數，沒有來源、日期，也不區分庫存、預約、手上與工地。紀事只留最近 500 筆，一日（12000 tick）的搬運事件就會被擠掉，無法回溯。
- 門派方針有「修屋／備糧／修行」三選項，但程式只讀 `build`（施工 +20）與 `train`（練功 +20）；**「備糧」實際上沒有任何作用**。
- 掌門簿只有「近一分鐘：n 次成長 · n 鍋交餐 · n 處完工」。
- 職務（主／次）與日課補給地板已存在，可沿用。

## 參考（2026-10-26 實讀）

[Eremite Games Rebel Hideout 1.11](https://eremitegames.com/rebel-hideout-update-1-11/)：更新紀錄裡有把「為何受阻」用圖示與說明直接標在介面上（季節轉換受阻的鎖頭、交易受阻的提示）、需求滿足的實際加成直接寫在說明、改寫飢荒警示文字。採用「受阻原因與確切影響直接寫出來」；不採用其建築／交易／種族系統，也不把開發者的單次改動當普遍共識。

## 有限實作

1. 明示採用「經營簿 v1」（`w.opsPlan`），新局與舊檔都要按一次才啟用；採用後保存標記 `chapter1-ops-1`，舊 reader 明確拒絕。未採用的世界行為與 hash 不變。
2. 真實流量帳（只在採用後記錄）：`add()` 的來源（採集、烹調、施工耗用、用餐、招待、營地用糧……）逐日記入「產出／耗用」；`transfer()` 記入「交入庫存」與「從庫存領出」。每 tick 分類每位成年常住者的時間：勞作、搬運、行走、修行（含交手）、休息、用餐、相處、受阻、外出、閒置；受阻再依原因累計秒數與人物。只留今日與前三日。
3. 摘要分欄且不重複計算：**庫存**＝倉／水缸／餐桌的實物（其中「已預約」單獨列出，是庫存的子集）；**手上**＝人物包裹與鍋中；**工地**＝已交到工地的材料；**今日耗用**＝流量帳。每一行都寫來源（例如「餐 −6：用餐 6」「木 −4：施工 4」）；瓶頸列原因、秒數、人物，並附 M8 的建議。
4. 方針取捨（只在採用經營簿後生效，沿用原三選項與職務）：
   - 修屋：沿用施工 +20。
   - 備糧：糧水目標提高（水到缸容量、餐到每位常住 3 份），補給相關的取水、採菜、耕作、烹調 +15；最終膳房後另以每位成年常住 2 份乾糧為儲備目標。代價是時間：勞作時段做補給，就少做施工；用料是真的菜與水。
   - 修行：沿用練功 +20。
   不新增任意懲罰或數值腐壞。
5. 新「經營」頁：採用、方針選擇（逐項寫出它實際改變什麼與代價）、今日／昨日帳、時間分配、瓶頸與回溯。

判讀（只描述，不挑選）：

- **五個新局 seed 結果逐值相同**：本作的 seed 只影響野生物初始朝向等，新局三人的生活路徑不受影響。實際上只有兩個獨立起點，不能當五個樣本。
- **兩個起點都沒有已開工的工地**，而事前規定不加其他指令，所以「修屋」在這次實驗裡等於沒有加成可用：差異不明顯，不能據此說修屋沒用。修屋的收益要在玩家下令施工後才會出現。
- **備糧**：期末庫存最高（showcase 30、新局 18），showcase 的最低庫存也最高（19 對 11）；代價是每位成人修行少約 100 秒、熟練增加較少、受阻較多。showcase 裡備糧的「桌上無餐」反而最多（434 tick）：最終膳房後的乾糧儲備真的用掉菜，與做餐搶同一批菜。這是「為遠行囤乾糧」對「今天的飯」的實際代價，沒有調參掩蓋。
- **修行**：修行秒數與熟練最多、showcase 從未斷餐，但庫存緩衝與修屋一樣薄（最低 11），新局受阻秒較多（等練功位）。
- 適用情境：準備遠行、預期有人外出時選備糧；要趕工時先下令施工再選修屋；物資穩定、想讓弟子成長時選修行。新局早期三種都會斷餐（1213 tick），根因是開局只有野菜與小水缸，不是方針。

中斷保留：第一次比較在補上收成流量前被我主動停止（只跑完 showcase 三列），留存為 comparison-interrupted-before-harvest-flow-fix.log；收成補記不改行為，三列數字與正式輸出相同。
