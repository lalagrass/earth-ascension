# M18 公版語義與 GPT 唯讀轉接：實作前規格

base `291fcc7`（M17 交付）；規劃 GPT / Codex（M17-M23-PLAN、PUBLIC-PANELS-ADOPTION），實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。

## 上游版本與取用

- 固定上游提案 `6e5e69dbe3fa166f06659d7835feb510deb9f08b`：`sect-chronicle/docs/CHARACTER_CARD_PUBLIC_PROPOSAL.md`（R2）與 `MARTIAL_ART_PUBLIC_TEMPLATE_PROPOSAL.md`。以 `gh api` 讀一次固定版本作設計參考；runtime 不載入、不依賴 GitHub raw，也不把上游文件複製進本版。
- 上游狀態是「評估基準」，不是已發布 schema。本地轉接版本 `gpt-public-adapter` v1，欄位命名沿上游第 4 節（semanticId／category／availability／rawValue／unit／domain／provenance／origin／changePolicy／initial／base／effective／visibility）。GPT 擴充欄位（snapshotTick、reasonCode、visibility 與命令權限分開、sources 保留範圍）放在 `gpt` 命名空間，不宣稱其他兩版支援。
- 投影只在記憶體中產生，不進存檔；沒有新的持久狀態，所以不升存檔版本。

## 本版對照（事前查核的事實）

| 公版語義 | GPT 來源 | 投影方式 |
| --- | --- | --- |
| 身份 | `people[id]` 的 id、name、rank、adult、kind、residence | actorId 用穩定 id；不從姓名或顏色認人 |
| 現在／原因／下一步 | `person-view.situation` | 直接引用，不另算 |
| 體魄／臂力／身法／悟性／定力 | `stats[0..4]`，1–7，創角後程式內沒有任何寫入 | category 依真作用：體魄＝capability（生命上限 80+5×）、身法＝capability（轉身、短步收勢）、悟性＝aptitude（學理增量）；臂力、定力在現行規則找不到作用，照實標「本版無規則作用」。origin＝創角基線，changePolicy＝fixed；initial 沒有獨立快照 → unknown，不從現值反推 |
| 性情兩軸 | `traits[0]`（勤勉＋／隨興−，創角問題 q0+q1）、`traits[1]`（顧人＋／自持−，q2+q3），−2..2 | persona，非戰力 |
| 精力、生命、傷勢 | energy 0–10000、hp/maxHp、injury | 資源 current/max；精力原值與顯示值（÷100）都給，不叫耐力 |
| 用餐 | meals／mealDay | 當日紀錄，不是飽足值 |
| 移動與負重 | `navigation.speed`（DU/秒，含負重、傷勢、低精力）、distance、`bagWeight` | performance，effective 為當下值；distance 是行走累計，不叫腿力 |
| 武學定義 | `ART`、`movesFor`（core 與已安裝包） | artId／moveId／pack id+version 分開；規則值原樣 |
| 人物所學 | `skill[art]` U/F/I、contexts、sources、contentMoves | 三值分列；sources 在程式中從不截斷，起始拳 U5 沒有來源紀錄 → 照實寫 |
| 招式能否使用 | `content.movePrerequisite`、`combat.startAction`、`actionTiming` | 見下「共用純查詢」 |

## 可見性政策（照現行 UI 已揭露的範圍，不新增揭露）

- 掌門（leader）的五項屬性與性情兩軸：玩家在創角時親自設定 → known。
- 其他人的五項屬性與性情：現行 GPT UI 從未顯示原值（只透過行為文字間接呈現）→ hidden。hidden 在投影產生時就不放原值（不是只藏在畫面），快照序列化後也找不到。
- 資源、行動、武學 U/F/I、所學招式：現行 UI 已顯示 → known。
- 野外／守路人等非門人：只出身份、資源與行動，屬性 notApplicable，操作清單為空並寫原因。
- 能看見不等於能命令：小禾（未成年家人）快照完整可見，但練武、研讀、試招操作都附核心給的拒絕原因。

## 共用純查詢

`combat.startAction` 目前把「招式是否已學會、是否持對器械」與副作用（放下背包、扣精力）寫在一起。抽出兩個純函式 `moveLearnError`（內容招式是否已研讀、前置是否足）與 `moveKitError`（武學是否學會、器械、九劍持劍、推掌真授），`startAction` 改為呼叫它們，原檢查順序與拒絕文字不變；投影也只呼叫它們。距離、空間、精力、起手中等當下條件仍只在核心按下時判定，投影標為「按下時由核心判定」，不在面板另算。

## 新模組 `src/public-view.mjs`（責任僅四項）

1. `personSnapshot(w,id)`：人物快照（身份、現在、分組數值、資源、表現、性情、GPT 擴充）。
2. `artDefinition(w,art)`／`moveDefinition(w,move)`：武學與招式定義投影，不含任何人的進度。
3. `personArts(w,id)`：人物所學投影（每門 U/F/I、階段、來源、該門可用招式與學會狀態）。
4. `personActions(w,id)`：可用操作描述（指令意圖＋快照當下核心預判原因），按下時一律重送核心。

每份輸出帶 `adapter`、`snapshotTick`、`rulesVersion`；全部是新建的純資料（structuredClone 後可序列化），不持有世界參照。

## 事前驗收

1. 不改世界：對 leader、amu、child 與一名野外人物各產生四種投影，前後世界 hash、RNG、事件數、物品、技能完全相同；同一 seed 下有無呼叫投影，跑 600 tick 後 hash 相同。
2. known 0 保留：精力 0、傷勢 0、熟練 F0 都是 availability known、rawValue 0；不出現以 0 代替 unknown／hidden。
3. 五種 availability 分得開：leader 屬性 known、amu 屬性 hidden（無 rawValue 鍵、序列化文字不含其原值欄位）、initial unknown、臂力／定力作用 unsupported、野外人物屬性 notApplicable。
4. 武學：基礎拳（core 招直拳、推掌未真授 → 拒絕原因）、九劍入門（只有辨隙截擊一招，說明寫明非完整九式，未持劍時給核心拒絕原因）、一個已安裝進階招（M14 包 advanced.closefist：未研讀時給真前置、研讀後成為已學會）。
5. 共用查詢：抽出後原 startAction 的拒絕文字與順序不變（重放既有 M2–M17 回歸全部通過）；投影的招式可用性與 `command(attack)` 結果在測試案例中一致。
6. 過期操作：快照時「坐休」可用，之後人物被派去遠行／倒地，再送快照中的指令由核心拒絕或改按現況處理，不依快照 enabled 直接執行。
7. 受限人物：小禾的練拳、研讀、試招操作都附原因；可見資訊不少於其他門人（除 hidden 欄位）。
8. 正常 UI（1440×900）：人物頁新增收合的「公版資料（預覽）」區，選掌門／阿木／小禾分別展開，看到分組與 availability；阿木的屬性顯示「未揭露」，DOM 不含其屬性原值；展開前後（暫停中）世界存檔 hash 相同。正式版面留給 M19。
9. 既有回歸全部通過。

## 不做

不新增屬性或成長（根骨、腿力、耐力等）；不改招式數值或命令權限；不做 #339 素材、雷達圖、手機版；不改存檔格式。

## 實作紀錄

新模組 `src/public-view.mjs`（`ADAPTER` gpt-public-adapter v1，上游 6e5e69d）只有四個出口：`personSnapshot`、`artDefinition`／`moveDefinition`、`personArts`、`personActions`；輸出都經 structuredClone，不持有世界參照。共用純查詢：`combat.mjs` 抽出 `moveLearnError`／`moveKitError`，`startAction` 改呼叫它們（順序與拒絕文字不變）；`content.mjs` 抽出 `studyError`／`preferError`，研讀與偏好指令改呼叫它們；`person-view.predict` 也認得研讀／偏好指令。人物頁新增收合的「公版資料（預覽）」，展開時才產生快照。
