# M27 從設施卡看懂派工與缺料：實作前規格

base `334f0e7`（M26 交付）；規劃 GPT / Codex（M24-M30-PLAN），實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。

## 玩家問題、真實來源與缺口

點建築只會讓選中的人走過去；想知道「膳房為什麼沒在煮」「誰正搬東西進倉」「練功樁誰在用」得一個個點人。核心其實有足夠的權威資料（讀 M23 示範存檔確認）：

| 設施（本核心 ID） | 互動點 | 物資歸屬 | 佔用／排隊 |
| --- | --- | --- | --- |
| 倉庫 `store` | `store.drop`（交料處）、`store.work`（施工位）；門 `rects.store.door` | `inventories.store`（容量 96）；進出預約 `reservations` 的 `dest:store:*`、`source:store:*` | `station:store.drop` 一次一人的預約＋`queues` |
| 膳房 `kitchen` | `kitchen.cook`（爐灶）、`kitchen.vat`（水缸）；門 | `inventories.vat`（水，容量 24）、`inventories.pot`；`facilities.kitchen.wip` 正在煮的配方與進度 | 爐灶、水缸各一次一人＋排隊 |
| 外功場 `yard` | `yard.1`–`yard.4` 練功樁（可用樁數依階段 1／2／4，核心 `stationAvailable` 與畫面同一規則）；露天、沒有門 | 沒有歸屬此處的庫存 → 不適用 | 每樁一次一人＋排隊 |

上游 `facility-view/gpt.mjs`（ef823ac）綁 6cbd3e6 舊核心，把使用者、容量、排隊、命令一律標 unsupported——這只是舊投影沒接，不代表本核心沒有；不採用該檔。

## 修改範圍

1. 採用公版 `facility-view/contract.mjs`（`facility()`、`pickFacility()`）到 `vendor/public/ef823ac/`，更新 `SOURCES.md`；`render.mjs` 不採用（命令與人物切換與本版介面不同）。
2. 新增 `src/facility-view.mjs`（只讀）：三張卡各有互動點與門（外功場門＝不適用）、階段與施工進度、物資（現存／容量／正在送來／已被預約取走，分列不加總）、在場者（真的站在互動點 12 DU 內並持有該站位）、路途中（活動目標是此處但還沒到）、排隊者、受阻原因（取自那些人的核心 `blocked`）、可派的工作。外功場可用樁數抽成核心共用純查詢 `yardStakes(w)`，核心與卡片都呼叫它。
3. 合法派工只送既有命令：倉庫＝採木／石／菜／藥（入倉）；膳房＝做基礎餐／製乾糧／煮藥茶、挑水（入缸）；外功場＝練主修。按鈕停用時寫核心預判原因；按下仍由核心重驗。
4. 介面：建設頁頂端新增「設施卡」（三選一）；卡上的人名按鈕切到該人物卡；人物卡在其活動屬於這三處時多一顆「看設施」；地圖上三處各畫一個「設」字小標，點它開卡（不改原本點地面移動）。卡片是暫存畫面狀態，不進存檔。
5. 不新增建築、容量或排隊機制。

## 事前驗收

1. 投影不改世界（hash、RNG、事件、物品）；在場、途中、排隊與核心狀態一致；同一物資不重複加總；外功場庫存不適用、門不適用。
2. 過期：卡片上某派工可行，之後人忙了／被取消，按下由核心拒絕並顯示原因；讀入另一存檔後原先開著的設施若不在就回到清單，不報錯。
3. 正常 UI（1440×900、1280×800）：膳房卡顯示受阻原因（缺菜或缺水）→ 從卡上派一人採菜（或挑水）→ 實際搬進倉／缸、卡上的物資增加 → 爐灶開工、出餐；並示範地圖「設」標→設施卡→人物卡→「看設施」互相定位。
4. 回歸全過。
