# M7 指令可靠：實作前規格

base `292bc9a`；Claude Opus 5.5（Anthropic），單一作者。本節在實作前寫定並先 commit；之後的實作補記另列在「實作紀錄」，不回改本節標準。

## 已重現的 P2

`createWorld()` → 全員 `auto=false` → 測試 fixture `add(store, ration, 4)` → `expedition{actors:[leader], target:forest}` → `spar{leader,amu}` 或 `recall{leader}` → 2000 tick。結果：遠征停在 `prepare`、`packed=[]`、leader `storyBusy=true`、`activity=null`，存讀後一樣，且同時只能一隊遠征，玩家無從恢復（外部審查 probe 兩項失敗）。

原因：`dispatch` 讓隊員以 `pack` 活動和 `storyBusy` 表達「遠征擁有此人」，但 `spar`（`beginSpar` 內 `cancel`）和個別 `recall`（`begin('return')` 內 `cancel`）只拆掉 `pack` 活動，沒有釋放或轉移遠征的所有權；`expeditionTick` 只等 `packed.length===actors.length`，沒有偵測「無人再負責領糧」。現有 invariants 只檢查物資、預約與幾何，沒有活性（liveness）條件。

盤點同類路徑：`task`／`stop` 對隊員會把整隊設成無出口的 `halted`；`class` 老師、`drill`、`build` 的 actors、`guard`、`cohabit`、`story` 的發起人、`dispatch` 的隊員本身都沒有檢查他人既有的共享安排；`depart` 能送走正在護送途中的村人；修大廳時臨鋪遷床會無條件 `cancel` 正在領糧的掌門。

## 活動所有權

每位人物同時最多一個「擁有者」，由 `src/commitment.mjs` 從現有欄位推得（不新增平行狀態）：

| 擁有者 | 判定 | 個別改派（task/stop/guard/build） | 個別召回 recall | 新的共享安排（spar/class/drill/practice/story/culture/school/fame/dispatch/cohabit） |
| --- | --- | --- | --- | --- |
| 遠征 expedition | 進行中遠征的 actors | 拒絕，提示「召回全隊」 | 轉為隊伍語義：準備中＝取消出發（全隊解鎖、釋放預約、手中糧保留）；已出門＝全隊召回、實走返院 | 拒絕 |
| 遠行同伴 journey | 護送村人、營地切磋的守路人、被扶助的周行 | 拒絕 | 拒絕 | 拒絕；送客 depart 也拒絕 |
| 救援 rescue | 進行中的救援者 | 拒絕 | 拒絕 | 拒絕 |
| 教習對練 practice | 武學教習 trial | 允許，先叫停教習 | 允許 | 拒絕 |
| 同堂 class | classSession | 允許：老師離開＝整堂結束不給學理；學生離開＝只退自己 | 允許（同左） | 拒絕 |
| 演武 drill | 進行中演武的 combatSession | 允許，此人退出 | 允許 | 拒絕 |
| 切磋 spar | sparUntil | 允許，雙方一起結束 | 允許 | 拒絕 |
| 門風相處 culture | 進行中相處的 cast | 允許，整場叫停不結算 | 允許 | 拒絕 |
| 約定 story／接待 | story 活動雙方、義學／接待對象 | 允許，約定回到可重約 | 允許 | 拒絕 |
| 其他約定 appointment | 其餘 storyBusy（訪客到場、見證人） | 拒絕 | 拒絕 | 拒絕 |

規則：新的共享安排不能搶走他人共享安排中的人物；個別指令只能在上表允許時撤出，並由該擁有者的既有取消路徑完整清理。拒絕的指令在任何副作用之前回傳，不先中斷交手、不先 halt、不先釋放預約。指令本身的參數驗證（例如 task 的未知活動、目標無路）也移到中斷交手之前。

低層 `beginSpar` 不加 storyBusy 禁令；遠行營地切磋由 `journeyTick` 直接呼叫，屬於遠征自己的合法轉移，不經玩家指令層。

## 舊存檔與診斷

不默默修復：`livenessIssues(w)` 列出「遠征準備中、未領糧也沒有領糧活動」「舊版 halted 遠征」「storyBusy 卻無任何擁有者」。`expeditionTick` 偵測到準備中斷時記錄一次 `expedition-stalled` 事件與 `expedition.stall={version:1,code,actors,since}`，不補物資、不改狀態。UI 顯示原因與可做的事；玩家按「召回全隊」走既有取消／返程路徑恢復。舊 halted 遠征同樣可用召回全隊收尾。stall 欄位有版本與引用驗證，未知版本拒絕。

## 事前驗收

1. 兩個 P2 重現（spar、recall）：修正後 spar 被拒絕且遠征照常領糧出發；recall 轉成取消出發、全隊 storyBusy 清除、預約釋放、遠征 phase=cancelled；兩者 2000 tick 內不存在活性問題，encode/decode 後一致。
2. 已卡住的舊狀態（以舊程式真實產生，非手寫）讀入後：`livenessIssues` 回報 pack-missing，記錄 stall 事件且物資不變；召回全隊後有限時間內解除，不複製乾糧。
3. 多人與授課衝突：遠征隊員不能當老師、學生、切磋方、演武者、約定發起人；同堂學生不能被拉去切磋或演武；切磋中的人不能被派遠征。task 撤出同堂學生只退自己，老師撤出整堂結束。
4. 無效指令不改狀態：對每一種被拒絕的指令，世界 hash 在指令前後除指令紀錄與 rejected 事件外不變（比較去掉 commands／seenCommands／journal／commandSeq／facts 後的 hash）。
5. 正常打包出發、全隊返程：已出門後個別 recall 等同召回全隊，全員實走回安全位、phase=returned、storyBusy 清除；物資守恆（ledger invariant）與預約無孤兒。
6. 指令序列測試：固定 5 seed，每 seed 隨機產生至少 60 個混合指令（遠征、切磋、授課、召回、改派、停工、演武、恢復），每 50 tick 檢查 invariants 與 livenessIssues 為空；每序列中途 encode/decode 後雙軌續跑 hash 相同。最後全隊召回後 6000 tick 內所有遠征結束（returned/cancelled）。
7. 既有營地切磋（M5）、教習對練（M3）、同堂（第一版）與全部既有回歸照常通過。
8. 正常 UI：從新局經正式 UI 派遠征後試切磋與個別召回，看見明確拒絕／取消出發訊息並能再次出發；讀入以舊程式產生的卡住存檔，看到診斷並以召回全隊恢復。1280×800 與 1440×900 截圖。
