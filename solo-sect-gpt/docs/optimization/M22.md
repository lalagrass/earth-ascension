# M22 招募與相處留下可延續的故事：實作前規格

base `a8c2d34`（M21 交付）；規劃 GPT / Codex（M17-M23-PLAN），實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列。

## 玩家問題

義學教過林青、和阿木一起做過工、兩位成年人結伴同住之後，就再也沒有下文：邀請入門只是一顆按鈕，答應或不答應看不出與之前發生過的事有什麼關係；同住的人受傷被照料，也不會有人記得。

## 修改範圍（後續 v1，明示採用）

1. 門風／人物頁新增「採用後續 v1」，`w.followPlan={version:1,lines:{}}`，標記 `chapter1-follow-1`（最高優先），舊 reader 拒絕；未採用的局不變。
2. 三條後續、各兩段；每段都是兩人實際走到一起、談話 10 秒（沿用談話活動），談完才記下：

| 後續 | 起點（必須是真紀錄） | 第一段 | 第二段（本人回應） |
| --- | --- | --- | --- |
| 義學之後 | 義學完成（教者與林青的「指點」記憶）、林青尚未入門且在院中 | 回訪：教者與林青談那堂課 | 再邀：林青自己回答 |
| 共作之後 | 與一位非門人（例如雇工阿木）有「共作」記憶 | 談入門：掌門提起 | 對方自己回答 |
| 同住之後 | 兩位成年人已結伴（非親屬） | 共同生活：兩人談同住的日子 | 傷後照料：結伴後其中一人照料過受傷的另一人，被照料者回應 |

3. 本人回應只讀既有事實，不加新數值：入門意願已達 6 且對對方信任 ≥ 4 → 答應（仍要按既有「邀請入門」，床位、供餐等條件照舊）；信任 ≥ 4 但意願未到 → 延後（3 日後可再問）；信任 < 4 → 婉拒（這條後續結束，過往記憶仍在）。同住之後的第二段只有「記得了」與「條件不足」，不產生戀愛或其他權限。
4. 不直接送入門、不改關係數值、不改武學；小禾不能成為任何後續的對象（未成年、親情與伴侶分開）。
5. 有限事實：每段只存引用（記憶 id、tick）與一句結果；起點記憶若已不在紀錄中，畫面寫「缺來源」，不編往事。
6. 取消／再約：談話中任一方被叫停，該段不算完成，可再約；對方忙碌、離院時按鈕停用並寫原因；完成的段落讀檔後不會重領或重播。
7. 存檔：`followPlan` 版本、後續 id、段落狀態、回應值、引用與時間逐項驗證；談話活動帶的後續引用也驗證。

## 事前驗收

1. 三條後續在模型中各走一次正向與一次反向／條件不足分支：義學之後（答應、延後再問）、共作之後（婉拒、條件不足）、同住之後（完成兩段、尚無照料紀錄）。
2. 中途叫停後可再約；對方忙碌時被拒且世界不變；對方離院時條件不足；存讀雙軌 hash 相同；完成的段落重讀不重領。
3. 小禾不能被選為對象；回應不改入門狀態、關係數值與武學。
4. 起點記憶被移除（標註 fixture）時顯示「缺來源」，第一段停用。
5. 回歸全過。
6. 正常 UI（1440×900、1280×800）：新局走到義學完成（正常操作）→ 採用後續 → 回訪 → 再邀，看到林青依真實紀錄回答。

## 實作紀錄

新增 `src/followups.mjs`：`adoptFollowups`（`w.followPlan`，`chapter1-follow-1`）、`lineStatus`（從真紀錄判定對象、起點與下一段，只讀）、`startFollowup`（指令 `followup`，開一段 10 秒談話）、`completeFollowup`（談話完成時記一次，同一活動不重記）、`validFollowPlan`。談話活動完成時呼叫 `completeFollowup`；存檔驗證後續紀錄與帶 `followup` 的談話活動。江湖頁「下山義學」下方新增「後續」區：每條顯示對象、起點（第幾日的哪種記憶；起點不在就寫「缺來源」）、已完成段落與回應，下一段的按鈕停用時附原因。

與事前寫的不同（照實記錄）：
- 共作之後的正向分支是**答應**，不是規格表推想的延後：既有規則是「與阿木共作後再談話，阿木就形成入門意願」，第一段的談話本身觸發了這條規則。所以「延後」分支在義學之後驗（標註 fixture：林青意願 3），「婉拒」在共作之後驗（標註 fixture：雙方信任 1）。
- 「對方忙碌」在核心有兩層：有共享安排（切磋、演練等）時按鈕直接被拒；只是在吃飯等個人活動時，談話會開始但寫「對方正在忙，可先叫停再邀」等著。模型測試裡林青吃飯卡住 3 日後仍在吃，需要叫停才談得成；正常 UI 也照實先叫停。
- M16 示範存檔裡掌門與阿木本來就已結伴同住，所以同住之後直接用這對，不另造結伴。
- 正常 UI 不是從新局開始：新局要先修大廳、備四餐才能開義學，路程太長；改用 GPT 開發時以正常 UI 產生的 journey-03 存檔（第 9 日，林青尚未見過），之後的義學、採用、兩段後續都在畫面上實際操作。
