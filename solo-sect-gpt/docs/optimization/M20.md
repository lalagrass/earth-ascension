# M20 讓聯合演練的分工成立：實作前規格

base `248e763`（M19 交付）；規劃 GPT / Codex（M17-M23-PLAN），實作主筆 Claude Opus 5.5（Anthropic），單一作者。本節先 commit，結果另列；M15 的失敗比較與 exception 不改寫。

## 已知問題（M15 留下的紀錄與重讀程式後的查核）

1. 先開打再等隊友：`startDrill` 後 200 tick 第一波一定入場，不管參加者走到沒有；M15 C4 的守線者從菜地走了約 600 tick 才到線上，唯一一次漏過就在這段時間。
2. 對手一律鎖定名單上第一位沒退出的參加者，不看距離；追著前攔者的對手會被拖過前線而漏過。
3. 退出後的人還被舊演練管：`interruptCombat` 只把人標成退出；若他之後去切磋，切磋結束會把「退出」旗標清掉，`sessionsTick` 又把他當參加者分配目標，守線邏輯也會把他拉回線上，回顧還會把他在外面切磋的出手算進來。

## 修改範圍（聯合演練 v2，明示升級）

1. 已採用 v1 的局在遠征頁看到「升級為 v2（集合準備）」；新採用直接是 v2。v2 標記 `chapter1-joint-2`（最高優先），舊 reader 拒絕；v1 的回顧照常保留；沒升級的局行為不變。
2. 流程：組隊 → **集合準備**（前攔走到站位點、守線走到線上；每人顯示已就位／路程中，組隊前的候選人顯示忙碌／受傷原因）→ 全員就位後玩家按「開始」（未就位按了會被拒並寫誰還在路上）→ 對手 2 秒後入場、兩波 → 回顧。準備中可「撤回」（回顧寫「準備中撤回」，沒有對手入場）。角色一律實走。
3. 來路：新增兩種對手到場方式，玩家在組隊時選：「同時抵達」（現行）與「錯開抵達」（每波第二名晚 8 秒才動身）。
4. v2 的對手鎖定最近的、仍在演練中的參加者。前攔照原行為追擊；守線只攔線點 70 DU 內的對手，對手離開範圍就回線上（限制追擊、保留攔漏位置）。不調任何傷害、生命或招式數值。
5. 參與時段：每位參加者記入隊與退出 tick；退出後不再被演練分配目標、拉回線上，也不再計入出手／命中／受擊（此項修正對 v1 進行中的演練同樣生效，因為是錯誤修正）。回顧另記每人精力消耗、傷勢變化，以及每名對手第一次被打中時的 x 位置（攔截位置）、準備用時與交手用時。
6. 存檔：v2 狀態有版本，集合階段、站位點、來路、入退時間、攔截紀錄逐項驗證；未知版本或不合法引用拒絕，正在玩的世界不被覆寫。

## 事前驗收

1. 未升級的 v1 局：行為與 hash 不變（既有 M15 回歸）；升級後集合中按開始、未就位被拒且不改世界。
2. 集合準備期間沒有任何對手入場；撤回後無殘留交手、站位、共享安排或活性問題。
3. 退出：參加者中途退出並去切磋，切磋結束後舊演練不再分配目標、不拉回線上，回顧不計切磋的出手。
4. 存檔：集合中、交手中存讀雙軌 hash 相同；壞的 v2 欄位、未知版本被拒。
5. 回歸全過。
6. 正常 UI（1440×900、1280×800）：示範存檔匯入 → 升級 v2 → 選阿木前攔、林青守線、錯開抵達 → 看兩人從路程中變成已就位 → 開始 → 回顧顯示攔截位置與每人消耗；另一次組隊後在集合中撤回。

## 第一輪比較（v2 第一版，結果照實記錄）

`m20-model/comparison-r1.json`（commit 見下）。六格全部「守住、0 漏過、擊退 4」。D1 **不成立**（S2 兩種安排都 0 漏過）；D2 成立（0≤0）；D3 成立（S3 兩人前攔 648 tick，守線安排 971 tick，同為 0 漏過）；D4 在有守線出手的兩格成立（前攔攔截 x 平均 1449，守線 1356／1362），S2-Y 的林青整場沒有出手。

原因（讀程式確認）：集合準備消除了「守線者還在路上」的競速，而對手的行為只有「追最近的參加者」，沒有要越過前線的目的；漏過只會在對手追人追過 x1300 時順帶發生。深修的阿木一人在東側就把對手全部接住，守線者沒有東西可攔。也就是說，第一版 v2 的「守住前線」只是名目，守線的用途在規則裡不存在。

## 第二輪設計修正（第二輪結果出來前寫定；場景、安排與 D1–D4 不改）

對手改成真的要過線：v2 的對手放行後朝外功場西側（x1280，沿自己入場的列）前進；只有在 60 DU 內有仍在演練中的參加者時才轉向交手（鎖最近的那位），被纏住就停下來打，脫離 60 DU 又繼續往西。前攔仍主動追擊（照原分配），守線仍只攔線點 70 DU 內的對手。生命、傷害、招式數值不改。v1 不受影響。
