# M7–M11 真人試玩計畫（未執行）

狀態：**尚未執行**。本次沒有人類受試者；作者自己操作與自動化 UI 腳本不算真人試玩，也不以它們代替。

參考：[Cronin, Playtesting Process for Ultra Small Teams（GDC 2026 投影片）](https://media.gdcvault.com/gdc2026/Slides/Cronin_Brian_PlaytestingProcessForUltraSmallTeams.pdf)。2026-10-26 以 macOS PDFKit 抽出 89 頁文字實讀。採用：一對一試玩；每輪先寫假設、1–5 人（講者經驗 3 人通常足夠）、整理筆記並排序、每輪至少做一個行動再回到假設；受試者玩的是整個遊戲，不只假設那一塊。不採用：講者 Discord 招募與一小時遠端流程的細節（本作是私人本機原型），以及「這不是科學」之外的任何量化門檻。

## 招募與設定

- 3–5 人，未玩過本作；每人約 20–30 分鐘，一次一人。
- 本機 Chrome，1440×900；啟動方式見 DELIVERY。觀察者不提示操作，只在卡住超過 2 分鐘時給一句提示並記錄。
- 起點：全功能示範存檔（存檔→匯入→繼續）。

## 任務（依序）

1. （理解，5 分鐘）點三個人物，說出他們現在在做什麼、為什麼、接著會做什麼。
2. （介入，5 分鐘）派一位遠征領糧中的人去切磋，再想辦法讓他回來。
3. （經營，5 分鐘）採用經營簿，選一個方針，看一個活動日後說出物資用到哪裡、哪裡卡住。
4. （遠行，5 分鐘）升級遠行方針，比較「3 份糧」和「1 份糧」的預估，選一個出發並看返院報告。
5. （人物記憶，5–8 分鐘）收一位弟子，做到「一起遠行」的約定並完成一段後續。

結束後三題：哪一個人物你記得最清楚、為什麼？哪一次你覺得選擇真的有代價？哪裡最想放棄？

## 判讀

只記錄觀察到的行為與原話；不把個人偏好當結論。任何「看不懂」優先於「不喜歡」。結果出來前不宣稱 M8–M11 的體驗目標成立。

## 每輪流程（依來源）

1. 假設：例如「玩家能從情境卡說出人物卡住的原因」。
2. 一輪 3 人（最多 5 人），一對一。
3. 每份筆記標出行動項，再彙整成一份排序清單。
4. 至少做一個行動；高優先多做，不必全做。
5. 回到 1。
