## M17 修復交付邊界

**玩家結果：** 已練到頂的弟子不被不可能的目標卡住，錯誤存檔不把遊戲帶入崩潰狀態。成本小。

1. 修前次 review：`mentor.proposeDirection`／`completeEvent`／`practiceProgress` 可接受 F100 後再加10，但 F上限100，且不能換方向。提議與真正定向兩個時點都檢查可達性；已卡住的方向給明示取消／重定向出口，不免費授予成長或驗收。新目標仍須真訓練。覆蓋 F89、90、91、100，以及答應後才練滿的情境；器械方向 +6 同理。
2. 修 `save.mjs` 聯合演練驗證：參加者 roles/stats 完整一致，逐項驗 moves、hits、received、必要引用與時點；歷史回顧同樣驗結構。空 stats 子物件目前能載入，結束演練時會在 `Object.values(s.moves)` 崩潰。壞檔須拒絕且不覆寫正在玩的世界。
3. 核對教學進度是否因有限歷史清除而倒退，只修可重現者；不要把四日經營資料誤當永久成就來源。

**出口：** 兩個已重現反例轉為針對性回歸，正常流程仍可完成；保留 M12/M15 的原始 exception，不改寫舊比較結果。此階段不借機平衡招式。

## M18 公版語義與 GPT 唯讀轉接

**玩家結果：** 同一角色、同一武學的說明來自同一份權威資料，不因換面板出現另一套值。成本中。

依 [PUBLIC-PANELS-ADOPTION.md](PUBLIC-PANELS-ADOPTION.md) 固定上游提案與本地 adapter 版本。先做最小可執行 GPT 投影，不等待跨版共用套件。人物以 leader、amu 及一個受限制人物作案例；武學以基礎拳、九劍入門和一個已安裝進階招式作案例。測試選角不改角色權限。

新增模組的責任僅限：人物快照、武學定義投影、人物所學投影、可用操作描述。保留目前 `person-view.situation` 與核心規則；若要抽出純查詢函式，命令執行路徑必須共用它，不能另複製門檻公式。

**出口：** 開卡前後世界 hash、RNG、事件數、物品及技能皆不變；known 0 保留，unknown／hidden／unsupported／notApplicable 不混。hidden 原值不進 DOM 或序列化快照。開卡後狀態變動再按操作，由核心重新驗證。此階段可用現有 UI 檢查快照，正式版面下一階段交。

## M19 人物與武學面板接入

**玩家結果：** 點一名弟子，看懂他正在做什麼、為何受阻、練成什麼，以及下一個真正可做的選擇。成本中。

1. 既有人物頁整理為「生活總覽／武學成長」兩入口。保留選人與回到地圖；頭像、當前活動、重要狀態在卡首，詳細來源按需展開。沿現有桌面 UI，不新增第二試玩入口。
2. 武學詳情區分定義、此人 U/F/I、已學招式、當下可練／可用；下一招讀 M14 的真前置。九劍入門保持名稱與窗口限制，不宣稱完整九式。資料包移除／版本不相容的選中條目有合法回退。
3. 指點、練習、領器械、設偏好、叫停等沿既有命令。先只接現在已存在且權限相符的操作，不把缺項變成能點的承諾。
4. 先用現有可用外觀，缺立繪用中性回退；素材來源與 actorId 分開。不搬 #339 的大圖，不因卡片先改地圖骨架。

**出口：** 正常 UI 走「受阻→看到原因→實際取得條件→練習→看到真進步→同圖試招」。覆蓋忙碌、缺器械、未知資料、成長歷史已截斷與角色切換。1440×900、1280×800 的資訊與按鈕可讀；卡片不洩漏隱藏值，不出現假雷達六角。

## M20 讓聯合演練的分工成立

**玩家結果：** 玩家能理解何時前攔、何時守線有用，而非先開打再等隊友長途走來。成本中。

限原場地、最多三名成年門人、兩波及兩種角色。補「集合準備→玩家開始→演練→回顧」；已就位／路程中／忙碌／受傷清楚顯示，準備可取消，未準備完成不悄悄開始波次。角色仍實走，不能瞬移。

修到前攔與守線在指定可達場景各有用途及代價；前攔提早接敵，守線限制追擊並保留攔漏位置。退出後不再由舊演練改 target／路徑或統計外部切磋；回顧按 session 與參與時段歸屬。不要只把全員傷害調高使所有配置都零漏敵。

**出口：** 先登記「不同來路／抵達時間」至少兩個場景，各從同一狀態分叉比較兩種安排；記漏過、攔截位置、出手、受傷／耗能與時間。有一個合理反例說明守線不是永遠最優。正常 UI 完成及撤回各一次。未證實用途時同包修設計，保留失敗比較，不以新文案結案。

## M21 自主生活有個性且能回到目標

**玩家結果：** 設好日課後，弟子自行工作、練功、休息、找人相處；臨時打斷後能接回原生活。成本中至大。

沿現有 life-policy、martial focus、師徒方向與生活候選，不增加第二份志向數值。只深化三類目標：門派工作、已選武學、閒暇相處。空閒時以既有性格／關係影響對象或活動；工作缺料／目標達成後轉向合法候選，不在同一失敗任務反覆打轉。保留危急補給優先，不能為顯示政策差異而令角色挨餓。

人物卡顯示現在／原因／下一步及目標來源；只輸出已知理由，不能暴露隱藏性格分數。臨時命令、共享活動、中止與回日課沿唯一活動所有權。已學滿時提供完成或重新選目標，不無限加經驗。

**出口：** 正常供給、有工地缺料、傷後恢復三個預先固定場景；至少兩種人物配置比較實際時間分配、切換、受阻與必要介入。安排一次完整模擬日的正常 UI 觀察，記模擬時間、倍率與牆鐘時間；模型長跑與畫面證據分開。原本兩組介入皆0時，不宣稱改善百分比；個性差異以行動證據交付。

## M22 招募與相處留下可延續的故事

**玩家結果：** 義學遇見的人、共同工作的人和一起生活的人，有可辨認的後續。成本中。

沿現有義學、雇工、招募、家庭、師徒與 memories。最多三條各兩段的新後續：義學後回訪／再邀；共作後談入門／本人回應；成年同住者共同生活／傷後照料回應。選角讀真 actorId、事件與雙向關係，不靠改名複製人物；事件不直接送入門、戀愛或武學等級。

每條保留接受、婉拒／延後與條件不足。親情與成年伴侶分開；不增加小禾的勞動、戰鬥或戀愛權限。只擷取有限重要事實供後續引用，不保存無限對話；普通短期紀事仍可清理。若必要事實已過保留範圍，就誠實缺來源，不編出往事。

**出口：** 至少一條正常 UI 全流程、三條模型正反分支；取消／再約、對方忙碌、離開、讀回不重領或重播。家庭／師徒不是必經流程，不強迫全員相同結局。此包不新增十二名經典人物或《功夫》全套角色。

## M23 場景可讀性與整批交付

**玩家結果：** 少開面板也能看懂門派今天發生什麼，點人又能回到上述資訊與操作。成本中。

限現有家園及演練區：施工階段與使用中設施、搬運物、練習／交談／休息姿態、集合線與戰鬥階段可辨。以現有程序圖與素材補細節，遮擋、腳錨、兵器握點與可通行範圍對齊；不重畫整張大地圖。招式畫面讀真 action.phase，缺 motion 用相容回退，不改命中與時間。大型新遠征圖列下一批候選。

交一份正常 UI 取得的 M17–M23 試玩存檔及 5–10 分鐘觀看路線，串「看卡→安排日課→一段相處→試招／集合→聯合演練→回生活」。保留舊 showcase。新局入口可達、一般舊檔續玩、壞檔拒絕、刷新與槽位保護一併統整；不得為展示注入資源或完成旗標。

**出口：** 各階段結果、未完成、exception 與證據索引齊全，正常 UI 路線可重走；畫面／趣味未經真人評估就明記，不以作者腳本冒充真人試玩。整體存檔工程最後收尾，但新增狀態的保存契約及相容反例必須在引入當階段處理。手機仍留後續，不因收尾擴範圍。完成 M23 停止。

## Claude 執行節奏

每階段先交 `docs/optimization/Mxx.md`：玩家問題、修改範圍、狀態／保存影響、正常流程、反例與事前比較；再實作、驗收、修補、提交。每階段完成再進下一階段，例外不自動解除下游依賴。公版後續有修訂只在階段邊界核差異，固定版本不追動態 HEAD。

沿 CONTRIBUTING 與既有測試政策做受影響檢查；模型 fixtures 和正常 UI 分開，輸出用新的 evidence/optimization/mxx/，不覆寫歷史證據。不為純投影重跑全世界長矩陣，也不刪必要存讀／所有權反例。服務只用空閒隔離埠，避免8800。不要清理既有 `.serena/` 或 `jsconfig.json`。

各階段標記 `handoff/optimization-mxx.done.json`；總交付 `optimization-m17-m23.done.json`，列實際作者、base、已存在的 artifactCommit、spec、正常 UI 與測試證據、限制。未達出口只留 checkpoint，不能用一次 turn 結束代替 milestone 完成。不啟永久 loop、不自行延伸 M24。
